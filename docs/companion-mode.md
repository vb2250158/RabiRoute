# 桌宠陪伴模式

状态：实验功能。Windows 桌宠右键开启“陪伴模式”，在“陪伴方式”中选择自适应、一起看、陪我玩、工作模式或安静陪着。模式来自 Manager 的预设目录；切换保留当前活动、路线和讨论，使旧画面回复与语音失效。

开启后，桌宠观察当前前台窗口，向本角色已启用的本机 Agent 路线递送当前画面、窗口标题和进程名。自适应模式判断游戏、观看、工作、其他活动或不确定；手选观看、游戏或工作时保持所选活动类型。不确定和专注工作时保持安静。看作品只讨论眼前内容，不查询后续剧情；游戏只观察和讨论，不发送操作。Agent 可以仅更新判断，不说话。缩略帧作为真实图片附件交给 Agent；本机临时附件只保留当前讨论，最多 180 秒，切换或退出时移除。本机异常退出可能留下该代临时文件，恢复时不会把它当作当前画面。

工作模式每 60 秒向 Agent 递送一次当前画面，自动观察只更新判断，不显示或播放评论；用户明确提问时才回应。安静陪着只在用户发言时讨论。画面采样按当前 observationPolicy 执行，模式节奏控制递送给 Agent 的频率。

开启后连续缓冲前台画面与默认声卡的播放音频，不启动摄像头或麦克风。默认每 0.5 秒采一帧、每 2 秒上传一次观察；采集、上传和 ASR 独立运行，投递期间继续记录下一段。窗口或标题变化会清空旧片段、使旧回应失效并取消上一版本的语音。画面中断超过 20 秒时暂停，恢复可用前台画面后自动继续；手动暂停、隐藏、静音和结束不会因此自动恢复。

## 两次投递之间的画面与声音

每次投递冻结上次投递尝试边界到本次采集时刻的片段。画面按时间分区，选择各区变化最大的候选，保留首尾帧，按时间排序合成 2 列、最多 6 格的 JPEG；每格标注序号和相对时间。静止片段只保留首尾，原比例缩放并留边。首轮先积累 5 秒，后续沿用预设的讨论间隔。Agent 看的是这一段过程，而非仅最后一帧。

播放声音通过 WASAPI 默认输出回环采集，统一为 16 kHz 单声道 PCM，按采集时间去重、裁剪并与画面使用同一边界。投递前调用既有 RabiSpeech 批量 ASR，附上整段转写。桌宠语音播放期间排除系统音频，并标出排除时长；这也会排除该时刻混在同一输出上的其他声音。后台音乐或其他应用的声音可能混入，因此材料标作“系统播放”，不冒充用户发言或专属游戏音轨。ASR 失败、静音和采集缺口分别标明，画面仍会投递；切页会取消旧 ASR 结果。

可调采样密度、N 帧数量、变化阈值、格宽、缓存和转写时限统一位于 `packages/rabi-companion/observation.json`。录屏样本和声音只在本机进程内存中缓冲：默认最长 300 秒，JPEG 缓冲最多 32 MiB；不写录屏或原声文件。超出窗口的画面过期，并在投递中标明实际覆盖起点；单次声音上传最多覆盖 30 秒，网络缺口不会被描述成已听见。Manager 冻结并消费已投递区间，暂停、结束、切窗和重启清空缓冲，重试不会重复累积同一段声音。批量 ASR 使用计算入口，临时上传文件在计算结束后清除；已开启全天记录时，同一区间的播放转写与 WAV 由全天记录 owner 保存为“电脑播放”事件，不进入麦克风消息流。

开启时自动查找本机已绑定的 DSH owner。服务离线时调用该 Home 的已有 `start-dsh.ps1` 入口，再从当前启动日志发现地址、恢复本机登录并核对原会话 ID 与工作区；不扫描端口，不新建替代会话，不覆盖手动断开授权。连接失败按 60–120 秒退避重试，不重放结果不确定的投递。右键菜单显示识别或恢复状态。该自动启动流程适用于已有受支持启动入口的本机 DSH；其他 Agent 沿用其已有投递合同。

前台播放器、视频页和匹配前台标题的正在播放视频元数据先给出场景判断，无须等待 Agent。播放信息只读，不控制播放器；后台音乐不作为前台视频证据。规则位于 `packages/rabi-companion/scene-rules.json`，未命中仍交给 Agent 看当前画面。Agent 每次回传活动判断，安静时 `text` 为空；不确定的回应不会抹掉已有窗口判断。自动识别结果允许在 180 秒内返回；默认评论时限为转写准备结束后的 90 秒，并受本轮原始识别期限限制。超过后只更新判断，不补播旧评论。

动作包可用 `companionStates` 将 `watch`、`play`、`work` 映射到循环动作。观看保持沙发姿态，游戏保持电竞椅姿态；工作优先使用包内工作动作，没有映射时使用循环思考动作或待机。语音和评论走气泡。陪伴期间暂停普通随机动作、睡眠和漫游，切换场景更换对应姿态；暂停或结束后退出场景姿态，结束后恢复原待机设置。

## 模式动画组

需要每种模式有自己的待机和小动作时，在动作包声明 `modeAnimationSets`。优先匹配当前预设 ID，其次匹配活动类型；自适应识别到工作时也能使用 `work` 组。

```json
"modeAnimationSets": {
  "work": {
    "idleState": "work-idle",
    "randomIntervalSeconds": {"min": 45, "max": 120},
    "randomStates": ["work-type", "work-read", "work-stretch"],
    "clickStates": ["work-nod"]
  }
}
```

组内待机须循环；随机和点击动作须单次播放，`next` 返回该组的待机。点击优先使用本组的点击动作，随机动作只在可播放时触发；语音保持当前组内姿势，拖动或移动结束后恢复当前模式。换组后不补播旧动作。陪伴期间不睡眠，结束后恢复普通待机、休眠与闲逛设置。

旧包的 `companionStates` 继续提供单一循环姿态，不复制普通待机动作池。新包使用 `modeAnimationSets`，旧映射仅在没有对应组时回退。迁移时在新包中声明动画组并移除同名旧映射，保留已接受的旧包并导入新 ID；不能覆盖旧包。

陪伴开启期间桌宠不会因全屏应用隐藏，并停止随机漫游；退出后恢复原设置。保留原鼠标点透设置，需要右键退出时可从托盘取消点透。角色的 Agent 路线必须已启用且唯一；多个启用路线时不会猜测投递目标，管理页可以使用当前选中的路线开启。桌宠开启意图由 Manager 保存为本机恢复检查点；Manager 或桌宠重启后，经原路线重新核验并建立新活动，不复用旧画面、回复或语音。手动暂停、隐藏、静音或结束会清除恢复意图。网页本地播放器不自动恢复。

切换浏览器标签页时，Manager 在接收新画面的同一次请求中使旧回复失效并更新观看状态，取消旧语音不会阻塞画面接收。因请求延迟而过期的画面会重新采集，不重复发送旧帧。观看或游戏动作加载失败时保留当前场景目标，按 1.5–30 秒退避重试；退出陪伴、隐藏或关闭桌宠后停止重试。

未知游戏无需预先登记：Agent 根据标题、进程和画面回传 `activityKind`，立即驱动桌宠状态。已确认的类型按角色原子保存到 `companion/window-types.json`，以进程名和去除首尾空白的窗口标题共同匹配；再次切回或重启后复用。浏览器不同页面分别判断，`uncertain` 和过期回复不写分类。文件只保存窗口标识和类型，不保存截图、会话或评论；重复分类不重复写入，可由后续有效判断纠正。

陪伴投递只带本轮情况、画面与简短回传定位，不带普通 Route 包装模板、历史观察正文、计划记忆清单、日志路径或通用禁止事项。详细资料由 Agent 按需查询。

## 与全天记录配合

麦克风继续由全天记录的唯一 RabiSpeech 会话监听。陪伴每次投递按序列图的起止时间读取已完成麦克风转写，附带分段时间和来源；不再次调用麦克风 ASR。语音转写与画面采集独立，不等待下一次画面保存。

陪伴评论使用[通用桌宠气泡与语音](desktop-pet-bubbles.md)。语音开始时显示对应文字，播放结束后按气泡时限淡出；普通角色语音也使用这一入口。气泡不附带收起、重听按钮，支持角色自定义样式。

已开启该角色全天记录时，开始、用户发言、Agent 回传和模式或暂停状态变化会更新活动进度，结束时保存摘要和时间轴入口；不保存陪伴原图、窗口标题或字幕。不改变全天记录的采集来源和设置。全天记录未开启时，桌宠入口只保留当前活动；开始后关闭全天记录，会停止后续进度和摘要写入，但不删除已保存记录。角色页“共同活动”可显式选择保存本次进度与讨论。

角色页另有本地视频入口，可加载 WebVTT 字幕，读取当前播放进度和正在显示的字幕。仅当前片段交给 Agent，不装入未来字幕。手动“说话”按钮最多录入 30 秒并使用现有 ASR 服务，转写后作为用户发言；它不会录入作品原声或自行开启持续监听。

## 验证范围与限制

有界队列、过期回复拒绝、窗口切换、点透设置恢复、桌宠右键入口、持久化摘要和语音单活动取消有自动检查。具体游戏的画面识别、不同播放器、独占全屏或受保护画面的采集、Agent 反应时机及实际语音效果仍需现场验收；黑屏或无法识别应如实反馈，不代表已经看懂内容。视觉推断不能精确判断每一句对白的起止。

## 角色陪伴配置

每次讨论从当前角色目录重新读取 `persona.md`（或路线指定的角色文件）、`prompts/companionship.md`、可选 `growth.md` 和 `skills/companionship-response.md`。缺少响应 Skill 不影响已有陪伴提示词加载；角色文件或陪伴提示词缺失、为空或无效时显示投递失败，不改用通用安慰文案。全局模式预设只约束观察节奏、行为边界和回传，不决定角色口吻。

可在该角色的 `personaConfig.json` 中指定自己的提示词和模式附加模板；不配置时仍读取既有 `prompts/companionship.md`，无需迁移该文件：

```json
{
  "companion": {
    "promptFile": "prompts/companionship.md",
    "templates": { "watch": "prompts/companionship-watch.md" }
  }
}
```

模板路径必须位于当前角色目录内，不能通过目录联接跳出。支持 `{roleId}`、`{presetId}`、`{activityKind}` 占位符；模式模板在基础提示词之后加载，不能取消模式或回传限制。示例见 `examples/data/roles/Rabi/`。

Manager 的角色面板和计划反馈正文经子进程标准输入投递（最多 256 KiB UTF-8），避免中文上下文 URL 编码后超过 Windows 命令行长度。CLI 的 `--role-panel-text=` / `--plan-feedback-text=` 保留给已有外部调用；Manager 不再使用它们。接收端仍走同一消息路线和已绑定 Agent，不创建备用执行端。

角色上下文最多 28,000 字符：角色和基础提示词各最多 6,000，模式模板和成长记录各最多 3,000，响应 Skill 最多 1,500。近期记忆只取 Manager 已发布目录中最新的三份未归档摘要及详情接口，不装入正文或扫描记忆目录；目录未就绪时投递失败，等待后续正常投递。历史摘要最多四条讨论，历史窗口类型最多 1,500 字符。更长来源仅在相关时按来源继续读取；历史内容明确标记为背景，不作为当前观察或操作指令。

选择保存时，`companion/sessions/<活动ID>.json` 按稳定 ID 更新；`companion/state.json` 记录最近活动及 `lastInteractionAt`，表示开始时间或最近一次用户发言、有效文字回应的时间，不把自动截图或安静识别当成新互动。`companion/last.json` 只指向最近结束并保存的摘要，因此开始新活动不会遮住上一份结束摘要。写入串行执行，结束摘要不会被较早的异步进度覆盖。读取历史不会自动恢复活动；恢复仍走原路线重新核验。

## 接口

通过当前 Host `status --json` 发布的 `managerBaseUrl` 访问，并核对 `/meta` 的代际和实例身份。接口沿用 Manager 的正常鉴权规则，已鉴权的远端 Agent 与本机入口使用同一公开合同；用户明确关闭的能力仍受限制。

- `GET /api/roles/{roleId}/companion`：预设与当前活动。
- `POST .../start`：`requestId`, 可选 `gatewayId`, `presetId`, `title`, `autoReview`, `voice`, 可选 `saveSummary`, `observationOwner`。
- `POST .../command`：`sessionId`, `revision`, `action`（pause/resume/seek/interrupt/stop/set-mode）；seek 加 `positionSeconds`，set-mode 加目录内的 `presetId`，返回当前活动的新版本。
- `POST .../observation`：活动与版本，以及有顺序号、时间和 JPEG 的 `observation`。
- `POST .../review`：活动、版本、可选用户 `text`。
- `GET .../frame?reviewId=...`：该次讨论的冻结画面，过期后不可读取。
- `POST .../reply`：`sessionId`, `revision`, `reviewId`, `text`, 可选 `state`, `activityKind`（play/watch/work/other/uncertain）。安静时 `text` 为空。
- `GET .../last`：最近一份结束并保存的摘要；不会自动开始或恢复活动。

陪伴模块不自动建立记忆或计划。投递给 Agent 的缩略画面与文字仍可能由既有路线保存为附件、聊天历史或缓存，沿用其原有保留规则；关闭活动摘要不等于删除 Agent 历史。活动摘要以稳定活动 ID 原子保存，当前活动由 Manager 拥有。Agent 必须使用 fenced reply 回传；过期的 409 安静结束，不改成普通任务播报或外发消息。

## 评论节奏与排障

自适应与观看预设每 25 秒尝试讨论，游戏预设每 30 秒；上一轮仍有有效回应时等待它完成，评论时限已过则在下一次观察中换成新片段，不等满 180 秒。转写准备不消耗评论预算，切窗、暂停、结束仍使旧回应立即失效。

默认提示邀请 Agent 从本段内容里分享一两句反应：视频聊剧情、对白、槽点或感受，游戏回应操作、输赢、意外或等待中的趣事。每次附带最近多久没评论、连续安静回传数和最近三句对话。画面未变化且安静达到 90 秒时，也会重新讨论当前片段；这提供聊天机会，不生成固定话术，也不强制每轮发言。`quiet` 预设仍仅响应用户主动讨论。`reviewSeconds`、`reactionAgeSeconds` 和 `silenceReviewSeconds` 位于 `packages/rabi-companion/presets.json`。

`session.review.outcome` 区分 `commented`、`quiet`、`comment_expired`；`deliveredAt` 仅证明投递完成，不证明 Agent 已回传。`session.participation` 保存本次活动的最近评论时间与连续安静回传数，活动重建时清空，不跨重启延续旧评论状态。若一直停在 `delivered` 或 `failed`，检查实际 Agent 接收与回传链；气泡文字进入记录而语音失败时，另查语音服务。
