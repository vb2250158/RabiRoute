# 桌宠陪伴模式

状态：实验功能。Windows 桌宠右键开启“陪伴模式”，在“陪伴方式”中选择自适应、一起看、陪我玩、工作模式或安静陪着。模式来自 Manager 的预设目录；切换保留当前活动、路线和讨论，使旧画面回复与语音失效。

开启后，桌宠观察当前前台窗口，向本人格已启用的本机 Agent 路线递送当前画面、窗口标题和进程名。自适应模式判断游戏、观看、工作、其他活动或不确定；手选观看、游戏或工作时保持所选活动类型。不确定和专注工作时保持安静。看作品只讨论眼前内容，不查询后续剧情；游戏只观察和讨论，不发送操作。Agent 可以仅更新判断，不说话。缩略帧作为真实图片附件交给 Agent；本机临时附件只保留当前讨论，最多 180 秒，切换或退出时移除。本机异常退出可能留下该代临时文件，恢复时不会把它当作当前画面。

工作模式每 60 秒向 Agent 递送一次当前画面，自动观察只更新判断，不显示或播放评论；用户明确提问时才回应。安静陪着只在用户发言时讨论。画面采集间隔仍为 5 秒，模式节奏控制的是递送给 Agent 的频率。

画面每次采集完成后等待 5 秒再采集，不并发堆积。原图只在内存短暂保留，缩至最大 960 像素后递送；不会因开启陪伴而启动摄像头、麦克风或系统音频。窗口切换与同一窗口标题变化会使旧回应失效，并取消该活动上一版本的语音，不停止其他任务的播放。画面中断超过 20 秒时暂停，恢复可用前台画面后自动继续；手动暂停、隐藏、静音和结束不会因此自动恢复。

开启时自动查找本机已绑定的 DSH owner。服务离线时调用该 Home 的已有 `start-dsh.ps1` 入口，再从当前启动日志发现地址、恢复本机登录并核对原会话 ID 与工作区；不扫描端口，不新建替代会话，不覆盖手动断开授权。连接失败按 60–120 秒退避重试，不重放结果不确定的投递。右键菜单显示识别或恢复状态。该自动启动流程适用于已有受支持启动入口的本机 DSH；其他 Agent 沿用其已有投递合同。

前台播放器、视频页和匹配前台标题的正在播放视频元数据先给出场景判断，无须等待 Agent。播放信息只读，不控制播放器；后台音乐不作为前台视频证据。规则位于 `packages/rabi-companion/scene-rules.json`，未命中仍交给 Agent 看当前画面。Agent 每次回传活动判断，安静时 `text` 为空；不确定的回应不会抹掉已有窗口判断。自动识别结果允许在 180 秒内返回；眼前评论仍限 30 秒，超过后只更新判断，不补播旧场景评论。

动作包可用 `companionStates` 将 `watch`、`play`、`work` 映射到循环动作。观看保持沙发姿态，游戏保持电竞椅姿态；工作优先使用包内工作动作，没有映射时使用循环思考动作或待机。语音和评论走气泡。陪伴期间暂停普通随机动作、睡眠和漫游，切换场景更换对应姿态；暂停或结束后退出场景姿态，结束后恢复原待机设置。

## 模式动画组

需要每种模式有自己的待机和小动作时，在动作包声明 `modeAnimationSets`。优先匹配当前预设 ID，其次匹配活动类型；自适应识别到工作时也能使用 `work` 组。

```json
"modeAnimationSets": {
  "work": {
    "idleState": "work-idle",
    "randomIntervalSeconds": {"min": 45, "max": 120},
    "randomStates": ["work-type", "work-read", "work-stretch"],
    "clickStates": ["work-nod"]
  }
}
```

组内待机须循环；随机和点击动作须单次播放，`next` 返回该组的待机。点击优先使用本组的点击动作，随机动作只在可播放时触发；语音保持当前组内姿势，拖动或移动结束后恢复当前模式。换组后不补播旧动作。陪伴期间不睡眠，结束后恢复普通待机、休眠与闲逛设置。

旧包的 `companionStates` 继续提供单一循环姿态，不复制普通待机动作池。新包使用 `modeAnimationSets`，旧映射仅在没有对应组时回退。迁移时在新包中声明动画组并移除同名旧映射，保留已接受的旧包并导入新 ID；不能覆盖旧包。

陪伴开启期间桌宠不会因全屏应用隐藏，并停止随机漫游；退出后恢复原设置。保留原鼠标点透设置，需要右键退出时可从托盘取消点透。人格的 Agent 路线必须已启用且唯一；多个启用路线时不会猜测投递目标，管理页可以使用当前选中的路线开启。桌宠开启意图由 Manager 保存为本机恢复检查点；Manager 或桌宠重启后，经原路线重新核验并建立新活动，不复用旧画面、回复或语音。手动暂停、隐藏、静音或结束会清除恢复意图。网页本地播放器不自动恢复。

切换浏览器标签页时，Manager 在接收新画面的同一次请求中使旧回复失效并更新观看状态，取消旧语音不会阻塞画面接收。因请求延迟而过期的画面会重新采集，不重复发送旧帧。观看或游戏动作加载失败时保留当前场景目标，按 1.5–30 秒退避重试；退出陪伴、隐藏或关闭桌宠后停止重试。

## 与全天记录配合

陪伴评论使用[通用桌宠气泡与语音](desktop-pet-bubbles.md)。语音开始时显示对应文字，播放结束后按气泡时限淡出；普通人格语音也使用这一入口。气泡不附带收起、重听按钮，支持人格自定义样式。

已开启该人格全天记录时，结束陪伴会保存一份活动摘要和时间轴入口；不重复保存陪伴原图。不改变全天记录的采集来源和设置。全天记录未开启时，桌宠入口只保留当前活动；开始后关闭全天记录，也不会在结束时补写摘要。人格页“共同活动”可显式选择保存本次进度与讨论。

人格页另有本地视频入口，可加载 WebVTT 字幕，读取当前播放进度和正在显示的字幕。仅当前片段交给 Agent，不装入未来字幕。手动“说话”按钮最多录入 30 秒并使用现有 ASR 服务，转写后作为用户发言；它不会录入作品原声或自行开启持续监听。

## 验证范围与限制

有界队列、过期回复拒绝、窗口切换、点透设置恢复、桌宠右键入口、持久化摘要和语音单活动取消有自动检查。具体游戏的画面识别、不同播放器、独占全屏或受保护画面的采集、Agent 反应时机及实际语音效果仍需现场验收；黑屏或无法识别应如实反馈，不代表已经看懂内容。视觉推断不能精确判断每一句对白的起止。

## 接口

通过当前 Host `status --json` 发布的 `managerBaseUrl` 访问，并核对 `/meta` 的代际和实例身份。接口沿用 Manager 的正常鉴权规则，已鉴权的远端 Agent 与本机入口使用同一公开合同；用户明确关闭的能力仍受限制。

- `GET /api/roles/{roleId}/companion`：预设与当前活动。
- `POST .../start`：`requestId`, 可选 `gatewayId`, `presetId`, `title`, `autoReview`, `voice`, 可选 `saveSummary`, `observationOwner`。
- `POST .../command`：`sessionId`, `revision`, `action`（pause/resume/seek/interrupt/stop/set-mode）；seek 加 `positionSeconds`，set-mode 加目录内的 `presetId`，返回当前活动的新版本。
- `POST .../observation`：活动与版本，以及有顺序号、时间和 JPEG 的 `observation`。
- `POST .../review`：活动、版本、可选用户 `text`。
- `GET .../frame?reviewId=...`：该次讨论的冻结画面，过期后不可读取。
- `POST .../reply`：`sessionId`, `revision`, `reviewId`, `text`, 可选 `state`, `activityKind`（play/watch/work/other/uncertain）。安静时 `text` 为空。
- `GET .../last`：最近一份主动保存的摘要；不会自动开始或恢复活动。

陪伴模块不自动建立记忆或计划。投递给 Agent 的缩略画面与文字仍可能由既有路线保存为附件、聊天历史或缓存，沿用其原有保留规则；关闭活动摘要不等于删除 Agent 历史。活动摘要以稳定活动 ID 原子保存，当前活动由 Manager 拥有。Agent 必须使用 fenced reply 回传；过期的 409 安静结束，不改成普通任务播报或外发消息。
