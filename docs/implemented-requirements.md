## 0.3.49 激活超时备忘

Developer 激活与发布脚本默认只等 120 秒；Host 自身允许 Manager 启动 180 秒、托盘启动 120 秒，另有健康准入与启动引导时间。外层预算短于内层预算，会把仍在正常启动的候选提前回滚。

本机日志显示，回滚指令抵达时候选 Manager 仅启动约 66 秒；随后替换进程遭遇旧 Manager 的单实例保护。0.3.50 已将两个脚本的默认预算统一为 420 秒，并把修复后的脚本纳入不可变候选包。代际围栏、指针比较交换、完整就绪核验与失败回滚继续生效。

420 秒是有界等待预算，不保证所有慢存储启动都成功。启动取消后的子进程退出时序、Manager 心跳失败重启、计划存储降级仍须分别跟踪；本次预算修复不作为这些问题已解决的证据。其他机器曾报告相似慢启动症状，尚未核对其现场日志，不据此认定同一根因。

本次正式安装为 `0.3.53-de9597b1bb16`，构建源码为 `074c19c9`，启用 v20 验收动作包。222 项桌宠回归和安装版复验通过。私有部署回执记录机器身份、完整代际核对、两屏生产窗口截图、安装版拖拽/抛掷/滞空循环/缩放证据；截图和运行数据不进入公开仓库。Host 整体健康仍为 `degraded`，不把桌宠验收扩写成所有后台功能健康。

## 同批源码合并

生产窗口复验发现并修复两项位置问题：0.3.50 在 75% 缩回 50% 后保留放大时的位置，造成 128px 空隙；首次载入又因占位框尺寸造成 10px 横向偏差。对应修复分别为 `7e4c4dc9` 与 `074c19c9`，均已包含在正式安装的 0.3.53 中。

生产窗口在 25%→50%→75%→50% 后，实际位置与大小均恢复，保存的位置配置保持一致。首帧位置、迟到素材期间的用户拖动，以及其他设置不重置当前位置均有独立回归。
