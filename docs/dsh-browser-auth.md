## 唯一执行与认证路径

RabiRoute 仍只通过当前 DSH Web owner 的会话接口访问任务；不启动第二 Runtime，不修改 DSH 认证、不从凭据库取得签名密钥或自行生成 Cookie。任务模型、工具、权限、会话和执行结果仍由 DSH 拥有；计划和投递回执由 Manager 拥有。

当前 DSH Web 使用启动登录 URL 在根路径交换 Cookie。旧的无认证桥会得到 HTTP 401。仅改端口不能恢复认证或旧版 RPC 合同。

## 会话桥地址选择

会话桥按顺序使用调用选项中的显式 `dshBaseUrl`、完整 DSH 主绑定的地址，最后调用共享 `resolveDshBaseUrl()`。没有完整主绑定时，默认读取和列表请求也使用现有本机发现：优先 `DSH_WEB_URL`，再读取 `DSH_HOME` 下已知启动日志中的干净回环地址；均未发现时仍使用原 `DEFAULT_DSH_BASE_URL`。只有地址、没有有效会话 ID 和工作目录的配置不算完整主绑定。

地址发现不扫描端口或切换目标实例；认证只使用目标 origin 的启动日志。会话列表收到 401 时可恢复认证并重试一次；写请求不自动重放。

## 自动连接已运行的本机 DSH

进入会话选择或发起投递时，桥在派发前恢复过期连接。优先使用已有端点日志配置；没有默认认证配置，或默认配置所指的旧启动日志已不存在时，使用已发现的本机 `DSH_HOME/logs/web-host.stdout.log`。只读取末尾 256 KiB 中与目标 origin 严格匹配的当前登录链接，不要求额外点击“连接 DSH”。过期授权经登录交换和只读会话接口验证后加密保存，保留原会话绑定；并发修改通过 revision 检查保护。显式注入的配置仍为权威来源。

手动断开仍保持断开。日志缺失、目标不匹配或登录验证失败时显示具体错误，保留手动连接入口。只有 `session/list` 的 401 可自动恢复并重试一次；任务写入、超时和断线不自动重放。连接恢复由实际请求触发，不增加后台会话轮询，也不启动另一个 DSH Runtime。

DSH 端点探测最多等待十秒，避免宿主加载目录期间因通用的一点二秒探测预算被误报离线，导致会话查询和自动恢复尚未执行就被跳过。

## 在 WebGUI 连接（开发中，尚未部署验收）

在本机 RabiRoute 控制台的 DSH 设置中使用“连接 DSH”：

1. 启动 DSH，确认下方的 DSH 地址指向当前实例。已有保存授权，或当前浏览器已经登录同 hostname 的 DSH 时，直接点击“连接 DSH”，无需填写密钥或登录链接。
2. 没有有效登录时，展开“使用登录链接连接”，粘贴 DSH 提供的当前登录链接后连接。链接包含访问凭据，不要分享。RabiRoute 验证登录和只读会话接口后，加密保存授权并自动填入不含凭据的地址。
3. 点击原有扫描按钮选择会话，再保存路线。连接或移除授权都不创建、删除或替换会话绑定。
4. 已有日志配置也通过同一个“连接 DSH”按钮验证并迁移；旧日志不可用时使用浏览器登录或当前登录链接。

浏览器登录复用只发生在用户点击连接时：浏览器自动携带的 HttpOnly Cookie 由后端按 DSH 的 hostname 和端口选择，DSH 验证其签名后才保存原有效期；不读取浏览器凭据库或签名密钥，不延长授权期限，也不转发其它 Cookie。`localhost` 与 `127.0.0.1` 是不同 hostname，需在相同 hostname 的控制台连接，或使用登录链接。过期记录可按上述本机启动日志恢复；已手动断开的记录必须显式重新连接。

授权只保存在当前电脑的 `stateRoot/data/dsh-connections/`，不属于角色同步数据。Windows 使用当前用户 DPAPI；其他平台使用本机受限权限密钥加密。DSH 目前授予的是整个 Web owner 的访问权限，不支持仅投递或单会话 scope。移除授权只停止 RabiRoute 使用，不会撤销其他客户端的登录。

同地址、同签名配置的正常 DSH 重启可沿用未过期授权。过期或签名配置变化可由本机启动日志恢复；换 hostname/端口时仍使用明确选择的地址，不扫描端口或自动切换到另一个实例。连接管理接口沿用当前连接鉴权合同；跨电脑分别连接各自的 DSH，不共享 Cookie。

### 接口与安全边界

- `GET /api/agent-adapters/dsh/connections`：返回 `ok`、`revision`、`endpoints`，仅含干净地址、状态、时间；`saved` 不代表在线。
- `GET /api/agent-adapters/dsh/connection?baseUrl=<origin>`：返回单项元数据及全局配置 revision，不扫描会话。
- `POST /api/agent-adapters/dsh/connection`：JSON `{launchUrl, expectedRevision}`，或直接连接 `{baseUrl, expectedRevision}`。直接连接依次复用保存授权、同 hostname 请求携带的目标 DSH Cookie，以及尚未迁移的显式旧日志配置；严格限定目标 origin，验证只读 `session/list` 后返回 `connection` 和新 revision。请求体不接受 Cookie。
- `DELETE /api/agent-adapters/dsh/connection`：JSON `{baseUrl, expectedRevision}`，保存断开标记，阻止旧日志配置自动恢复授权。
- 写请求遵循当前连接鉴权合同：允许本机请求及已鉴权且未被用户禁用的远端连接；本机浏览器检查 Origin，拒绝伪造身份、跨站和不可信转发头。请求体上限 16 KiB。冲突返回 409，重新读取后决定是否提交，客户端不自动重放。
- 认证只接受本机回环根路径和单一 token，不跟随重定向，凭据不进入普通配置、API 响应、错误或日志。登录交换最多十秒，只读会话验证最多六十秒；任务写入仍保持不自动重放的边界。

### 旧日志兼容的退出条件

`dsh-auth.json` 只为非标准启动器提供明确的端点日志映射；默认启动器直接使用已知的本机日志，无需新增配置。未建立保护存储记录的旧端点继续复用短时内存认证；过期保护记录通过同一目标日志验证并重新保存。手动断开阻止日志恢复，需显式重新连接。授权即时保存，不受路线表单取消影响；断开不能撤回已经交给 DSH 的任务。

旧配置只提供对应 origin 的凭据来源，不是可访问端点白名单。配置有效但没有当前地址的条目时，请求不携带其它地址的 Cookie，由目标 DSH 决定是否接受。明确断开的保护记录始终阻断自动恢复。

错误展示层将旧连接配置问题分类为 `dsh_connection_configuration`，将宿主认证交换、连接过期或断开分类为 `dsh_connection_required`，不再笼统标记为 Agent 业务权限不足。错误响应保留原始诊断，并附 `errorMessages.zh-CN/en`；WebGUI 的语言选项保存在浏览器，不是 Manager 全局语言设置，API 消费者应选择对应字段。中文提示中的连接入口为本机「消息路线 → 消息适配器 → Agent 端 → DSH → 连接 DSH」。自动接入和真实部署仍需单独验收。

对于 `DSH RPC transport failed; result may be unknown, check the original receipt before retrying.`，展示层使用 `dsh_transport_failed`，优先于 HTTP 400 的通用参数错误分类。它表示 DSH 连接传输未完成，不等于请求参数错误或 Agent 业务权限不足；原英文 `message` 和 `retryable: false` 保持不变。请求不自动重放，结果可能未知，应先核对原任务和操作回执，不能认定请求尚未执行。此修正只涉及展示，不改变 HTTP 状态码或认证、RPC 执行逻辑；尚未部署验收。

## 旧版本本机配置（兼容入口）

在 Host 的稳定 `stateRoot/data/dsh-auth.json` 配置端点和该 DSH owner 的启动日志路径。可用进程变量 `RABI_DSH_AUTH_FILE` 显式指定配置文件；不需要修改用户级环境或 DSH 启动方式。示例中的路径由运维替换为已核验的本机值：

```json
{
  "endpoints": [
    {
      "baseUrl": "http://127.0.0.1:3000",
      "launchLogPath": "/absolute/path/to/owner-stdout.log"
    }
  ]
}
```

配置不含 Token 或 Cookie，不要提交真实机器路径。日志必须来自目标 DSH 的现有启动器，包含当前进程输出的 `dsh web:` 登录 URL。此模式只支持明确的回环端点；远程认证不在本次范围。不扫描磁盘、浏览器或其它日志来寻找凭据。

桥最多读取日志尾部 256 KiB，严格选择同 origin、根路径、单一 token 的最后启动 URL。禁止跟随认证及 RPC 重定向；只接受根路径 303 和一个受支持的 HttpOnly Cookie。Cookie 仅在内存短时缓存并合并并发交换；配置路径或端点改变不复用旧缓存。错误不输出登录 URL、Cookie 或日志正文。

401 会清除对应缓存；只有会话列表查询可恢复后重试一次。超时或断线的写入结果可能未知，先查原任务/投递回执，不另建或盲目重发。没有匹配日志及保护记录时可由目标接受无认证请求；显式指定的认证文件缺失仍报配置错误。缓存不超过 Cookie 的 Max-Age/Expires 或本地五分钟刷新上限，拒绝删除和过期 Cookie。
