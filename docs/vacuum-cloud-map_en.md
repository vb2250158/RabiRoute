# Vacuum cloud map connection (experimental)

When “Start video” is clicked, the preview first verifies the current Manager identity and queries the video owner. An existing session for the same device and region is reattached without verifying the PIN again or starting another camera connection. Stopped sessions are not revived, and active sessions for another device are neither stopped nor taken over. A Manager identity change invalidates the query result. Normal exit, closing the detail view, and hiding the page retain their existing stop behavior.

WebGUI consumes the same session's video-only MP4 through MediaSource and checks the provider's actual Content-Type codec. It neither guesses codecs nor starts another camera session. Startup accumulates a0.3-second decode margin; normal playback stays at1x without seeking for brief jitter. Lag above0.65 seconds sustained for one second starts gentle1.03x catch-up, returning to1x below0.4 seconds. Lag above1.5 seconds sustained for one second seeks to0.3 seconds before the live edge, with at least five seconds between seeks. A position outside discarded history recovers immediately. Media is trimmed to the latest five seconds only when retained history exceeds six seconds. Exit releases the reader, object URL and player. Unsupported browsers or codecs fail explicitly without falling back to a player accumulating stale footage. The overlay's playback-buffer value measures lag behind received media, excluding camera, device transport and network delay; it is not an end-to-end zero-latency guarantee. Reference: fixed-version [go2rtc MP4 output contract](https://github.com/AlexxIT/go2rtc/blob/v1.9.14/internal/mp4/mp4.go).

The Manager Xiaomi Home provider supplies QR connection, raw maps, trajectory queries and explicit video sessions, shared by authenticated DSH, Codex and other Agents. Existing HA controls retain their API. Map and trajectory queries are read-only; video does not clean, drive, navigate or record audio.

In the current WebGUI Xiaomi Setup, select “连接扫地机地图（实验）”, generate a QR image, scan Xiaomi's original image with Mi Home and confirm login on the phone. Attempts expire after five minutes; explicitly start a new attempt afterward. Select the account region, discover vacuums and fetch the file. Alternatively append `/api/agent/xiaomi-home/vacuum-cloud/connect` to the complete dynamic Manager URL published by Host. Verify `/meta` using the [interface guide](rabi-agent-interfaces_en.md); never assume a port. Do not send passwords, cookies or tokens through chat.

## API

Paths below have prefix `/api/agent/xiaomi-home/vacuum-cloud` and reuse connection authentication.

Position reads follow the [official Xiaomi SDK data-source contract](https://github.com/MiEcosystem/miot-plugin-sdk/wiki/04-miot_spec#ispecgetpropertiesvalueparams-datasource--promisejson): datasource=1 prefers cached values, while datasource=2 sends a device RPC. A successful RPC does not prove that the localization engine updated its sample, so request time is not presented as pose time.

GET `/feedback?region=cn&deviceId=<device ID>&slot=0` returns `map` (the existing map result) and `feedback` for shared map/trajectory consumption. Omit continuation parameters on the first read. Subsequent reads pass the previous `feedback.scope` and `feedback.nextPoseId` as `scope` and `poseId`, together. A changed account, device, map, task or coordinate frame resets the cursor instead of merging points across tasks.

The provider brackets trajectory queries with map reads and queries one overlapping point before the consumed cursor. It returns `newPointCount` and `nextPoseId`; repeats do not count as movement again, and an older tail cannot replace a newer map position. `scope` is a continuation identity hint, not additional authentication or action permission. Clients discard it when switching devices, read serially, and stop when hidden. The API creates no background poller or navigation task.

Supported-model feedback includes `source=get-vacuum-route`, `coordinateUnit=millimeters`, and `yawUnit=milliradians`, verified against the official plugin's coordinate conversion. `observedAt` remains read time, with `poseFreshness=unverified` and `coordinateNavigation=false`. State `sample` only means a returned tail is not older than the map cursor; it does not prove movement or arrival. Missing map identity, task changes across requests, unsupported models and trajectory failures return an explicit unavailable state alongside the map. A readable cloud snapshot remains visible when trajectory reads fail. Clients must inspect `feedback.state`; HTTP 200 alone is not localization success.

## Map and coordinates

The provider's `vacuumMapDecoder.ts` decrypts version-2 JSON files with a16 MiB inflate limit and4 MiB grid limit. Failure retains the raw file with decoded=false without guessing its format. Grid fields include uint8-row-major data, width/height, mapId, originX/originY, resolution and rotation. Coordinates and resolution use millimeters in this format; rowZero is originY. Room labels come from the file; grid IDs are not device navigation parameters.

The page displays cells, room names, the dock, optional robot position and file read/change timestamps. Clicking selects a coordinate and requests a read-only path preview without a device action. robotPosition is a cloud file snapshot with poseFreshness=unverified. observedAt records download time, not localization time. Saved maps may have no robot position. Nonzero rotation and different model coordinate conventions require calibration before navigation.

The map fits the available width and height, with zoom in/out and reset-to-fit controls. The dialog follows screen height. Map details are collapsed by default. Zoom and viewport resizing preserve native point coordinates.

The video panel is responsive, keeps a 16:9 preview, and moves below the map in narrow windows. Saved PIN input is collapsed by default. Submission, connection and playback hide credential management; a confirmed exit restores replacement/deletion. An uncertain exit does not expose management early. See the [device UI guide](user-guide/home-devices_en.md).

## Credentials and recovery

Trajectory parse errors include a fixed reason such as invalid_json, points_type, pose_id or coordinate, without raw failing payloads or JSON parser excerpts. These diagnostics help verify the actual protocol; neither provider acceptance nor a parse failure establishes device movement.

The map includes a compact floating video preview. Playback shows only the picture; pointer and keyboard interactions toggle controls inside it without interrupting playback. “Start video” explicitly opens a bounded MISS session without audio, recording or robot movement. The existing Mi Home provider provisions ephemeral X25519 session material; the video process receives no cloud login credentials. Only the inspected pv11cn model and TUTK/CS2 transports are supported; other vendors are rejected. Compatibility requires a real first frame and browser playback, not an enabled camera switch or a connecting session.

On Windows, operators can run `scripts/Install-VacuumVideoTransport.ps1 -RuntimeDir <Xiaomi Home runtime directory>` to install pinned go2rtc 1.9.14 (MIT). The installer verifies the official ZIP and executable SHA256 digests and starts no process. Video uses hidden processes, a random loopback endpoint and internal authentication. Ephemeral keys are passed only in the dedicated child environment, never configuration files or argv. Video has no playback duration limit. Its IPC supervisor stops the native child on explicit exit, closing details, changing tabs, hiding the page or Manager disconnect. Handshake and individual frame requests retain deadlines; failures are reported without indefinite waits or automatic camera restart. New sessions omit expiresAt; historical receipts retain it for read-only inspection, never scheduling, and still report stopped after restart. Session JSON files under `vacuum-video/sessions/` record native/supervisor/Manager PIDs, lifecycle and first-frame evidence; native logs are disabled to prevent key leakage. Camera switch state still refreshes every five seconds; starting a stream does not automatically change that switch.

Under `/vacuum-cloud/video`, POST `/start` accepts `{deviceId,region,password?,rememberPassword?}` with an existing four-digit video PIN; POST `/stop` accepts `{sessionId}`. Both require current generation/instance headers and a stable Idempotency-Key. GET `/status` accepts either sessionId or idempotencyKey to reconcile the original session/receipt, never both. GET `/stream?sessionId=...` and `/frame?sessionId=...` return MP4 from an already started session and do not create another one. The start receipt is saved before PIN verification, without the PIN or a PIN hash. After restart the original start key returns stopped instead of restarting the camera; reconcile timeouts using that key. firstFrameAt is set only after a bounded MP4 check; browser playback is validated separately. Audio is always disabled.

The video panel provides a masked PIN field, cleared on submission. With rememberPassword=true, a device-verified PIN is encrypted locally and reused when password is omitted. The verified pv11cn plugin contract uses service 21: verify-video-password (action 7, original string input) and enter-exit-video-page (action 4, string 3 to enter and 4 to exit). A rejected PIN prevents page entry and MISS provisioning. Password setting/reset and sharing settings are never called. Stop, connection failure and normal Manager shutdown attempt one paired exit; pageExit reports completed or uncertain. An unexpected Manager crash stops the local transport through IPC disconnect but does not establish a confirmed device-page exit receipt.

GET `/trajectory?region=cn&deviceId=<device ID>&poseId=<cursor>` uses the existing authenticated cloud provider and ownership check to invoke the verified read-only get-vacuum-route contract. Explicit poseId is required (0–2147483647); models without a verified contract return422. It returns points, nextPoseId, newPointCount and optional latestReturnedPoint. It never enters remote mode or moves the device, and callers cannot supply siid, aiid, method names or arbitrary RPC. The initial contract comes from the official pv11cn version-61 package. pose_id becomes poseId while coordinates and optional yaw remain native values; replies are bounded to1024 points and128 KiB of trajectory JSON. Empty points produce no position. Device refusal, mismatched identity and malformed data fail explicitly. nextPoseId is a read cursor, not localization time. latestReturnedPoint may be historical; poseFreshness remains unverified and cannot prove navigation feedback or arrival. No persistent polling is started.

The same provider exclusively owns the cloud session, separate from HA OAuth and access tokens. `vacuum-cloud-session.json` lives in the plugin runtime directory. Windows uses current-user DPAPI; other systems reuse the restricted local-key AES-GCM protector. APIs never return cloud credentials, device tokens, signed download URLs or login callbacks. Mi Home login passwords and renewal passTokens are not stored; expired sessions require QR reconnection. There is no new persistent subprocess or background map polling. The page explicitly enables5/10/30-second refresh and schedules each read after the previous one finishes. Hidden pages pause, visible pages resume, and three consecutive failures stop refresh. Unchanged files only update the read timestamp without redrawing. The provider merges concurrent reads of the same object; later reads download again.

QR initiation retains durable key records and merges requests within the current instance. After a timeout, inspect status; the original key never creates another QR. Old attempts do not resume or replay after Manager restart: inspect connection state before explicitly starting a new intent. Rediscover after identity changes and verify identity after writes; failed verification means uncertain. Home map data must remain in authorized environments and never enter a public repository.

## Read-only path preview

The inspected pv11cn version-61 grid contract defines0 as unknown,1 as wall,2 as temporary floor and3–255 as rooms. Additional bits mark hidden1, unreachable2, carpet4 and object8; unknown bits are blocked. Other models remain cellSemanticsVerified=false. Additional grid length must match the base grid.

`vacuumPath.ts` uses the owned freshly downloaded map, requires its SHA256 to match the displayed snapshot, and starts only at the file's robot position. Eight-neighbor A* avoids diagonal corner cutting and inflates blocked cells, hidden polygons and virtual walls for clearance. The default250 mm radius is conservative preview input, not a calibrated robot dimension. Nonzero rotation, unfamiliar forbidden regions, absent position or insufficient endpoint clearance fail explicitly without snapping points. Limits are one million cells,20 million constraint checks,250,000 expansions and500,000 queue insertions. Blue dashed previews disappear after file changes; select again. This is not motion control, live localization or proof of physical reachability or arrival.

## Maturity

Developer diagnostics can download the owned vacuum model's official package for static protocol inspection. The pv11cn version-61 package has been retrieved. Its shared action-name table contains an arrive-at-designated-place name, but this model's spec has no matching action binding and no invocation parameters were found in the package. start-patrol appears only in the spec declaration; its string contract remains unconfirmed. This does not establish connected point navigation. Package files stay in local diagnostics and are neither executed nor copied into the public repository.

Tests cover an independent RFC 6229 cipher vector, merged QR requests, protected session recovery, token redaction, ownership checks, download limits, malicious redirects and bounded map decoding. Local acceptance completed Mi Home QR login, actual pv11cn version-2 download, decryption and rendering. Position changed between two files, but real-time freshness remains unverified. Other model formats, reliable live localization and physical navigation require separate acceptance. No navigation action or robot audio bridge is provided yet.

Read-only protocol reference: [Xiaomi Vacuum cloud connector](https://github.com/letitbe-dull/xiaomi-vac/blob/3b358103a0a04fd8cca9c15c35a0c453812311bc/custom_components/xiaomi_vac/cloud/connector.py). Password login and device commands are not ported. See [home device API](home-device-agent-api_en.md) for further boundaries.

Video page entry/exit accepts omitted or empty output under the official no-output contract, while retaining strict device, service, action and success-code checks; PIN verification keeps its separate strict output contract.

GET `/video/network?deviceId=...&region=cn` returns the owned device localAddress, onLinkInterfacePresent, connectionScope=local-or-relay and read time. The same provider resolves the address without returning credentials. A matching local subnet is not reachability or connection proof. This read verifies no PIN, requests no media keys and never enters the video page.

CS2 video adds experimental Xiaomi relay transport. When the authenticated cloud response supplies valid relay parameters, the existing video supervisor establishes a bounded UDP relay and forwards encrypted MISS data to pinned go2rtc. This path is retained even on the device subnet: matching subnets do not prove native MISS reachability and must not discard a usable relay offer. Handshake is limited to30 seconds; established sessions continue until explicit exit or IPC lifetime ends. Closing releases sockets and processes. Callers cannot choose relay addresses, and credentials, device UIDs and relay tokens never enter logs or receipts. Public state adds only connectionMode=local or relay and fixed failure reasons. Missing parameters retain the LAN path. This feature changes no routers, port mappings or system networking. Real first frames and browser playback require separate device acceptance.

Home Assistant provides device queries and control. The Xiaomi cloud provider still supplies map, trajectory and video extensions: the official HA integration explicitly excludes maps and P2P video, while community video paths require model-specific stream contracts such as camera-stream-for-google-home. Video management switches are not camera streams. This extension is not exposed as an HA camera entity. Wire-format reference: [micam CS2 relay documentation](https://github.com/eugeneRover/micam); only protocol facts are used, without its login implementation.

Relay port allocation reads the verified six-byte prefix (four-byte token and two-byte big-endian port), allowing trailing extension bytes. An independent eight-byte wire vector is covered by regression tests. Datagram length, source endpoint and nonzero port checks remain strict; handshake responses alone do not establish received video.

First-frame verification and browser subscriptions share a continuous video source. The component validates the first complete MP4 fragment, then reads and discards subsequent data until exit or Manager lifetime ends; it stores no recording. This avoids closing the MISS connection when a one-shot frame request ends, which would break the browser's subsequent subscription. A real relay session received its first MP4 frame on 2026-10-06; browser playback and physical navigation still require separate acceptance.


Registration failures allow up to three discovery rounds within the same 30-second handshake deadline, collecting fresh server tokens and retaining late discovery replies during registration. This does not reenter the camera or repeat cloud provisioning. Reconnect explicitly confirms exit of the previous session before a new connection intent. Manual control uses the [shared HA API](home-device-agent-api_en.md#shared-manual-remote-control), independently of cloud video.


CS2 first attempts a three-second UDP handshake at the provider-owned LAN address, verifying the source address and cloud UID. The same supervisor bridges encrypted MISS data over loopback to the pinned transport. Subnet membership or discovery replies do not prove playable video; MISS frames and browser playback remain required. A failed LAN handshake closes its sockets before using retained authenticated relay parameters within the same start intent, without repeating PIN verification, camera-page entry or cloud media provisioning. Network settings remain unchanged. LAN exit uses the verified CS2 close frame.

LAN handshake and close framing follow the pinned [go2rtc 1.9.14 CS2 implementation](https://github.com/AlexxIT/go2rtc/blob/v1.9.14/pkg/xiaomi/miss/cs2/conn.go); Rabi additionally verifies the cloud-owned device UID before forwarding.
