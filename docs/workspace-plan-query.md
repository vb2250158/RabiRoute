# 工作区计划查询

`POST /api/roles/:roleId/plans/query` 是只读分页查询，与 WebGUI 共用关键字递归匹配、状态/标签过滤和排序。正文支持 `query`、`cursor`、`limit`（1–250）、`view`、`sort`、`statuses` 和 `tags`。

必填 `bindingScope` 包含 `agentType`、绝对路径 `workspace` 与宿主确认存在的 `sessionIds`。任务或秘书绑定须同时匹配三项；空身份集合返回空页。过滤发生在排序、分页、总数和 facets 计算前。同一计划的多个绑定只产生一项。接口不查询 Agent 宿主，调用方负责提供当前工作区的真实会话身份。

DSH 的 Rabi 增强先通过路由角色配置匹配工作区，再按角色并行请求摘要页。按钮发现阶段不读取计划；弹窗按页加载，关闭取消读取和事件订阅。计划正文仍由 Rabi WebGUI 按需加载。

计划页目录的常驻拥有者数量有界。名额满时，仅回收已完成初始化、没有订阅者且没有未结束查询的闲置拥有者；确认旧资源停止后才接纳新角色。取消 HTTP 等待不等于底层查询已结束，初始化中或仍有工作的拥有者不被挤出。所有名额忙碌时仍返回容量错误，不删除计划、不扩大进程预算。

## 精确计划读取

精确计划投影使用有界异步身份读取，仍检查活动、归档和非规范物理目录中的重复逻辑 ID。冷查询不会因找到首个目标而跳过重复校验。强 ETag 来自完整存储包清单；包返回内容直接复用清单检查过的字节，不在计算哈希后再次读文件，避免并发替换造成哈希与响应内容错配；反馈摘要直接解析同次包读取中已经取得的 `feedback.jsonl` 字节，不再为摘要获取写租约、创建或回收锁。计划详情与角色工作流并行读取；工作流读取使用异步只读入口，不在 GET 中创建、迁移或升级配置，缺失时明确失败。此优化不解除启动恢复门禁，也不裁决旧计划冲突。共享存储超时仍是读取失败，不是空计划或恢复成功。

详情与列表呈现使用角色工作流已声明的 `legacyAliases` 解析旧标记，优先读取规范 `markerStatus`；响应中的标记键与呈现保持一致。该投影不修改计划字节、历史或强 ETag，不把生命周期状态当作工作流标记，也不猜测未知状态；未配置的标记仍明确失败。

## 启动恢复退出边界

启动恢复的 IPC 结果只作为待确认结果；子进程正常退出后才发布就绪。失败结果也等待进程退出后才安排重试。超时取消必须确认退出；若终止失败，保留原进程拥有者和 PID，保持门禁关闭，不启动重叠恢复。停止操作共享进行中的取消，未确认退出时不报告已停止。该约束不自动裁决存储冲突，也不放行尚未恢复的计划写入。

## 状态驱动推进

`GET/PUT /api/roles/:roleId/plan-advance/settings` 按角色和工作区保存状态规则。`POST .../check` 只返回候选、阻止原因、指纹及实际提示词；`POST .../run` 必须带检查得到的指纹，重新核对计划、审批、原绑定会话和空闲状态后才保留派发回执。自动推进默认关闭，状态提示词由角色配置提供。回执按工作区和计划持久去重；结果不明确时停止自动重试。派发走正式 Agent 线程桥，DSH 使用 `queue`，防止检查后出现的新回合被插入打断；真正执行前提示原会话重新读取计划。宿主提供当前工作区的真实 `sessionIds`，Rabi 不按标题猜测会话。

检查响应的 `total` 是当前工作区内符合已启用状态规则的计划总数，用于批量检查的查找进度；它不表示可推进数，实际可推进性仍以每项的 `eligible` 和派发时的重新核对为准。

同一批检查中的 DSH 会话状态按服务地址读取一次完整目录，并在派发前按会话再取一次状态快照；不为每个计划重复扫描全部会话。DSH 状态读取允许最长 10 秒，超时或不可达时仍阻止派发。原会话在状态快照后开始新回合时，`queue` 投递等待该回合结束。

实际派发内容包含该状态规则的可编辑推进提示词、角色工作流中的状态名称与说明、计划和当前步骤身份，以及只检查或继续已授权工作的动作约束。Agent 必须先重新读取计划与反馈；状态说明仅解释阶段，不代替最新计划或授权，也不会由检查接口直接修改计划状态。状态说明由角色工作流统一维护，工作区推进规则只保存该状态的提示词和触发设置。
