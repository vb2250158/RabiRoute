## 2. Current evidence and gaps

Implemented foundations include runtime schema compilation/validation in `apiOperationContract.ts`, `ManagerPluginRouteRegistry.registerOperations()`, active snapshots and request-scoped version isolation, OpenAPI projection, ETags, snapshot pagination, and `api.catalog.changed`. Discovery, upload GET/PUT, QQ connection diagnostics and group-file metadata reads, send, send capabilities, receipt reads, receipt verify/settle, Agent request list/read/cancel, and send traces use executable registration. Framework error responses are included automatically while retaining business response media types and header requirements. The connector adds `invokeOperation()` and `--operation`, resolves paths from discovery, conditionally refreshes on demand before calls, and never automatically replays writes. SDK types are generated from the same contract source.

Evidence is in `apiOperationContract.test.ts`, `apiOperationLifecycle.test.ts`, `apiDiscoveryRoutes.test.ts`, `apiRemoteContract.integration.test.ts`, `apiOutOfTreePlugin.test.ts`, and the connector's `api-catalog-client.test.mjs`. Tests cover independent out-of-tree registration, update, retaining previous behavior after an invalid candidate, and unloading. They do not establish installed or real two-computer acceptance.

Current `coverage.gaps` explicitly lists registered routes lacking executable contracts. It covers only entries visible to the registry. Unmanaged control-plane branches, resources, SSE, and upgrades still require inventory; this field cannot establish whole-project coverage. The manual `agentApiPolicy.ts` catalog and old compatibility handlers have not been removed. Stages C–E remain outstanding.
