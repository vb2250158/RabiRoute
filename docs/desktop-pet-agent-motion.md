# 桌宠移动接口

Agent 通过 Manager 指挥已启用的桌宠走路、奔跑或传送，Qt Desktop 复用当前动作包和移动动画执行。无需开启闲逛；接口也不会修改闲逛开关、窗口焦点或应用窗口位置。

希望桌宠平时移向激活窗口时，在 WebGUI 人格的虚拟形象设置中开启闲逛与移向激活窗口；对应绑定配置为 `wanderEnabled=true`、`wanderToActiveWindow=true`。桌宠按配置的等待间隔重新读取前台窗口，再选可达位置。陪伴期间暂停闲逛，结束后恢复；这与下面的一次性移动指令独立。

先从 Host 当前状态发现 Manager 地址，并按[Agent 接口](rabi-agent-interfaces.md)核验 `/meta` 的代际与实例身份。

`POST /api/desktop-pet/roles/:roleId/motion`，请求头 `Content-Type: application/json` 和 `Idempotency-Key`（与 `requestId` 相同）：

```json
{"requestId":"pet-move-0001","mode":"auto","target":{"kind":"active-window","corner":"bottom-right"}}
```

| 字段 | 合同 |
| --- | --- |
| `requestId` | 8–128 位 ASCII 标识，允许字母、数字、`_`、`.`、`-`，首位为字母或数字 |
| `mode` | 可省略，默认 `auto`；`walk` 强制走路，`run` 强制奔跑，`teleport` 强制传送 |
| `target.kind=position` | `x`、`y` 为 Qt 逻辑桌面像素整数（不是物理像素），范围 ±100000，支持负坐标；目标须位于已连接屏幕，并按工作区边缘收敛以使整个桌宠可见 |
| `target.kind=screen-corner` | `corner` 指定屏幕角；可用 `screenName` 选择 Qt 屏幕名，否则使用桌宠当前屏幕 |
| `target.kind=active-window` | 在执行时读取激活窗口的可见边界与所属屏幕；只移动一次，不持续跟随 |
| `corner` | `bottom-right`、`bottom-left`、`top-right`、`top-left` |

坐标指桌宠窗口左上角。`auto` 与闲逛使用同一距离规则：起终点欧氏距离超过桌宠所在屏幕可用宽度的一半时奔跑，其余走路。距离与屏幕宽度均为 Qt 逻辑像素，跨屏目标也按此规则选择；自动远距离传送已移除，传送须显式选择 `teleport`。窗口角目标会缩进并限制在可用工作区内。

奔跑使用包内独立的循环 `run` 动画，以该动作的接地步长和播放周期计算速度，保留腾空阶段。缺少 `run` 或无法标定有效步态时失败并保持原位置，不把走路加速后当作奔跑。旧动作包可继续显式走路；需要自动远距离移动时，导入含 `run` 的新包。

Desktop 在预载时用最长边 256 像素的统一参考帧标定步长：按透明度 ≥128 的角色有效像素确定实际高度，在底部 12% 的脚部区域分开左右鞋底，并对底部约 1% 高度的像素取平均位置。接地容差随角色有效高度变化，双脚靠近时不会缩小正常步长的过滤上限。以连续接地鞋底相对素材朝向的后移量标定整周期步长；鞋底前移、换支撑脚、静止帧和不可靠的跳变不计入标定。参考步长和脚底高度偏移按实际渲染宽高等比例换算为 Qt 逻辑像素，避免小尺寸重新采样导致速度比例失真；屏幕 DPI 由 Qt 换算，不重复乘缩放倍数。速度为周期步长除以实际播放周期时长，随显示大小及帧率上限变化。走路期间同一精确计时器驱动动画和连续位移，约每 16ms 更新位置，不再每换一帧跳动一次；延迟回调最多推进 50ms，动画和身体一起减速，不追赶到远处。GIF 保留原始帧时长，脚底高度按动画校正，不另加弹跳。无法测出有效步态时拒绝走路。

动作包根字段 `sourceFacing` 标记原始素材朝向（`left` 或 `right`，缺失/无效时兼容默认 `right`），由 Manager 校验并传给 Desktop。首次迈步前按目标方向决定是否镜像，向原始朝向行进时不翻转。抵达后读取当前激活窗口中心，用 180ms 的原地镜像过渡朝向中心；没有可用窗口或已朝向中心时保留朝向，中心附近 8 个逻辑像素内不反复翻转。窗口位置不变，帧序列保持正向播放。取消、拖动、隐藏或新移动会终止转身，新移动立即朝行进方向迈步。

切换动作包会先取消移动，再加载新包；旧包迟到的动画、预载和目录结果不会进入新包。重复的移动状态不重启帧序列或开启第二个时钟，动画丢失时停止位移。选定包不可用时显示错误，不自动替换为另一个缓存包。从 Manager 改变显示大小后，Desktop 会按新尺寸重新准备缓存中的动作和步长。

这是基于现有二维素材的步频与步长估算。正面踏步素材的左右镜像不等于侧面转身；任意斜向路径也不能保证支撑脚完全锁定在地面。严格无滑步需要对应方向的走路素材和足部接触标定。

陪伴模式的状态更新和即时小动作不会打断显式移动、拖动、点击回应或正在播放的语音；错过的小动作直接跳过，不积压到空闲后补播。点击回应结束、拖动松开和移动抵达后，按当前语音状态恢复说话或待机，不恢复已经结束的语音。循环回应最长播放 30 秒，并受 Manager 事件有效期限制；被动陪伴回应不计为用户活动，不推迟休眠。

“全屏时隐藏”只在桌宠所在屏幕出现真正全屏的前台窗口时触发；普通最大化窗口、桌面和其他屏幕的全屏窗口不会隐藏桌宠。离开全屏后恢复当前动画状态；全屏期间禁用桌宠不会因随后切换焦点而重新显示。

切换动画前完整解码新素材，失败时继续播放原动作。普通静止动作之间保留旧画面并用 120ms 过渡；走路、传送、拖动和转身期间不叠加画面。重复的同一状态不重置播放进度。GIF 与 PNG 序列共用播放器，GIF 保留帧时长，循环和后续动作以动作包声明为准。随机待机优先避开最近两个小动作，动作池较小时退回避免连续重复。

查询 `GET /api/desktop-pet/roles/:roleId/motion/:requestId`，成功返回 `code=0`、`data` 回执：

- `accepted`：Manager 已接受，尚未由 Desktop 领取。
- `running`：Desktop 已领取，可能在准备动画或正在移动。
- `succeeded`：Desktop 报告抵达，包含实际 `position`、解析后的 `destination` 和 `travelKind`（`move`、`run` 或 `teleport`）。已经站在目标附近时可直接成功。
- `failed`：禁用、隐藏、锁定、拖动、已有移动、缺少动画、无法解析目标或 Desktop 未领取等失败。
- `cancelled`：移动被点击、拖动、隐藏、关闭或屏幕变更打断。
- `uncertain`：Desktop 领取后超过 30 秒没有抵达或实际移动进度确认，不能假定未移动。慢走期间只有位置确实变化，Desktop 才每五秒用当前 claim 续报 `running`；进度不等于抵达，停滞不会无限续期。

同一人格同时只接受一条 Agent 移动。显式移动可以唤醒睡眠，鼠标操作与隐藏/锁定仍优先；正在闲逛时返回失败，等待其结束再发新请求。动作包须具备本次选择的 `move`、`run` 或传送 `teleport-out`、`teleport-in` 动画，准备时间最多 10 秒。

相同 ID 与相同参数只返回原回执，不重复移动；相同 ID 不同参数返回 `409`。受理返回 `202` 不代表抵达。请求结果不确定时先查询原 ID；禁止改 ID 自动重发。

回执只保留在当前 Manager 代际的内存中，终态保留一小时，最多 1000 条。重启、过期或切代后的 `404` 表示结果不可恢复，不能据此推断未移动。未领取超过 20 秒标为失败。Desktop 内部 claim/result 接口不开放给 Agent，回执不包含 claim token。

手动拖拽由约 16ms 的独立时钟平滑跟随指针。Windows 使用同一原生像素坐标系读取指针和窗口位置，抓取点按比例记录，跨屏时保持原生像素尺寸，支持负坐标屏幕。拖住期间捕获鼠标，不执行屏幕边界收拢、位置恢复或全屏隐藏；切换拖拽动画也不会把角色拉回原屏。轻放时以当时的指针位置作最多 180ms 的短暂收尾，不再跟随之后的指针移动；随后将角色收拢到松手屏幕的工作区并保存位置。同名显示器的位置键附带屏幕原点，避免位置同步后回到第一块同名屏幕；旧的普通屏幕名仍可读取。轻微抖动保持点击语义；窗外松手、隐藏或关闭会释放拖拽状态。

快速甩动后松手会按最近 100ms 的原生指针轨迹计算初速，加入惯性、重力、边缘反弹和地面摩擦；停止拖动后再松手则正常放下。力度和重力随当前窗口像素尺寸缩放，跨屏 DPI 变化不会混用坐标。飞行使用不超过 1/240 秒的积分子步，单帧最多补算 50ms；相邻显示器接缝放行，桌面空洞和外边缘反弹，落地线采用工作区以避开任务栏。飞行期间保留拖拽交互状态，不被自动走动、位置同步或动画结束打断；落稳后保存一次位置并恢复当前待机、陪伴或说话状态。再次抓取立即接管；隐藏、关闭、锁定、缩放或开启鼠标穿透会取消飞行。

桌宠大小按原生像素计算：动作包画布乘以 10%–200% 的缩放值后得到固定像素尺寸。切换显示器或 Windows DPI 时，角色像素尺寸保持不变；只换算 Qt 窗口的逻辑尺寸，原生窗口约束配合固定像素图片，透明窗口边缘最多保留 1 像素的小数舍入余量。图片解码缓存和播放进度不因跨屏重建；步幅和气泡锚点换算为所在屏的 Qt 单位，实际像素步幅保持一致。右键“大小”滑块直接预览已解码帧，关闭菜单后保存大小与当前位置；预览不反复解码或重启动画。

动作包可增加 `lift`（一次性提起，结束后进入 `drag`）、`throw`（一次性抛出，结束后进入 `airborne`）与 `airborne`（循环滞空）状态。松手后的飞行期间持续播放滞空动作，角色随水平速度轻微倾斜并摆动；窗口像素尺寸保持不变。落地或重新抓住后清除倾斜，恢复当前陪伴、说话或待机状态。旧动作包继续使用 `drag`。这些状态不会加入随机待机池。
