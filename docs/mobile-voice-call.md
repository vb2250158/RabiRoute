# 手机语音通话与消息路线

[English](mobile-voice-call_en.md) | 简体中文

> 状态：实验实现。自动检查与构建不能替代实际手机的多轮语音、听感、断网及记录恢复验收。

## 使用

消息列表每行对应电脑提供的一条可选 RabiLink 消息路线。同人格的多条路线分别显示：左侧头像，第一行左侧人格名、右侧“电脑名 · 路线名”，第二行左侧最后消息摘要、右侧消息日期或时间。仅有人格而没有启用手机消息路线的配置行不进入该列表。连接和入口诊断放在会话详情及设置中；本地历史保留，已下线路线的历史仍可按原路线通知入口查看。

进入会话，点右上角“电话”。需要手机麦克风权限，以及电脑发布的通话协议版本。通话开始时固定电脑身份、路线和登录连接，后续切换消息列表或其他电脑不会改变本次通话目标。远端人格资料的来源电脑与路线所属电脑是不同概念：列表右侧始终显示拥有路线的电脑；远端人格名称未取得时使用明确的人格 ID，不拿本机同名人格的头像或名称代替。

通话页面显示连接、收音、等待回复、播报、静音或错误状态。每句声学有效录音仍保存为记录，复用 PC 转写，最终非空转写立即进入当前路线的正式消息队列。普通“仅转写”记录没有通话授权，不因此唤醒 Agent。

“静音”阻止新的麦克风数据进入记录和上行；回复仍可播报。“挂断”停止本次通话采集和自动播报，保存已接收声音，并按原记录设置恢复既有记录任务。保存失败时保持停止并报告原因。用户在记录页明确切换或暂停时结束通话，由新的记录操作决定后续采集。通话本身不修改持久化的记录开关、模式和路线。进程退出后不自动恢复通话。

当前为轮流说话：播报会抑制收音，不支持自然插话。手机以 AudioTrack 播放完成标记作为播放确认，这不证明音量合适、外部设备听得到或听感正常。

## 投递和迟到回复

- 通话输入从录音结束时起最多有效 90 秒。手机投递前和 PC 接收后分别校验。过期、挂断后尚未送出的输入保留为录音，不在重连后无限补投。
- 每个最终事件使用稳定的 `rabi-call-v1` 来源消息 ID，包含通话、截止时间、电脑、路线和事件摘要。Relay 可以只透传；PC 在正式转发前校验完整身份与时效。电脑或路线不一致时拒绝，不改投。
- PC 对同一来源 ID 持久化一次领取。领取后异常或进程退出可能使结果不确定；重复输入不再次触发 Agent。用户可以通过新一句话发起新的输入，原录音仍可审阅。
- 来源 ID 经 AgentPacket 和正式 RabiLink 发送入口传递到回复的 `taskId`。只有关联到当前通话且路线相同的回复自动在手机播报。旧通话、挂断后到达、另一条路线或缺少关联的回复保留为聊天消息；缺少关联时不把普通回复猜成当前通话回复。
- 挂断不表示已经取消电脑上的 Agent 执行。已经送达的输入可能继续处理；Relay 已接收但 PC 尚未处理的输入仍受上述 90 秒时效约束。

领取记录在落盘并同步后发布写入审计，只记录输入摘要和结果，不保存录音正文、来源 ID 或本机目录。

## 维护边界

`RabiConversationService` 是唯一协调 owner，复用 `CaptureOwnership`、`RabiPhoneAudioCapture`、声学切句、durable spool、`RabiEventAsrUploader` 和手机播放器。通话采集使用冻结的 `call_` captureId 与仅转写策略；最终转写回调只向正在进行的对应通话授予消息投递。

已有记录上传授权照常冻结。通话事件先完成同一 ASR actor 的最终转写回执，再进入既有可靠归档上传，避免归档清理与读取 PCM 冲突。网络故障不删除录音；语音输入的实时截止时间与记录的可靠保存、归档是不同合同。

SDK 的 `getMobileRoutes` 返回真实可选手机路线；`getMobileRouteCatalog` 仍保留完整配置目录用于管理，不能将它直接当成聊天选择列表。手机缓存保留路线所属电脑、电脑名、人格来源电脑及通话协议版本。PC 路线摘要由 `src/manager/rabiApi.ts` 提供，输入围栏由 `src/shared/mobileVoiceCall.ts` 与 RabiLink adapter 实施，不修改处理端 Runtime，也不创建备用执行链路。

验收必须覆盖同人格多路线、正确电脑与路线、至少两轮实际语音、最终转写投递、手机播报、静音、播放中挂断、旧回复到达、新通话与旧回复隔离、原记录恢复、断网与过期输入，以及权限或 PC 能力不足。分别记录逻辑测试、构建、安装、实际设备和听感证据，不相互替代。
