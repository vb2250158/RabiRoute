# 現在の能力と成熟度

0.3.22 接続契約: 同じ RabiLink アプリケーション内の認証されたデバイスは、PC によって実際に提供されるすべてのサービスを使用できます。ピン留めされたキーとアプリケーション スコープはチェックされたままになります。ナレッジの読み取り/書き込みは、別個の MCP シークレットやナレッジ付与を必要とせずに、マネージャー API を再利用します。サービスごとの権限フィールドと許可エディターは廃止されました。参照 [一般的な接続](rabilink-peer-tunnel_en.md) そして [ナレッジランタイム](rabilink-knowledge-runtime_en.md).

インストールされている Web ホット パッチは実験的なものです。参照 [Web ホット パッチ](web-hot-patches_en.md) 実稼働ビルド、ロールバック、バージョンの固定、およびインストールの受け入れ用。

この文書は、現在のRabiRoute作業ツリーに実際に存在する機能について説明する。要件、設計提案、外部デバイスのアイデアは、完成した機能としては提示されません。結論は、構成スキーマ、ランタイム エントリ ポイント、マネージャー API、WebGUI、アダプター実装、および対応する自動テストから得られます。導入と物理デバイスの証拠は、機能ごとに個別に記載されています。

メッセージエージェントリスト、タスク制限、および実際の配信は、1つの重み付けされた順序を共有する。つまり、引用されたエージェントが送信し、元のメッセージグループ、エンドポイント、会話、送信者、および最近の使用が優先され、安定したインデックスはタイブレーカーとしてのみ使用される。制限の削減後、未完了の計画進捗通知、計画/メモリ コールバック、エージェント間の応答要求、およびリマインダーは、ランク付けされた範囲内の現在のタスクに移動します。メッセージ エージェント モードが無効になると、これらのフォローアップと新しいチャット メッセージは、古いメッセージ エージェント タスクを再度開くのではなく、現在のルートのプライマリ ペルソナに送られます。完了した記録は、監査のために元の作業者を保持します。

## 成熟度の定義

ソース ホット パッチは実験的なものです。共有カタログが新しいモジュールを自動的に登録し、ソースとリソースを監視し、プラグイン サービスを通じて互換性のある更新全体の状態を保持します。テストには、自動登録、非同期リビジョン リース、障害の分離、繰り返しの更新、および回復が含まれます。任意の TypeScript 構文、自動構造移行、およびすべてのビジネス モジュールのカバレッジは不完全なままです。参照 [ソースホットパッチ](source-hot-patches_en.md) スコープとアップグレードの承認について。

|ステータス |意味 |
| --- | --- |
| `verified` |リポジトリには、完全な実装、構成/診断エントリ ポイント、および自動化されたコントラクト テストが含まれています。外部プラットフォームでは、依然としてアカウント、ログイン、または実際のハードウェアが必要な場合があります。 |
| `experimental` |コード パスと構成エントリ ポイントは存在し、部分的なテストまたはスキャン診断が行われますが、外部システムとのエンドツーエンドの互換性には依然として環境固有の受け入れが必要です。 |
| `stub` |アプリを開く、プロンプトをコピーする、ハンドオフ ファイルを書き込むなど、限定的なハンドオフのみが存在します。信頼できるバックグラウンド配信として宣伝してはなりません。 |
| `planned` |提案または計画だけが存在します。現在のコードはループを実装していません。 |
| `historical` |この文書には、置き換えられたルート、調査、またはハンドオフが記録されており、現在のプライマリ パスは定義されていません。 |

これらは、RabiRoute 独自のスキャン API によって使用される成熟度の値です。これらはサードパーティ プラットフォームからの製品認定ではありません。

## 現在のコアパス

```text
Message Adapter / Manager Entry
  -> JSONL Event Store
  -> RouteDecision
  -> AgentPacket
  -> Agent Adapter
  -> Outbox / Reply
```

RabiRouteは、イングレス、ルールマッチング、コンテキストパッケージ化、ハンドラ配信、応答ルーティング、および監査を所有する。ハンドラーは、応答、実行、ツール呼び出し、およびプライベート セッション状態を所有します。

## メッセージ入力

音声イングレスは現在、発話全体のRMSとタイミング、ソース、モデル、および完全なターンを含むピークをホスト全体のメッセージに一度保存し、次にそれらの事実を各ペルソナ自身の履歴/コンテキストにスナップショットする。ラウドネス フィールドは音声のみを記述し、ホスト ID の境界を拡張しません。

リポジトリは、いくつかのTTS音声を1つのWAVに構成するローカル声紋プリフライトも提供する。複合内の境界ごとの抽出とクラスタリングを検証しますが、明示的な境界は自動 ASR ダイアライゼーションの証拠ではなく、合成出力は正式な実際の人物のキャリブレーションには適していません。

ターゲットデスクトップタスクにおけるコマンド、ファイル、ネットワーク、許可、およびツールの承認は、RabiRouteの外部メッセージ送信ボックスポリシーとは別のままです。

## 送信トレイと明示的な送信

`POST /api/agent/send` は唯一のエージェントのアウトバウンド エンドポイントです。安定したものが必要です `deliveryId`、呼び出し側エージェントの `sender.agentType + sender.sessionId`、正確 `routeId`, `channel`、チャネル固有 `params`、および `payload`;レガシー `/api/agent/replies` が削除されます。戻ります `sent`, `draft`, `blocked`、または `failed`。完了した送信は次のようにクエリできます。 `deliveryId` またはチャネルによってトレースされ、 `sentMessageId`.

|出力 |現在の動作 |

## マネージャーと WebGUI

- Windowsパッケージでは、1つのRabiRouteホストがアプリケーション世代のマネージャとトレイの子を作成します。どちらも 1 つの Windows ジョブに参加します。トレイは構造化された Manager READY の正確な検証後にのみ開始され、どちらかの子が失敗すると、制限された世代全体の置き換えが発生し、並列ガーディアンはユーザーの終了を元に戻すことはできません。
- Linux ソース ビルドでは、最小限の Linux ホスト (`scripts/linux-host.mjs`) マネージャーのライフサイクル、動的ループバック アドレスを所有します。 `flock` 単一インスタンスのリース、およびステータス/再起動/終了コマンド。 UI は RibiWebGUI です。 Windows/Qt トレイ、スクリーンショット、グローバル ホットキーは対象外です。参照 [Linuxホスト](linux-host_en.md).
- マネージャは、オペレーティングシステムが割り当てたループバックポート上でRibiWebGUIおよびHTTP APIを提供し、ルート設定、プロセスリースバインドされた子、スキャン、ログ、およびグローバル設定を所有する。 Windows パッケージは、ホスト ステータスまたはトレイからこの世代の URL を取得します。デフォルトの固定ポートはありません。
- マネージャーは、専用のワーカー スレッドで大規模な音声履歴の読み取りを実行します。最大 2 個が同時に実行され、最大 8 個の待機が行われ、それぞれに 30 秒の期限があります。キャパシティーおよび期限の障害は、メインの HTTP スレッドを応答不能にするのではなく、明示的な 503/504 応答を返します。時間制限のある音声クエリでは、アーカイブ インデックスを使用して、内容が読み取られる前に重複しないファイルを除外します。同じ範囲に対する同時の概要のみのリクエストは 1 つのスキャンを共有します。 `GET /meta` は、アクティブな、キューに入れられた、および設定された制限を公開します `readWorkers`.
- 完全なルート診断は、限定された JSONL テールのみを読み取り、1 つの応答内で同じファイル結果を再利用します。また、マネージャーはヘッダー受信を 10 秒、リクエスト受信を 30 秒、アイドル キープアライブを 5 秒、1 つの接続を 100 リクエストに制限します。 `GET /meta.httpLimits` はこれらの値を公開します。
- コンソールは、LAN WebGUIアクセスを明示的に有効にし、専用キーを生成またはローテーションすることができます。 `data/Config.json.webguiLan`。 Manager が再起動すると、リスニングがループバックから LAN に変わります。経由してローカルで開かれたページ `localhost/127.0.0.1` 次に、現在のルートとページを保存しながら、優先LAN IPにリダイレクトします。非ローカル マネージャー API、SSE、およびプライベート リソース リクエストには、次の情報を含める必要があります。 `webgui_token` または専用のリクエストヘッダー。静的シェルのみをロードすると、データ アクセスは許可されません。スイッチとキーは、ループバックまたは独自の LAN アドレスの 1 つを介して管理者 PC 自体からのみ管理できます。他のデバイスは拒否されたままになります。サイドバーの変更 **現在のルート** リダイレクト `#/routes/<Route-config-name>/overview` または `knowledge`、コンソールは対応する完全なリンクをコピーできます。
- RabiLink Relay管理にサインインした後、 `https://<relay>/manage/<account>/<RabiGUID>/` 選択されたPCの完全なWebGUIコントロールプレーンを公開する。通常の API、画像、添付ファイル、オーディオ、ダウンロード、およびビデオの範囲は、アプリケーション トークンで認証された PC ワーカーを通過します。 Manager SSE は専用のライブ イベント チャネルを使用します。管理クッキー、RabiLinkアプリケーショントークン、LAN `webgui_token` 3つの別個の境界が残る。
- 現在のWebGUI領域は、コンソール、メッセージアダプタ、ペルソナ構成、プランおよびメモリ、音声サービス、モデル管理、ログ診断、およびユーザガイドである。モデル管理はホスト スコープであり、選択されたルートに従いません。クイック セットアップでは、入力、ハンドラー、ペルソナを選択します。
- 最初に読み取られたWebGUIは、ログ、メッセージファイル、または完全なペルソナ本体を含まない完全な編集可能なルート構成を返すようになった。コンソール、メッセージ アダプタ、およびログ診断は、必要な場合にのみ、より重いランタイム診断を要求します。ペルソナ設定には、最大 420 文字のプレーンテキストの概要が表示されます。 **ドキュメント全体を表示** 別の Markdown リーダーを開きます。どちらのページも選択した内容を読み取ります `persona.md` すべてのペルソナ本体を最初のファイルに埋め込む代わりに、制御されたペルソナ ファイル エンドポイントを介して `/gateways` 応答。
- パフォーマンス概要および最近のレコードは、ページトリガーによるフラッシュやJSONLの再解析を強制することなく、最大48時間をカバーするマネージャ限定生キャッシュおよび増分集計を読み取ります。音声読み取り専用ファイルとデバイス スキャンはワーカー スレッドで実行され、オーディオ ストリーム イベントはインデックス付き逆方向制限読み取りを使用します。初期テーマ、軽量ルート ステータス、メタデータ、およびネットワーク オプション リクエストは同時に開始されるため、ログ診断は無関係な起動読み取りをシリアル化しません。
- ペルソナデータの同期は廃止される。そのボタン、変更されたファイルのプレビュー、手動同期、および競合ワークスペースは、現在のエントリ ポイントではなくなりました。これは無効化されたスイッチではなく削除です。 RabiLink を使用して、レプリケーションを行わずにターゲット PC 上のペルソナとデータにアクセスします。参照してください [退職](persona-data-sync_en.md).
- **アイデンティティのポジショニング** は次のように分割されます **認識されたアイデンティティ** そして **認識されないアイデンティティ**。最初のグループは、QQ、WeChat、声紋、その他のエンドポイント アカウントを個人ごとに確認しました。 2 番目は、所有者がまだ不明なアカウントをエンドポイント タイプごとにグループ化し、ニックネームごとにマージしません。認識された人は、カード全体をエントリーポイントとして使用します。 1 つのワークスペースでは、基本的な詳細、エンドポイント アカウント、話し方の習慣、および関係を、3 つのドットのドロップダウンや個別の長期および短期の関係タイプなしで維持します。声紋は 1 つの確認済み ID に明示的にリンクでき、関連付けが間違っていた場合はその ID ワークスペースからリンクを解除できます。音声セクションは、最初のエントリ時に過去 24 時間の履歴をスキャンしません。ユーザーが選択した場合にのみ読み取りが開始されます。 **分類を更新** または始まり **次のセグメントをマークする**;後の記録イベントと関係イベントは、そのセクションがアクティブ化された後にのみ更新されます。
- Plans & Memory は、コンテンツを 4 つのタブに分割します。 **現在の計画**, **最近の記憶**, **統合されたメモリ**、および **アーカイブ済み**。現在の計画には、ペルソナ ステータス定義に次のものが含まれるアーカイブされていない計画が含まれています。 `current` ビュー、アーカイブでは独立したビューが使用されます `archiveStatus=已归档`。マネージャープロジェクトのステータスキー、ラベル、説明、パレット、順序、およびビュー `personaConfig.json.planWorkflow`; WebGUI とトレイには固定のステータス テーブルがありません。このページは、まず Manager によってソートされた 8 つの軽量の計画サマリーまたは 24 個のメモリー項目を読み取り、すぐに計画サマリーをマウントします。概要には、プレゼンテーションのステータス、現在のステップのタイトル、進行状況の数、添付ファイルの数、および更新時間がすでに含まれているため、本文を待ちません。表示されている間、ページは選択したプラン カテゴリを 8 つのバックグラウンド バッチで続行し、表示されているメモリ カテゴリを最大 100 ページで継続します。バックグラウンド プランの完了により、最初の画面のグローバル プログレス バーをアクティブのままにせずにカウント ステータスが更新されます。後ほどプランページを送信します `facets=0` 最初のページでステータスとタグ ファセットがすでに提供されているためです。カードが読み取り位置に近づくと、 `detail=preview` は、最大 4 つの同時プレビュー要求で、その説明、現在のステップの詳細、ブロッカー情報、および添付ファイルのメタデータを読み取ります。画像、ビデオ、マークダウンの添付ファイルは折りたたまれたカード上に表示されたままになり、優先度の低い読み取りが使用されます。カードを展開すると、エージェントの状態とフィードバックをクエリしながら、完全なステップと承認契約が取得されます。作業履歴は、オンデマンドで個別に改訂履歴を取得し続けます。非表示のタブはこの作業を一時停止し、再度表示されたときに続行する前に更新します。コンテンツ領域は、境界のあるレンダリング ウィンドウを保持し、現在のカードの位置を維持しながらバッチで調整します。
- プランリストのソートは、ステータス、更新時間、重要性、および緊急性をサポートします。更新時間にはタイムスタンプが使用されます。マネージャーは、並べ替える前にステータス、重要性、緊急度を整数レベルにプロジェクトします。重要性が優先 `importance`、レガシーの変換 `priority` 読み取り境界で 1 回。緊急性が優先されます `urgency`、従来のプランではオプションで互換性レベルを次から導き出します。 `dueAt`。ラベルとパレットはレベルごとに個別にマップされ、各ディレクトリ行にはアクティブな並べ替えモードの末尾ラベルが 1 つだけ表示されます。
- 最近のメモリカードは、最後の真のリコールヒットとは別に記録時間を表示し、マークダウンテキスト/画像を安全にレンダリングする。マネージャーは、最も早い 72 時間の期限に合わせてワンショット タスクを設定し、トリガー時間と 24 時間の候補上限を固定して、実行を自動的に実行します。遅延実行では、後の境界交差は追加されません。 WebGUI には、最後の 24 時間のみ、個別のカウントダウン、最もアクティブでないメモリ、候補数、およびカード マーカーが表示されます。完了した統合からの最近のソース レコードは再び候補にはなりませんが、生成された統合メモリは呼び出し可能のままです。
- RabiLink は、ホーム、リモート エージェント、および構成を組み合わせます。構成には、インスタンス名/GUID、リレー接続、およびエージェントのアップロード制限があり、詳細な接続パラメータの下にタイムアウトとローカル音声サービス アドレスが含まれます。古いサービス許可スイッチとナレッジ フォームは廃止されました。ディレクトリと LAN アクセスは [設定] に残ります。コンソールにはルートのライフサイクル制御が保持されます。ホーム デザインはコンパクトなネイティブ読み取り専用ビューで、中国語の UI に中国語のラベルが付いています。 Manager は、埋め込み管理ページ、反復ログイン、ホーム ブラウザに返されるトークンや URL に含まれるトークン、または Relay Web 管理者 ID を含まずに、アプリケーションから分離されたコンピュータ名、識別子、オンライン状態、およびサービスを提供します。ターゲットPCへのデバイスアクセス `manager` サービスは、同一アプリケーションのデフォルト アクセス契約に従います。接続または読み取りの失敗が、ゼロデバイスまたは初回の初期化として表示されてはなりません。管理者は次の場所に個別にサインインします。 `/manage` を別ウィンドウで表示します。この設計の展開と実際のブラウザーの相互作用は未検証のままです。
- メッセージアダプタには、ルートごとに1つのNapCatバインディング、リモートエージェント発見/接続、外部アダプタ診断、エージェントスキャン、プライマリエージェント選択、パイプライン、及び作業ディレクトリ構成が含まれる。
- ペルソナは、ペルソナのコンテンツ、ルート変数、ルール、ルートの種類、正規表現、スケジュール、およびテンプレートを管理します。提案されているドライラン プレビューは実装されていません。
- ログ診断は、接続状態、Codex配信チャネル、最近のログ、および手動トリガーを表示します。配信リプレイにはマネージャー API と台帳がありますが、現在のページにはリプレイ コントロールがありません。
- トップバーは、実行時に簡体字中国語、英語、日本語の間で切り替わります。日本語ブラウザは、設定が保存されていない場合は日本語で起動します。ロケール状態には 1 人の所有者があり、ブラウザーに保存されます `localStorage` 下 `rabiroute:webgui:locale`、付き `<html lang>` 同期が保たれています。これは UI 設定であり、ルート、ペルソナ、またはマネージャー構成には書き込まれません。
- 英語と日本語は、登録されたインターフェースのコピーと動的ステータステキストのみを翻訳する。ルート/ペルソナ ID、ルール名、テンプレート、正規表現、タスク名、パス、トークン、ログ、および実行時データは変更されません。ユーザーガイドは中国語で書かれていますが、 `_en.md` 英語と `_ja.md` 日本のマークダウンの下で `docs/user-guide/` そのページコンテンツソースとして。 README、ドキュメントのインデックス、はじめに、および現在の機能にも日本語版があります。未翻訳の開発者トピックは、リンクされた言語を保持します。
- マネージャは、エージェントスレッドブリッジ、ペルソナ知識、リモートエージェント、マルチラビ、NapCat管理、およびRabiLinkリモートWebGUI HTTP/SSEプロキシAPIも公開する。

## ペルソナの知識と実行時データ

- 計画、最近のメモリ、統合メモリ、統合実行、およびスキルインデックスはすべて、Manager API および信頼できるファイルソースを備えています。新しいメモリはマークダウンを使用しますが、レガシー JSON の互換性は維持されます。
