# 手机眼镜知识授权设置（实验）

[English](knowledge-grant-phone-ui_en.md) | 简体中文

设备 Agent profile 的 MCP 引用不是实际授权。知识授权面板分别设置角色 ID、固定支持的工具清单与默认关闭的写权限；不接受 PC 地址、Token 或连接凭据。角色 ID 必须与 PC 已有角色对应。最终权限仍是 Relay 设备授权、PC 本机设备 grant 与 MCP 服务权限的交集。

面板必须明确显示是否已选择 PC、PC 是否广告知识桥能力。保存仅表示 Relay 已保存授权，不证明本机授权或实际调用已生效。近期记忆详情会更新阅读时间，也受写权限限制；眼镜现有单步工具层仍只广告只读工具，启用写权限不自动提供写入交互。

## 保存与恢复

保存采用 `expectedRevision` 和稳定 `idempotencyKey`，先把冻结正文保存在当前账号／应用／设备隔离的 `sessionStorage`，存储失败不发送。200 回执必须完整校验授权内容、版本和键；网络错误或不完整回执不自动重发或换键。

刷新后先以已登录账号读取设备授权，再恢复待确认请求。通过 `GET /manage/api/apps/:appId/devices/:bindingId/knowledge-grant/operations/:key` 查询原操作；响应 `{code:0,data:{receipt:null|{idempotencyKey,revision,grant}}}`。历史回执完整匹配才能解除待确认，即使其他端已保存更高版本也可恢复。空回执或 404 不代表写入失败。关闭标签页或清除浏览器数据可能丢失会话恢复记录。

每设备授权回执最多 128 条；容量满时拒绝保存，不靠换键重试。此面板不更改 PC 本机安全配置，不启动 MCP，不执行知识业务。

## 验证状态

独立页面函数的纯 Node DOM 测试覆盖冻结请求、刷新恢复、完整回执、跨账号隔离、存储失败以及历史回读。管理页已在设备 Agent 设置旁接入“知识授权”按钮；真实隔离 Relay HTTP 测试覆盖历史回执、跨账号拒绝与未知键。界面与 HTTP 合计 6 项测试通过。模拟 DOM 不是手机布局或真机验收；未部署到公网或操作真实业务。

后续独占本机 Chrome 窄屏验收发现浏览器原生 `fetch` 被编辑器环境错误绑定，导致授权回读在发请求前抛出 `Illegal invocation`；已在注入处使用函数包装修复，并新增实际注入行的 receiver 回归测试。修复后 320、390、768 像素宽均完成 Agent profile 与知识授权保存及版本回读；长 Skill JSON 不产生页面横向溢出，保存按钮滚动可达，长工具名对应复选框可点击。此为桌面浏览器窄屏验证，不是手机触控或眼镜验收。先前冻结 Windows 发布包不含此修复，其手机知识授权功能存在已知问题，不能按该修复后的证据推荐部署。首次回读、保存中及待确认状态冻结角色和工具输入，避免迟到回读覆盖正在编辑的内容。工具及写权限使用独立整行 label，最小高度 44 像素，复选框 20 像素；不改变全局样式或授权策略。
