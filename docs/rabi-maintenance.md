# Rabi 长期维护与自修复

> 状态：Agent 维护工作流。计划、任务绑定和定时触发必须在当前安装环境分别配置并回读；本文不意味着所有 Bug 已修复，也不是独立于 Desktop 的守护程序。

## P0：可用接口、同步文档与安全热补丁

这是长期维护的最高优先级，优先于新增业务功能：允许功能频繁变化，同时维持已有接口可用。

- **接口文档属于交付物**：新增或修改接口必须同时提供与运行版本一致的路径、方法、鉴权、请求/响应 Schema、错误码、超时、幂等及回执查询合同，并附最小调用示例。文档入口不能依赖记忆整理、Agent 在线或其它后台任务完成；未部署的接口不得作为当前能力发布。
- **更新先验证，后激活**：源码变化先产生不可变候选和代码/文档版本标识，完成匹配测试与兼容性检查。禁止把编辑中的源码直接覆盖运行文件。兼容模块优先热替换，只影响目标模块，不重启无关接口、消息连接或任务。
- **在途请求有明确归属**：切换后新请求进入新模块，旧请求继续由旧模块完成；释放旧模块前排空其请求、订阅和资源。结果不确定的写入保持原键与原载荷，不自动重放。共享存储保留唯一写入 owner，禁止为零停机启动两个未隔离的业务写入者。
- **失败保留旧服务**：候选准备、文档校验或模块启动失败时不撤掉当前可用版本。激活失败可回滚；数据结构不兼容、无法排空或涉及核心生命周期时，明确拒绝热补丁并进入协调后的受控切换，不能把强制重启称为热更新。
- **用持续请求验收**：更新前、期间、之后持续验证独立查询和受控夹具写入，检查断连、超时、丢失与重复提交；同时核对文档/实现版本及旧资源释放。仅构建通过、单次健康检查或页面刷新，不足以证明热补丁可用。

当前边界：后台源码按[源码热补丁](source-hot-patches.md)的支持矩阵运行；安装版界面按[Web 热补丁](web-hot-patches.md)走生产构建、自动标记和回滚。兼容更新不重启 Manager；首次取得能力、后端或依赖变化仍须协调完整发布。

## 固定入口

维护计划负责 Rabi 自身的故障受理、恢复、回归验证和代码质量。通过当前 Manager 查询维护计划，读取唯一 `taskBinding.sessionId + workspace`；不得凭同名任务猜目标，也不为每次巡检创建新任务。计划长期保留在执行状态，每轮维护可以完成，长期计划仅在用户取消或明确替代时关闭。

报告故障时保留最小证据：发生时间、版本/generation、操作与预期/实际结果、相关接口和错误类别、可复现步骤、日志位置、原业务计划/任务，以及已尝试的恢复。不要附凭据或无关聊天。按模块、失败调用点、错误码/症状和目标生成稳定问题标识；同问题追加新证据，不重复创建计划或提醒。

正常投递走 [Rabi 接口](rabi-agent-interfaces.md)：先按 Host 状态发现当前 Manager 并核对 `/meta`，Agent 故障报告和定时任务通过线程桥投给绑定维护任务。`author=agent` 的计划 feedback 即使写 `notifyAgent=true` 也只记为 `record_only`，可保存证据但不能替代唤醒；只有用户来源 guidance 可通过 `notifyAgent=true` 通知。不要重复投递同一正文。结果不明确先查反馈/请求回执和任务状态；维护任务自己发现问题时直接处理，不向自己反复投递。

已有独立 Bug 计划及绑定任务时，维护任务把证据续投原任务并跟进，保留原归属；无归属的小问题由维护任务串行修复。需要独立验收的大问题建立单独计划，但只有确需新任务且授权允许时才新增任务。不得并行修改同一问题。

## 故障恢复

Rabi 健康时所有投递经 Rabi。只有当前动态发现与有界重试确认 Rabi 不可用，才按 [消息投递故障旁路](rabi-agent-interfaces.md) 使用事先核实的维护任务绑定，通过现有 Desktop owner 接收故障报告。旧端口失败不证明 Rabi 已挂。原投递结果不明时禁止换通道重复发送。

Rabi 无法写计划时，保留一份最小待恢复报告和实际旁路回执，继续能独立执行的本地排障；不直接编辑角色计划或回调存储。恢复后先读真实状态再补录，不为补回执重发正文。Host 管理安装版生命周期；不得杀 Manager、扫描旧端口或启动第二 Runtime。

## 每个问题的修复闭环

1. 确认问题归属、用户/其它任务的现有改动、故障范围与复现证据。
2. 先复现或取得能定位失败的证据，实施与原因匹配的最小修复，补必要的行为回归。
3. 按项目规范运行匹配测试；功能修改执行 `npm run build`，同步必要的中英文文档，清理本次触及的退役入口。
4. 修改 Manager、WebGUI、插件或启动链后，通过 Host 正式生命周期重载，动态核对新实例；根 HTML 引用本轮资源 hash 后再验证原故障场景。已有正在执行的发布/重载由原 owner 处理，不并发接管。
5. 写回实现、测试、构建、运行验证和剩余风险。源代码通过与运行问题修复分别记录；缺少真实验收时不得关闭 Bug。长期维护计划保留。

常规本地修复、匹配测试、构建和必要的本机 Host 重载属于维护范围。生产发布、对业务群发消息、凭据改写、破坏性清理和无关项目更改需要各自明确授权；维护不授权批量删日志或随意升级依赖。

## 定期维护

- 工作日 09:30：检查当前 Host/Manager 健康、近期新增故障、待处理报告和原任务进度；优先修复阻断问题。没有变化时不重复派发旧问题。
- 每周五 09:30：在当天巡检中增加质量维护，按本周改动检查数据归属、模块职责、错误处理、重复/废弃入口、文档和测试有效性；运行 `check:codex-contract`、`check:event-driven`、`check:plugin-architecture` 及匹配测试，按修改范围执行完整测试和构建。不要为了整理而做无关格式化、大规模重构或依赖升级。
- 时间使用维护环境时区；本机配置为 Asia/Hong_Kong。调度器在固定协调任务中触发，再经 Rabi 投给维护任务；Rabi 故障时才使用绑定恢复通路，不依赖 Rabi 为自身故障发出全部提醒。
- 仅新增且可行动的问题、修复完成、失败或需要用户决定时通知；状态不变保持安静。记录本轮已检查范围、实际结果与下一动作。
- Codex/Desktop 与主机需可运行才能执行调度。已发现问题由相关 Agent 当轮投递，不必等下次巡检；定时维护不是实时故障监控承诺。

## 验收

维护入口就绪需分别证明：真实计划及绑定 GET 回读、维护任务收到投递、调度已启用、工作流引用可达。日后每个 Bug 仍需自己的修复与原场景验证证据。不要用入口建成替代代码质量巡检或具体修复结果。
