# Rabi 长期维护与自修复

> 状态：Agent 维护工作流。计划、任务绑定和定时触发必须在当前安装环境分别配置并回读；本文不意味着所有 Bug 已修复，也不是独立于 Desktop 的守护程序。

插件清理超时后仍保留真实拥有者围栏。正常运行的切代不会额外等待整机退出宽限；应用退出则在 Manager 资源拥有者原有的剩余预算内继续等待实际清理。只有全部资源已确认关闭，才可把先前超时标记为 `lateConfirmed: true` 并报告退出成功；原超时诊断不删除，真实失败或未确认资源仍使退出失败。单次超时既不能证明进程已停止，也不应在实际迟到关闭已确认后继续冒充未知状态。

## P0：可用接口、同步文档与安全热补丁

这是长期维护的最高优先级，优先于新增业务功能：允许功能频繁变化，同时维持已有接口可用。

- **接口文档属于交付物**：新增或修改接口必须同时提供与运行版本一致的路径、方法、鉴权、请求/响应 Schema、错误码、超时、幂等及回执查询合同，并附最小调用示例。文档入口不能依赖记忆整理、Agent 在线或其它后台任务完成；未部署的接口不得作为当前能力发布。
- **更新先验证，后激活**：源码变化先产生不可变候选和代码/文档版本标识，完成匹配测试与兼容性检查。禁止把编辑中的源码直接覆盖运行文件。兼容模块优先热替换，只影响目标模块，不重启无关接口、消息连接或任务。
- **在途请求有明确归属**：切换后新请求进入新模块，旧请求继续由旧模块完成；释放旧模块前排空其请求、订阅和资源。结果不确定的写入保持原键与原载荷，不自动重放。共享存储保留唯一写入 owner，禁止为零停机启动两个未隔离的业务写入者。
- **失败保留旧服务**：候选准备、文档校验或模块启动失败时不撤掉当前可用版本。激活失败可回滚；数据结构不兼容、无法排空或涉及核心生命周期时，明确拒绝热补丁并进入协调后的受控切换，不能把强制重启称为热更新。
- **用持续请求验收**：更新前、期间、之后持续验证独立查询和受控夹具写入，检查断连、超时、丢失与重复提交；同时核对文档/实现版本及旧资源释放。仅构建通过、单次健康检查或页面刷新，不足以证明热补丁可用。

当前边界：后台源码按[源码热补丁](source-hot-patches.md)的支持矩阵运行；安装版界面按[Web 热补丁](web-hot-patches.md)走生产构建、自动标记和回滚。兼容更新不重启 Manager；首次取得补丁能力、Host／依赖 ABI 或无法迁移的状态变化仍须协调完整发布。

## 功能故障隔离

插件包加载逐项保留结果和诊断。可选包缺失或损坏不阻断可用的必需能力；更新失败时沿用该实例上一份已验证候选与配置。缺少真实必需能力仍如实报告，失败插件及真正依赖它的功能不可用。共享提供者的独立消费者不会因其中一项激活失败一起撤回；已有提供者换版涉及的消费者仍按一致性边界重建。

同一 `pluginId + version` 的多个实例共享 Web 资源时，代码 revision 升级必须一起准备和回滚，保证后端与页面使用同一份代码。某项升级失败时保留已确认版本；目标 revision 冲突时明确拒绝冲突项。仅配置变化且代码 hash 相同、或没有共享 Web 资源的实例继续独立处理。

发布回滚失败时，旧代码版本不能证明公开状态已恢复。立即撤销受影响原子组及其实际依赖者的接口和服务准入，保留未确认拥有者的隔离状态，并报告降级；无关功能继续可用。

Profile 和包元数据读取在独立子进程执行，默认最多 2 项运行、32 项等待；批量按唯一包有界生产，并复用同包在途读取，不因一次大 Profile 自行填满队列而误拒有效插件。单项默认 30 秒预算从入队开始，包含启动、读取和关闭。子进程只继承必要 OS 环境，不继承正式 API 凭据或 Desktop IPC，也不导入插件入口。收到元数据后仍须确认进程关闭；超时或停止先终止并等待原进程，再用最多 5 秒的受管清理进程处理该任务唯一暂存目录。未确认关闭不释放槽位，清理失败明确记录且不发布候选。

已发布元数据按实际 generation 的完整插件身份及 activationId 保存；下一轮回退和页面资源都使用该已确认快照。加载成功而激活失败的版本不能成为下一轮回退依据，也不能替换仍运行旧版本的页面资源。

插件准备、激活、每个副作用启动及发布后启动分别有默认 30 秒的异步等待预算，并非整次插件切代共用 30 秒。超时关闭所属作用域的新增入口，保留未结束工作及迟到资源清理的归属；未确认退役仅阻止同一拥有者重新启动，不占住无关插件的发布与故障处理。不能把等待超时当成工作已经停止。

公共 API 的请求截止会及时结束客户端等待，已经开始执行的写操作仍保留结果不确定状态。原操作及晚到流的清理持续持有真实租约；排空超时返回失败并保留未完成计数，不伪造成功，也不自动重放写入。业务可用性在对应插件及其依赖处判断，不用一项能力失效拒绝全部无关写请求；既有连接鉴权和事务校验继续生效。

源码发现过程中收到更新事件时，已过期的组会在编译前重新排队，避免反复编译过期文件拖延独立模块就绪；编译后的源版本与发布身份校验继续保留。

API 注册复用已核验的路径元数据和可独立复用的 schema 校验器，缓存同时限制数量和容量，并保留引用作用域及原有匹配语义。生命周期阶段之间会让出事件循环，让健康检查、取消及其它请求及时运行；取消后尚未入场的阶段不会执行，已入场工作仍保留真实归属。

批量 HTTP API 注册使用 `await registerOperationsAsync(..., context.lifecycle.signal)`：先固定合同与回调，逐项让出事件循环完成准备，全部成功且未取消后才一次挂载。准备失败不发布部分路由，创建在等待之前的资源必须立即登记幂等清理；停止失败及迟到资源继续持有未确认退役围栏。

Speech 退出由已验证的进程拥有者统一停止并确认，不再与麦克风、播放的额外 HTTP stop 并发竞争。停止不要求启动依赖仍然存在；只有明确离线才可报告已经停止。拥有者未知、无权停止、杀进程失败或服务仍在线时，继续报告未确认。

可信同进程业务回调沿原拥有者执行，不使用 `node:vm` 的短同步预算打断事务。异步截止只结束等待，不能抢占实际工作；在途资源和清理继续保留原归属。需要隔离原生阻塞、模块导入求值或不可协作的同步代码时，使用已有 Worker／子进程，并确认实际退出。验收同时覆盖正常冷启动、故障注入、无关接口响应及旧拥有者真实退役。

### 大型请求记录与接口目录

请求记录由独立持久化进程处理，主进程保留已提交的读模型；完整投递正文及大型记录列表按需异步读取。记录变更按单一拥有者串行执行，完整 JSON 完成原子写入、同步落盘和替换后，才发布缓存、事件与成功结果。失败草稿不能成为可见状态；提交回执丢失时保留不确定围栏，不自动重放。该进程只负责记录存取，不创建或执行 Agent 会话，旧运行包仍可读取同一完整 JSON 格式。

初始化尚未完成或记录不可用时，仅依赖这些记录的接口返回局部不可用状态，不能返回空目录假装记录不存在，也不能阻断无关健康检查和接口。后台自动化等待其依赖就绪，等待与退出均保留真实拥有者；应用退出要确认持久化进程实际关闭。禁止为排障删除历史记录或覆盖用户账本。

帮助、能力和 OpenAPI 目录按同一不可变快照分批投影与编码，每项继续执行原有合同校验。编码只绑定到对应的不可变响应对象，发送前仍完整校验响应 Schema；外部拥有者的可变数据只复制、不冻结。字段、分页、别名、鉴权和 ETag 合同保持一致，大目录不能通过提高超时或改成不透明响应来绕过校验。

## 固定入口

按 ID 查询计划或会话返回 404 时，继续按已知名称搜索计划或任务，或分页列出最近活动会话；使用候选前核对完整 ID、人格/实例、工作区与绑定。同名记录不能直接替代原对象，单次 404 也不能作为重建或改绑的依据。接口返回提示应提供当前版本实际支持的名称搜索或近期列表入口。若原对象确实存在却返回 404，仍须修复读取、索引或存储问题；检索提示不代替修复。管理超时、5xx 与未知投递回执保持原义，不自动重发消息。

维护计划负责 Rabi 自身的故障受理、恢复、回归验证和代码质量。通过当前 Manager 查询维护计划，读取唯一 `taskBinding.sessionId + workspace`；不得凭同名任务猜目标，也不为每次巡检创建新任务。计划长期保留在执行状态，每轮维护可以完成，长期计划仅在用户取消或明确替代时关闭。

报告故障时保留最小证据：发生时间、版本/generation、操作与预期/实际结果、相关接口和错误类别、可复现步骤、日志位置、原业务计划/任务，以及已尝试的恢复。不要附凭据或无关聊天。按模块、失败调用点、错误码/症状和目标生成稳定问题标识；同问题追加新证据，不重复创建计划或提醒。

正常投递走 [Rabi 接口](rabi-agent-interfaces.md)：先按 Host 状态发现当前 Manager 并核对 `/meta`，Agent 故障报告和定时任务通过线程桥投给绑定维护任务。`author=agent` 的计划 feedback 即使写 `notifyAgent=true` 也只记为 `record_only`，可保存证据但不能替代唤醒；只有用户来源 guidance 可通过 `notifyAgent=true` 通知。不要重复投递同一正文。结果不明确先查反馈/请求回执和任务状态；维护任务自己发现问题时直接处理，不向自己反复投递。

已有独立 Bug 计划及绑定任务时，维护任务把证据续投原任务并跟进，保留原归属；无归属的小问题由维护任务串行修复。需要独立验收的大问题建立单独计划，但只有确需新任务且授权允许时才新增任务。不得并行修改同一问题。

同步计划锁等待续期线程首次确认时，以既有租约有效期作为等待上限，不再在 10 秒时提前判定启动失败。首次确认前不执行事务；线程仍逐次核对锁文件、拥有者、回收隔离标记和过期时间。正常续期间隔与结束确认时限保持不变。

## 故障恢复

只读 Worker 返回全目录后，Manager 按条准备规范化与不可变快照，每条之间使用 `setImmediate` 让出；准备阶段保留旧快照，发布前再次校验读围栏和取消状态，再一次性替换计划、记忆与元数据缓存。不能在主线程同步重复规范化并复制整个目录，也不能把准备中的部分结果写入正式缓存。

可选的局域网服务发现同样在结构化 READY 后启动，不等待 mDNS 发布完成才让 Host 确认控制面已就绪。

单计划投影在只读子进程执行。反馈投影的强 ETag 保持完整包清单算法，附件采用 64 KiB 流式哈希，不再为版本读取复制整个包；哈希缓存每次核对设备、文件身份、大小、mtime 和 ctime，原子替换使缓存失效，计划和历史仍逐次校验。遍历和哈希分块让出事件循环。计划详情继续从同一完整包快照读取修订和反馈摘要，避免混合不同版本。全天记录的意图恢复在结构化 READY 后调度，失败保留诊断。文件监听扫描默认有 30 秒进程预算，连续失败指数退避至最多 30 秒，排队事件不绕过失败退避，避免高负载时反复重建扫描进程。

计划存储恢复在独立子进程中执行，其未完成或重试不降低 Manager 的健康状态；`businessReady` 仍单独报告计划存储是否就绪，受影响的计划写入继续返回可重试的 503，避免与恢复并发写入。`backgroundLifecycle.planStorageStartup` 提供恢复状态和失败摘要；不要通过删除记录或跳过冲突校验恢复就绪。

普通消息投递的持久回执由独立 Worker 续租。Manager 异步等待心跳 Worker 启动和停止，单次握手截止仍为 10 秒；等待不会阻塞 HTTP 健康检查。投递前后继续核对原连接权限与回执拥有者，结果不确定时核对原投递，不自动重发。

Rabi 健康时所有投递经 Rabi。只有当前动态发现与有界重试确认 Rabi 不可用，才按 [消息投递故障旁路](rabi-agent-interfaces.md) 使用事先核实的维护任务绑定，通过现有 Desktop owner 接收故障报告。旧端口失败不证明 Rabi 已挂。原投递结果不明时禁止换通道重复发送。

Rabi 无法写计划时，保留一份最小待恢复报告和实际旁路回执，继续能独立执行的本地排障；不直接编辑角色计划或回调存储。恢复后先读真实状态再补录，不为补回执重发正文。Host 管理安装版生命周期；不得杀 Manager、扫描旧端口或启动第二 Runtime。

## 每个问题的修复闭环

1. 确认问题归属、用户/其它任务的现有改动、故障范围与复现证据。
2. 先复现或取得能定位失败的证据，实施与原因匹配的最小修复，补必要的行为回归。
3. 按项目规范运行匹配测试；功能修改执行 `npm run build`，同步必要的中英文文档，清理本次触及的退役入口。
4. 修改 Manager、WebGUI、插件或启动链后，通过 Host 正式生命周期重载，动态核对新实例；根 HTML 引用本轮资源 hash 后再验证原故障场景。已有正在执行的发布/重载由原 owner 处理，不并发接管。
5. 写回实现、测试、构建、运行验证和剩余风险。源代码通过与运行问题修复分别记录；缺少真实验收时不得关闭 Bug。长期维护计划保留。

常规本地修复、匹配测试、构建和必要的本机 Host 重载属于维护范围。生产发布、对业务群发消息、凭据改写、破坏性清理和无关项目更改需要各自明确授权；维护不授权批量删日志或随意升级依赖。

## 定期维护

- 工作日 09:30：检查当前 Host/Manager 健康、近期新增故障、待处理报告和原任务进度；优先修复阻断问题。没有变化时不重复派发旧问题。
- 每周五 09:30：在当天巡检中增加质量维护，按本周改动检查数据归属、模块职责、错误处理、重复/废弃入口、文档和测试有效性；运行 `check:codex-contract`、`check:event-driven`、`check:plugin-architecture` 及匹配测试，按修改范围执行完整测试和构建。不要为了整理而做无关格式化、大规模重构或依赖升级。
- 时间使用维护环境时区；本机配置为 Asia/Hong_Kong。调度器在固定协调任务中触发，再经 Rabi 投给维护任务；Rabi 故障时才使用绑定恢复通路，不依赖 Rabi 为自身故障发出全部提醒。
- 仅新增且可行动的问题、修复完成、失败或需要用户决定时通知；状态不变保持安静。记录本轮已检查范围、实际结果与下一动作。
- Codex/Desktop 与主机需可运行才能执行调度。已发现问题由相关 Agent 当轮投递，不必等下次巡检；定时维护不是实时故障监控承诺。

## 验收

维护入口就绪需分别证明：真实计划及绑定 GET 回读、维护任务收到投递、调度已启用、工作流引用可达。日后每个 Bug 仍需自己的修复与原场景验证证据。不要用入口建成替代代码质量巡检或具体修复结果。

## 配置目录启动恢复

路由目录子进程终止超时会阻止保存。后续保存或回执查询会向原进程 owner 再次确认退出；确认前不启动替代写入，确认后释放阻塞并处理本次请求。聚合任务报错不作为子进程退出证据，不自动重放之前失败或结果不明的保存。

单条路由保存仅校验本次写入的消息规则，不因其他路由尚未迁移而拒绝保存。当前角色的旧投递规则仍须通过 `scripts/migrate-agent-delivery-targets.ts` 预览和迁移；工具保留快照并复核原文件，按既有投递开关生成明确目标。

Windows 进程身份查询只读取 PID、父 PID、启动时间和程序路径，最多等待 60 秒；查询失败仍保留失败状态，不跳过进程归属检查。
