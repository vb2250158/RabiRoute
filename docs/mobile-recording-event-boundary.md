# 移动端记录与事件边界

[English](mobile-recording-event-boundary_en.md) | 简体中文

手表、手环和智能眼镜统一在 RabiLink 移动端设置。PC 的 Route 消息端列表、添加菜单和快速配置不再提供这些设备的独立入口，也不增加替代的“移动端消息端”开关。

## 分工

- 移动端记录系统拥有设备连接、权限、采集选择、开始与暂停、记录及上传许可。沿用 `RabiConversationService` 和现有记录控制器。
- 记录系统按用户许可，把需要处理的记录事件投递给选定 PC／人格。RabiLink 负责传输，不按手表、手环、眼镜再建立一套 Route 配置。
- RabiRoute 校验来源、目标和许可，记录接收结果，按事件规则交给 Agent。健康历史查询、转写和告警处理继续由各自现有模块承担。

设备种类是记录来源信息，不是需要用户在 PC 添加的消息端。暂停采集和关闭上传的含义沿用[全天记录合同](rabilink-all-day-recording.md)。

## 实施状态与旧协议退出

本次移除 PC 设备配置入口，并确定上述架构。统一记录事件投递尚需后续实现和端到端验收；不能把原有设备链路的成功记录作为新链路验收。

现有客户端、已保存 Route、健康时间线和旧消息仍使用 `rabilink`、`wearable`、`wearable_health_alert` 等内部键。保留其读取与传输兼容，避免删除历史或中断已授权客户端；不自动开启输入、不改写现有 Route 许可。旧独立健康 Route 创建脚本退役。

唯一迁移方向是移动端记录事件。退出里程碑：所有受支持客户端切换到统一记录事件，存量 Route 和未完成传输完成有回执的迁移，断网重试、去重、目标隔离、暂停与上传许可通过验收。满足后删除旧 adapter 注册、独立监听与配置键；不再扩展旧路径。迁移前旧配置仅用于兼容维护，不是新设备接入教程。
