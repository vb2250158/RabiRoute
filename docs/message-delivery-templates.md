# 消息投递结构与模板

RabiRoute 负责来源核验、上下文组装、路由和回执。处理端负责实际执行。模板表达本次任务和接口参数，不重复提供一套通用 Agent 工作规范。

普通消息默认使用简短现场卡：来源与正文各一次，附当前事件、角色、必要设备标识和最多三条简短近况；没有情况就不填空状态。计划、记忆、技能、日志路径、接口全文和通用行为限制不自动展开，可通过 `GET /api/agent/help` 按需查询。回传仅保留目标定位，不重复整个请求模板。已有显式依赖完整投递的接入方可通过 `BuildAgentPacketOptions.contextDetail = "full"` 请求完整投影；正常运行不自动切回完整投递。自定义任务正文保留，标准 `[RabiRoute 数据解构]` 包装不重复注入。

## 唯一入口与数据归属

| 内容 | 拥有者 | 边界 |
| --- | --- | --- |
| 来源、正文、上下文与控制块的最终展示 | `src/shared/rabiMessage.ts` | `renderRabiDelivery` 包装来源；`renderRabiDeliveryContent` 同时服务直接和中转投递。 |
| 各路由所需数据 | `src/routing/agentPacket.ts` | 生成结构化 `delivery`；`message` 和 `content` 是派生展示，不另存业务事实。 |
| Agent 回复参数 | `src/agentRequests/replyParameters.ts` | 从已核验的双方身份和请求记录生成一份完整请求体。 |
| 请求、结果与投递证据 | `src/agentRequests/store.ts` | 发送前保存结构化回复和实际正文 SHA-256；回执失败不得丢失待恢复证据。 |
| 结果不确定时的恢复 | `src/agentRequests/deliveryRecovery.ts` | 比对目标实际收到的 user 消息与正文校验值，从请求记录恢复结果；不解析新模板标题。 |
| 处理端传输 | Agent adapter / Desktop IPC | 不重新发明来源或添加通用协作模板，不通过正文获得工具权限。 |

## 展示顺序

1. `[消息源]`：保留来源类型、实际处理端、Agent/事件类型、名称、完整 ID、适用工作目录和投递时间。
2. `[消息内容]`：本次请求或结果。正式回复的结果、下一步各一次；仅删除完全相同的重复字段，不概括或截断证据。
3. `[相关上下文]`：有内容才出现，包含引用、附件、记录时间、相关计划与读取入口。
4. `[回传参数]`：投递标识、回复要求和适用的完整 API 参数。场景特有的写回步骤可跟随；无发送目标时不得猜测目标。

不生成 `[协作要求]`、`[主动协作要求]` 或 `[本轮工作契约]`。本次特有的授权范围、禁止重启、只读调查等仍由任务正文提供。初始化职责与已绑定角色的工作规范保留在原入口，不随每条普通投递重复。

## 场景清单

| 场景 | 保留与省略 |
| --- | --- |
| Agent 新任务、续投、回传 | 保留完整双方身份与请求参数；结果不再在合同中重印。 |
| 聊天、引用、附件 | 保留作者、时间、消息 ID 和原始证据；延续同 ID 完整消息去重。 |
| 计划引导、审批 | 保留计划、步骤、审批身份和实际写回要求；秘书职责通过唯一技能入口读取。 |
| 心跳、手动触发、整理 | 保留触发类型和范围；无新变化不外发，受阻记录原因和下一步。 |
| 消息处理任务 | 初始化保留职责；每轮保留需求归属、实际交接参数与结束条件。 |
| 角色 Hook | 首次基础上下文、后续增量；Manager 地址不在同一次基础上下文重复列出。 |
| 语音、眼镜、主动审阅 | 保留设备、会话、采样范围和下行参数；工具存在不能作为采集授权，人物不硬编码。 |
| 合并重放 | 外层时间是本次重放时间；内层保留原发送时间，缺失时标注旧记录未保存，并保留原投递记录时间。 |
| 用户结果通知 | 使用“本轮结果”，只显示任务名和结果正文，不另列计划名；不把执行结束写成业务验收；保留无损分段与逐段回执。 |
| 自定义 Route 模板 | 保留自定义语义；空补充或与当前正文完全相同的补充不重复显示。 |

## 历史兼容与退出条件

新投递只使用上述生成入口。升级前可能已经收到旧 `[Agent 回复合同]` 或 v2 正文的任务，其请求仍在等待回执；只读旧解析仅服务这些没有 `pendingResponseEvidence` 的既有预留，不能用于新消息生成。新消息存在证据时，校验失败不会降级为旧文案解析。

唯一迁移路径是查询原请求、核对实际接收证据并执行 `reconcile_delivery`，或按原请求的正常取消流程结束。不得为迁移重复发送正文或直接改运行存储。所有旧格式在途预留关闭、兼容回归仍通过后，才能删除旧解析。已完成/取消请求及明确失败的预留清除临时回复证据。

Desktop 传输与回执读取共用 `src/shared/deliveryIdentity.ts`：识别 JSON 回传参数、来源栏投递 ID 和必要旧格式，已有 ID 时保持正文原字节；显式传输 ID 与正文冲突时拒绝投递。回执扫描只读取实际 user 消息，不以工具输出或 Assistant 引用命中 ID 作为送达证据。

曾有旧传输层不识别新 JSON，向已经留证的正文追加第二个 `[投递编号]`。这类历史证据只允许剥离唯一、格式精确且位于末尾的传输段；原信封 ID 必须等于预留 deliveryId，剩余正文 hash 必须精确匹配。引用、正文篡改、重复尾段和额外尾文不能恢复。没有实际 user 消息证据时继续保持不确定，不认定未送达或重发；所有受影响预留闭合后可退役该兼容分支。

验证覆盖直接与中转渲染、来源字段、完整参数、历史回执、新证据跨重启恢复、正文篡改拒绝、写入失败重试、聊天/计划/语音场景及用户通知。源码测试和构建不等于当前 Host 已部署；运行验证需另行核对 generation 和实际产物。

Agent 来源区将类型与处理端合为一行（`类型：Agent｜处理端：codex`），使用“会话”和“投递时间”短标签；默认 Agent 角色省略，具体角色单列。完整会话 ID、工作目录与时间保留。重放读取同时识别新旧时间标签，历史回执正文保持原样。

正式回传只填写 result 和 nextAction，无需重复 prompt。新正文不生成 `[/回复]` 或 `[补充说明]`；旧调用者独立 prompt 内容无损放入 `[相关上下文]`，仅删除精确重复字段。旧结束标记仅用于历史回执解析；新投递按完整正文证据恢复。
