# 手机录音：电脑归档与 NAS 长期保存

> **状态：开发中，未部署。** 本页描述已实现的模块合同和正在接入的流程，不是可立即开启的运维功能。尚未启用自动清理，尚未完成局域网、P2P、Relay 三路实机验收，目标 NAS 隔离机制测试已通过，但目录 fsync 返回 `EPERM`，不能证明断电持久性或据此开启清理。旧版本的设备验收不能代替本功能验收。手机界面现状见[移动端记录与回看](rabilink-mobile-recording-ui.md)。

## 目标与三条独立状态轴

手机负责采集、可靠上传和回看；目标电脑负责长期归档、目录查询与异步转写。原音频只在受控 NAS 命名空间保存一份，手机保留未归档原件、轻量索引及可回收播放缓存。NAS 原件无 TTL 或容量自动删除。

- **归档**：`pending → uploading → committed`，失败独立显示重试等待或阻断。归档确认不表示转写成功。
- **转写**：排队、运行、完成、失败、模型阻断和 `ambiguous` 分开处理；空文字也可以是成功结果，不使录音失效。
- **手机原件清理**：`present → eviction_pending → evicted`。必须先核验并持久保存强归档回执，再通过写入者串行事务及读取占用保护清理；不能把传输 ACK、ASR 成功或旧 `durable:true` 当作删除许可。

最终设计中归档成功不等待 ASR 才释放手机空间，但当前远程历史、播放和恢复链路仍在集成验证，**源码已将清理闸门改为逐记录核验远程历史与原音频回读，手机安装版尚未开启**。ASR 不可用时原件应继续安全归档，而不是卡在手机处理队首。

## 身份、存储与不可变合同

认证 owner 来自手机安装实例的稳定设备身份，经隧道握手与公钥校验确认，不使用 Token 派生 scope。更换凭据需要重新授权，不等于修改录音归属；卸载重装产生的新身份不能自动继承旧身份。目标 worker 使用稳定电脑设备 ID，不使用临时 Manager 代际 ID。

电脑的归档设置接口复用连接鉴权来建立 `owner → role → archiveRoot` 绑定。角色目录通过现有配置解析，领域相对目录为 `all-day-recording/media-archive`；部署路径和角色值不写入协议默认值。上传正文不能自选 owner、role 或任意路径。命名空间使用持久 UUID；NAS 缺失、绑定禁用或 marker 不匹配时失败关闭，不回退成本机缓存归档。

协议保存 `pcm_s16le`、16 kHz、单声道原始 PCM。播放需要的 WAV 头临时生成，不把 WAV 与 PCM 作为两套长期媒体副本。上限分别为：

| 对象 | 上限 |
| --- | --- |
| 单媒体对象 | 1 MiB |
| HTTP manifest 正文 | 1 MiB |
| 单清单音频总量 | 128 MiB |
| 清单分片／对象数组 | 各最多 4096 项 |

清单冻结记录、来源、时间依据、处理策略、原分片顺序与哈希、对象偏移、缺口及字节总量。规范 JSON 递归排序键、保留数组顺序，使用 UTF-8 SHA-256。PC TypeScript 与 Android Java 的共享测试向量固定哈希为：

```text
c272627f1bec72e289cdd190fdf3534229e8b8a1062d11c28631b7339abc7a7b
```

强回执精确绑定 worker、namespace、recordId、manifestHash、totalBytes 和 segmentCount，并要求 `durability=archived`、`retention=indefinite`。服务端还要求清单设备身份与认证 owner 相同。相同记录与哈希重放幂等，冲突不能覆盖已有记录。

存储核心把 manifest 与 receipt 放入同一不可变 envelope，避免两文件提交裂缝；校验对象与原分片哈希后，使用临时文件 flush 和同文件系统 hard-link **no-overwrite** 发布。不支持硬链接的 NAS/SMB 环境失败关闭。目标 NAS 的隔离测试已验证文件 fsync、硬链接 no-overwrite、并发发布及重新打开读取；但目录 fsync 返回 `EPERM`。这些是文件操作机制证据，不是硬件断电持久性证明，不能据此开启手机原件清理。

## 网络顺序与不确定请求

上传、目录查询及播放统一复用现有 `resources` 隧道，顺序为 **局域网直连 → P2P → 服务器 Relay 中转**，保持认证和加密，不另建默认走服务器的上传通道。

首次授权可能借助服务器信令取得授权或公钥；这不等于后续媒体必须经 Relay。连接顺序已有源码依据，但三个路径及其失败回退尚未分别实机验收。写请求超时不能盲目切线路重复提交：先在同一 owner、worker、namespace、recordId 和 manifestHash 下查强回执；切网络不切历史归属。

## 电脑模型与异步作业

源码已将普通批量转写在未显式指定 model/provider 时的默认选择统一到电脑当前麦克风 ASR 配置；显式 API 参数仍保留通用覆盖能力。手机不选择、不发送模型名。电脑解析器核验模型可用性并冻结有效选择；配置指纹是派生哈希，不冒充官方 revision。模型不可用时阻断作业，不偷偷回退其他模型。

新增源码接口 `POST /v1/archive/transcriptions` 为 **loopback-only 纯计算接口**：要求 `job_key`，返回转写结果，不写语音库、不绑定说话人、不投递 Agent，临时上传文件在成功或异常后清理。`job_key` 只用于关联，**不提供计算幂等**。归档作业必须使用固定本机客户端，不随界面选中的远端电脑改变执行目标。

作业通过 NAS 持久意图冻结模型，以稳定 jobKey、单并发及租约围栏控制结果提交。发出请求后结果未知进入 `ambiguous`，不能自动重转；明确重算应产生新处理版本。空文本保留为合法结果。仅 `transcribe` 自动处理，历史 `agent` 策略不自动重放。

手机设置入口只选择电脑列表，不提供模型选择。只有新授权的 capture 进入新归档流程；旧历史尚未完成迁移。待上传预览最多展示 32 项，不代表全量待上传清单或完整迁移覆盖。源码清理要求强回执持久化、远程历史中同一清单可见、全部原音频对象回读校验通过，且无读取占用；任一失败保留手机原件。不能通过设置或转写完成推断已清理。

证据分开保留：早期 **41 项模块集成测试通过**，不覆盖随后新增的 Runtime 等集成；后续 Manager 完整 TypeScript 检查与 build 已通过。三项 P1 修复后的独立审查通过，最新 Android 全套 Gradle 验证已包含设置面板。PC 0.3.15 完整发行构建与 smoke 检查已通过，但未部署。发行包已冻结，本次文档更新仅进入后续包，不宣称当前安装包包含这些文字。2026-10-07 ADB 已连接手机并确认旧版因 8 GiB 应用配额停止采集，手机仍有约 45 GiB 可用空间；本次源码移除应用配额并缓存历史，候选更新仍待原签名覆盖安装。设备归档及 LAN／P2P／Relay 三路仍未验收。不要把不同快照、不同轮次的测试数量相加，或把历史录音夹具条数当作测试项目数。

历史 metadata 预检已开展，但缺少迁移所需的强完整性证据，尚未迁移；元数据可读不等于音频已核验或已归档。旧历史不会仅凭既有转写回执删除。

## 迁移与运维安全顺序

以下是后续验收顺序，**不是现在可复制执行的开启命令**：

1. 保存现有配置和原录音，生成只读迁移清单，核对稳定 owner、目标 worker、角色绑定和 namespace。
2. 在隔离测试位置验证 NAS no-overwrite、重启恢复、断连与哈希损坏；失败即保留本地原件，不换存储冒充成功。
3. 先用合成音频接通上传、回执查询、目录和按块播放，再分别验证 LAN、P2P、Relay 和断线回退。
4. 验证丢 ACK、提交后崩溃、回执持久化失败、读取占用期间清理、删除事务恢复、旧回执拒绝、模型缺失和 ASR 不确定状态。
5. 完成更新包、部署、实际设备回读及可识别新状态的回滚包后，才考虑逐批开启强回执约束下的手机清理。

旧全局 mobile events 和弱资源回执仅作为兼容读取或迁移输入，不能成为新 NAS 归档成功或删除授权，也不能继续作为第二份新业务真源。`local_only`、隔离、不完整、无可证归属的历史默认排除，缺归属不得猜当前选中电脑。迁移须保留原录音与旧转写，逐批核对字节、哈希和回执；空转写不是删除依据。
