# 人格全天记录

事件列表以 `(startedAt,id)` 游标双向读取 `GET /page?direction=older|newer&time=毫秒&id=事件ID&source=来源&type=all|asr|image|window|status`。每页最多 100 条，`hasMore` 表示该方向还有记录；跨空日期继续查找，直到真实边界。PC 内存保留最多 2000 条，移出的方向可重新分页读取；原始记录不删除。日期索引仍按日读取，首次索引恢复和稀疏筛选不保证恒定耗时。

录音使用稳定事件 ID；音频保存后在后台转写，有文字时显示为同一稳定 ID 的 ASR 事件。手机同步字段 `transcriptionState` 与电脑统一为 `pending/processing/ready/empty/error`，与音频是否保存分开。手机仅本地保存策略保持本地，不自动上传。浏览历史时新记录不会强制跳回实时。

在人格配置的「全天记录」页通过连续时间尺和事件列表回看，沿用移动端的固定中央指针、左右拖动、惯性滑动与跨日浏览。默认显示 30 分钟，缩放范围为 3 秒至 24 小时（时间轴左右边缘的总跨度）；日期用于跳转，回到实时后指针跟随当前时间。电脑麦克风沿用 RabiSpeech 的分段录音与 ASR；屏幕、摄像头按设定间隔保存 JPEG 画面，前台窗口在采样发现标题变化时生成事件。它不是连续屏幕录像，也不从窗口标题推断用户正在操作。空白区间保持空白，采集失败单独显示，不伪造全天覆盖。

四个电脑来源默认全部关闭；总开关首次开启需要至少选择一个来源。开启意图按本机持久化，下次软件启动恢复对应人格记录；关闭总开关清除恢复意图，正常退出软件保留它。同一电脑只有一个采集人格，其他人格显示占用状态。运行中可修改设备开关并保存，等待当前有界采样结束后生效。麦克风断流后按采样间隔尝试重开，屏幕和摄像头独立采样；一个来源失败不丢弃其他来源的结果。摄像头仍按配置编号选择，编号被系统重排时需要重新确认，不能保证物理设备身份不变。

麦克风复用唯一 RabiSpeech owner：已有电脑监听时共享其会话，只纳入本次开始后的电脑录音，关闭或租约到期不停止原有监听；原先未监听时才启动临时会话，关闭或失去 Manager 续租后停止并还原配置。远端输入不作为电脑麦克风，来源或会话改变时明确报错。原语音服务配置的 ASR、声音阈值与消息路由规则继续适用，未达到转写条件的声音不等于已保存事件。

手机转写成功后，将本次事件的来源时间、文字与可回放 WAV 通过已认证的 resources 通道同步到实际处理该事件的电脑。队列与 ASR ACK 分开，网络或旧电脑不支持事件接口时保留待同步状态，不阻塞转写。来源和账号在入队时冻结。只汇总用户在当前人格设置中选择的手机；设备身份由认证通道提供，正文不能冒认其他手机。目前这一同步覆盖更新后生成的转写事件，不会凭旧回执猜测账号并补传全部历史，也不包含手机尚未上传的视频和健康数据。

屏幕采集与 F1 复用桌面模块 `rabiroute_tray.desktop_capture.capture_desktop_pixels()`，统一抓取所有显示器的原生像素。全天记录只缩放和保存 JPEG，不加载 Qt、不打开框选或修改剪贴板；F1 继续负责选区、多屏坐标映射与交互。

预览区域在页面向下滚动时固定在顶部导航下方，时间尺随页面正常滚动，事件列表独立滚动。拖动时间尺会定位列表；滚动列表会同步中央时间和回看事件。点击时间尺事件或列表事件均可选中回看，事件按钮不接管拖拽。列表使用预取事件窗口，刷新时保留当前可见记录的位置，程序定位不会反向触发滚动联动。

屏幕预览完整等比显示虚拟桌面，保留 Windows 中各显示器的相对位置、比例和间隙；宽屏预览框不会裁掉图片下方的显示器。

## 数据与生命周期

- 电脑设置和事件在角色目录的 `all-day-recording/<host-hash>/`；不同电脑分开。设置不保存“正在采集”的意图。
- 事件以采集起始时间 `startedAt` 分 UTC 日期目录，每事件一个稳定身份哈希文件。页面按可见范围预取并替换窗口数据，跨午夜连续读取对应 UTC 分卷，每次接口请求不超过 26 小时。分卷只是物理组织，不是记忆沉淀或删除。
- JPEG/WAV 完成写入后提交事件。电脑录音复制进该记录存储，避免依赖语音服务的临时音频缓存。手机媒体由现有 ResourceCache 保管，校验每块 SHA-256 和持久化回执后才提交事件。
- 手机事件索引由接收电脑保存于 `data/mobile-recording-events/`，通过认证来源和稳定事件 ID 幂等覆盖；文件写入串行化、临时文件 fsync 后原子替换。未自动同步到其他电脑或人格。
- 不自动删除原始记录；仅删除本次原子写的临时文件。磁盘不足、语音服务离线、权限或摄像头故障必须显示未知/失败。
- 当前时间轴供用户和本机 Agent 按需查询，不自动投递 Agent，也不把全部原始记录注入提示词。

## 本机接口

Manager 地址必须从 Host 当前代发现并核对 `/meta`。以下接口仅允许本机且拒绝设备隧道，不接收任意路径或命令；沿用 Manager 鉴权和只读模式。

基路径：`/api/roles/:roleId/all-day-recording`。JSON 成功为 `{code:0,data:...}`，错误为 `{code:-1,message:...}`。

| 方法与路径 | 合同 |
| --- | --- |
| `GET /` | 设置、实际运行状态、采样时间、错误与可选择的手机来源 |
| `PUT /settings` | `sources:{microphone,screen,window,camera}` 全部为布尔；`intervalSeconds` 10–3600；`cameraIndex` 0–16；`mobileDeviceIds` 为发现列表里的来源哈希。运行中也可保存 |
| `POST /start` | 按已保存设置开始；同人格重复开始返回当前状态，另一人格占用则失败 |
| `POST /stop` | 等待本次有界采样完成并停止本会话；重复停止不产生第二次动作 |
| `GET /events?since=...&until=...` | 毫秒时间范围，不超过 26 小时；返回按真实来源时间排序的事件 |
| `GET /media/:day/:hash.jpg` 或 `.wav` | 只读当前人格、当前电脑的受控媒体 |
| `GET /audio?since=...&until=...&id=...` | 先验证事件属于该人格可见时间线，再读对应手机资源或语音音频 |

写设置、开始、停止以单个 Manager 串行队列执行；开始/停止天然按当前会话幂等，结果不确定先 GET 核对，不跨代自动重放。快照进程上限 15 秒，语音 API 上限 30 秒。界面由 `all_day_recording` SSE 更新，不轮询业务状态。

手机新增 `PUT /api/resource-cache/data/recording-events`，仅受信 resources 隧道调用。正文为 `{id,startedAt,endedAt,text,chunks}`；时间为毫秒，文字最大 100000 字符，最多 16 个 1 MiB 内容哈希块。每块必须已属于同一认证来源并通过校验；成功回 `{durable:true}`。相同来源/事件 ID 重试幂等；400 为数据/资源错误，403 为授权/只读限制，404 为旧电脑未支持。手机稍后使用同一冻结队列项重试。

列表只渲染可视区域附近最多 24 行；宽时间范围内同来源的密集事件按 0.5% 刻度分组合并，点击可放大并选中事件。后台刷新合并为一个待处理请求，不取消正在完成的读取；隐藏页面暂停自动刷新，返回后补一次。刷新保留已有内容与浏览位置。十万条前端合成数据测试不代表同规模 NAS 查询吞吐。

首屏并行读取最近事件快照与时间轴附近一小时的历史。`GET /recent` 不等待日期索引重建，电脑和已选择手机各最多返回 128 条。`recent-preview.json` 是按稳定 ID 去重、按 `startedAt` 排序的可重建快照；原始事件提交后及日期索引读取成功时原子更新，重启后继续可用。旧安装第一次尚无快照时，由下一次采样或历史查询补齐。原始记录不移动或删除。

浏览器按人格保留最近 24 小时内最多 200 条预览（序列化上限 100 万字符），新开标签页也先显示缓存并标明正在更新。缓存不代表采集状态；完整历史、运行状态和图片独立异步读取，历史请求未结束时新增事件仍可刷新。此处 24 小时仅是展示缓存有效期，不是原始记录保留期。

`events-index/YYYY-MM-DD.json` 是当前 Host 写入拥有者维护的可重建日期索引。写原始事件前持久化同日 `.dirty.json` 标记，原始事件和索引均提交成功后才移除标记；中断、缺失或损坏索引时按最多 16 个原始文件一批重建。正常写入和重建按日期串行，稳定事件 ID 防止重试重复；首次重建可能暂时延后同日的新采样落盘。有效索引不再依赖 NAS 目录时间戳，也不枚举原始目录。直接在拥有者之外修改原始文件不属于此写入协议，运维恢复时必须同时使对应索引失效。

同一日期的并发查询共享读取任务，成功结果缓存五秒，最多八个日期、每个最多两万条事件。拥有者写入成功立即使对应内存缓存失效，失败不缓存。索引和缓存均可重建，原始文件不移动或删除，不使用归档的 24/72 小时窗口。首次索引重建仍随当天文件数增长；日期索引不等于完成服务端游标分页。

## 宽屏回看布局

进入页面自动选择最近的屏幕画面，没有画面则选择最近的非状态事件。状态与事件独立读取；恢复标签页缓存后立即展示事件，缓存写入延后执行。时间范围查询使用区间索引，保留跨越可视范围的长音频，拖动不再扫描全部缓冲事件。快速导航后延迟 150 毫秒读取图片，旧请求取消且不能覆盖新选择；新图异步解码完成后才替换已有画面。页面内图片缓存最多四张、合计 16 MiB，退出页面释放。音频点击播放才加载；转写先展示 600 字符，按需展开全文（事件响应仍包含全文）。

宽度达到 1000px 时，左侧约 60% 固定显示预览和时间轴，右侧约 40% 为独立滚动的事件列表，两列整体等高。事件数量、来源筛选和刷新放在顶部标题与记录开关之间，空间不足时自动换行；窄屏为上下布局。列表按最新在上排序。时间轴定位列表，列表滚动定位时间，刷新保留正在浏览的事件。


回看只显示成功转录且有非空文字的 **ASR 事件**；纯录音仍保存，但不显示在事件列表和历史时间轴。事件沿用原始采集时间及稳定 ID，不使用转录完成时间。筛选、分页和上一个/下一个事件均在计页前排除隐藏录音。移动端回到实时仍显示麦克风波形。移动端日期、实时、刷新工具栏增加上一个/下一个事件，事件类型（ASR/录像）与设备来源独立筛选。

前后事件导航在完整加载且未裁剪的时间范围内直接定位；范围外才异步分页，显示加载状态并限制等待时间。相同采集时刻的不同事件按稳定 ID 逐条切换，不跳过。
