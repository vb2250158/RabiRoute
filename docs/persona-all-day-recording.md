# 人格全天记录

首次启用电脑采集时，Manager 使用安装包自带的 Python 自动准备 RabiSpeech 依赖，无需另装 Python 或手动运行脚本。已有环境在离线启动时按当前 `requirements.txt` 校验，只补缺失或不兼容的依赖；升级增加依赖时再次校验。模型权重仍由模型管理单独下载。安装结果只有通过版本及核心模块导入校验才写入就绪凭据，依赖留在本机稳定目录，安装过程不修改版本包。

环境准备复用模型管理的唯一安装任务，并发开启会等待同一次安装。失败后保留具体错误，本代 Manager 不按采样间隔重复下载；在模型管理中重试安装后自动继续采集。记录开关表示启用意图，状态另外区分准备、首次采集、失败、部分来源不可用和长时间未更新；`lastSampleAt` 只推进到成功采样。预览标注已显示事件的实际时间，实时模式下旧画面显示为“最近画面”，不套用当前时钟。

事件列表以 `(startedAt,id)` 游标双向读取 `GET /page?direction=older|newer&time=毫秒&id=事件ID&source=来源&type=all|asr|image|window|status|device`。每页最多 100 条；`loading=true` 时 `hasMore=true` 表示尚未确认边界，页面等待完成通知后继续定位，不跳过尚未读取的日期。首屏渐进读取日期索引，列表保留已加载的全部事件，使用虚拟滚动直接选择；原始记录不删除。

录音使用稳定事件 ID；音频保存后在后台转写，有文字时显示为同一稳定 ID 的 ASR 事件。手机同步字段 `transcriptionState` 与电脑统一为 `pending/processing/ready/empty/error`，与音频是否保存分开。手机仅本地保存策略保持本地，不自动上传。浏览历史时新记录不会强制跳回实时。

状态：新增实现，构建、安装与设备验收须分别确认。

记录 JSON、预览快照和媒体通过临时文件写入、同步后原子替换。Windows/NAS 文件占用导致 `EPERM/EACCES/EBUSY/ENOTEMPTY` 时，仅对同一次替换异步重试，最多 24 次，等待从 25 毫秒递增至每次最多 250 毫秒；不重放采集或删除目标文件。失败保留先前文件并清理本次临时文件，仍报告原始错误。文件系统错误与接口授权拒绝分别显示，`EPERM ... rename` 不再提示“当前身份没有权限”；持续失败时检查占用或共享目录访问。

在人格配置的「全天记录」页通过连续时间尺和事件列表回看，沿用移动端的固定中央指针、左右拖动、惯性滑动与跨日浏览。默认显示 30 分钟，缩放范围为 3 秒至 24 小时（时间轴左右边缘的总跨度）；日期用于跳转，回到实时后指针跟随当前时间。电脑麦克风沿用 RabiSpeech 的分段录音与 ASR；屏幕、摄像头按设定间隔保存 JPEG 画面，前台窗口在采样发现标题变化时生成事件。它不是连续屏幕录像，也不从窗口标题推断用户正在操作。空白区间保持空白，采集失败单独显示，不伪造全天覆盖。

电脑采集与 Home Assistant 来源默认全部关闭；总开关首次开启需要至少选择一个来源。开启意图按本机持久化，下次软件启动恢复对应人格记录；关闭总开关清除恢复意图，正常退出软件保留它。同一电脑只有一个采集人格，其他人格显示占用状态。运行中可修改设备开关并保存，等待当前有界采样结束后生效。麦克风断流后按采样间隔尝试重开，屏幕和摄像头独立采样；一个来源失败不丢弃其他来源的结果。摄像头仍按配置编号选择，编号被系统重排时需要重新确认，不能保证物理设备身份不变。

记录设置新增 **Home Assistant** 开关，可单独启用。它直接订阅 Home Assistant「活动」页所用的 `logbook/event_stream`：包括扫地机进度、普通状态变化和自定义活动，保留原事件时间、实体、状态文本和稳定去重 ID。先在米家设置中连接 Home Assistant；无需开启 Agent 事件监听、切换“显著/全部”或绑定相同人格。保存设置后开启全天记录，先同步本机当天已有活动，再持续接收新事件；暂停或关闭该来源后断开活动订阅。重连或重新启用时同步当天最近 24 小时内的活动并去重，不导入更早日期。时间轴、来源和“设备事件”筛选都可查看。未连接、授权失效和活动订阅失败会显示来源错误；不影响其他采集来源。仅选择 Home Assistant 时不调用语音或画面采集服务。原有 Agent 通知与摄像头事件录像保持独立。

设备记录保留活动实体、名称、状态文本与原事件时间；ID 由活动时间、实体、状态或消息及上下文生成，同一活动重试不重复写入。旧设置缺少 `homeAssistant` 时按关闭读取，下次保存写入统一格式；兼容仅用于旧设置升级，完成存量迁移后可移除缺省转换。新记录与电脑记录使用同一存储和索引，SSE 更新页面。活动来源不下载录像、不执行设备动作，也不自动投递 Agent。

麦克风复用唯一 RabiSpeech owner：已有电脑监听时共享其会话，只纳入本次开始后的电脑录音，关闭或租约到期不停止原有监听；原先未监听时才启动临时会话，关闭或失去 Manager 续租后停止并还原配置。远端输入不作为电脑麦克风，来源或会话改变时明确报错。原语音服务配置的 ASR、声音阈值与消息路由规则继续适用，未达到转写条件的声音不等于已保存事件。

手机转写成功后，将本次事件的来源时间、文字与可回放 WAV 通过已认证的 resources 通道同步到实际处理该事件的电脑。队列与 ASR ACK 分开，网络或旧电脑不支持事件接口时保留待同步状态，不阻塞转写。来源和账号在入队时冻结。只汇总用户在当前人格设置中选择的手机；设备身份由认证通道提供，正文不能冒认其他手机。目前这一同步覆盖更新后生成的转写事件，不会凭旧回执猜测账号并补传全部历史，也不包含手机尚未上传的视频和健康数据。

屏幕采集与 F1 复用桌面模块 `rabiroute_tray.desktop_capture.capture_desktop_pixels()`，统一抓取所有显示器的原生像素。全天记录只缩放和保存 JPEG，不加载 Qt、不打开框选或修改剪贴板；F1 继续负责选区、多屏坐标映射与交互。

预览区域在页面向下滚动时固定在顶部导航下方，时间尺随页面正常滚动，事件列表独立滚动。拖动时间尺会定位列表；滚动列表会同步中央时间和回看事件。点击时间尺事件或列表事件均可选中回看，事件按钮不接管拖拽。列表使用预取事件窗口，刷新时保留当前可见记录的位置，程序定位不会反向触发滚动联动。

屏幕预览完整等比显示虚拟桌面，保留 Windows 中各显示器的相对位置、比例和间隙；宽屏预览框不会裁掉图片下方的显示器。

## 数据与生命周期

- 电脑设置和事件在角色目录的 `all-day-recording/<host-hash>/`；不同电脑分开。设置不保存“正在采集”的意图。
- 事件以采集起始时间 `startedAt` 分 UTC 日期目录，每事件一个稳定身份哈希文件。页面读取完整日期索引并合并增量事件，缺失索引在后台按日补齐；跨午夜连续读取对应 UTC 分卷，每次接口请求不超过 26 小时。分卷只是物理组织，不是记忆沉淀或删除。
- JPEG/WAV 完成写入后提交事件。电脑录音复制进该记录存储，避免依赖语音服务的临时音频缓存。手机媒体由现有 ResourceCache 保管，校验每块 SHA-256 和持久化回执后才提交事件。
- 手机事件索引由接收电脑保存于 `data/mobile-recording-events/`，通过认证来源和稳定事件 ID 幂等覆盖；文件写入串行化、临时文件 fsync 后原子替换。未自动同步到其他电脑或人格。
- 不自动删除原始记录；仅删除本次原子写的临时文件。磁盘不足、语音服务离线、权限或摄像头故障必须显示未知/失败。
- 当前时间轴供用户、安全本机 Agent 和已认证远端 Agent 按需查询，不自动投递 Agent，也不把全部原始记录注入提示词。

## Manager 公开接口

Manager 地址必须从 Host 当前代发现并核对 `/meta`。以下公开接口允许安全本机请求与已认证远端 Agent，二者权限相同；不接收任意路径或命令，沿用 Manager 只读模式。远端请求始终校验最初准入的授权租约；正文读取、控制队列等待、存储及语音调用后重新校验，写入／下一次网络调用及返回数据、原始媒体前再次校验。撤销、替换或关闭后重新开启授权都不能回退到本机权限。公开权限不改变手机资源的认证 owner、人格可见设备选择或 Host 唯一采集 owner；设备隧道不是公开 Agent 凭据。

基路径：`/api/roles/:roleId/all-day-recording`。JSON 成功为 `{code:0,data:...}`，错误为 `{code:-1,message:...}`。

| 方法与路径 | 合同 |
| --- | --- |
| `GET /` | 设置、实际运行状态、采样时间、错误与可选择的手机来源 |
| `PUT /settings` | `sources:{microphone,screen,window,camera,homeAssistant}` 全部为布尔；`intervalSeconds` 10–3600；`cameraIndex` 0–16；`mobileDeviceIds` 为发现列表里的来源哈希。运行中也可保存 |
| `POST /start` | 按已保存设置开始；同人格重复开始返回当前状态，另一人格占用则失败 |
| `POST /stop` | 等待本次有界采样完成并停止本会话；重复停止不产生第二次动作 |
| `GET /catalog` | 轻量日期目录 `days`、最近事件及已知 `incompleteDays`；不等待完整历史 |
| `GET /catalog?day=YYYY-MM-DD` | 当日现成索引事件和完整性标记；不扫描原始事件或等待日期写锁 |
| `POST /index-repair/YYYY-MM-DD` | 立即确认索引重建已排队；同一人格、日期共享任务，完成或失败通过 SSE 通知。只重建派生索引，保留原始记录 |
| `GET /recent` | 当前电脑与已选手机的最近事件快照，独立于历史重建 |
| `GET /events?since=...&until=...` | 毫秒时间范围，不超过 26 小时；返回按真实来源时间排序的事件 |
| `GET /media/:day/:hash.jpg` 或 `.wav` | 只读当前人格、当前电脑的受控媒体 |
| `GET /audio?since=...&until=...&id=...` | 先验证事件属于该人格可见时间线，再读对应手机资源或语音音频 |

写设置、开始、停止以单个 Manager 串行队列执行；开始/停止天然按当前会话幂等，结果不确定先 GET 核对，不跨代自动重放。快照进程上限 15 秒，语音 API 上限 30 秒。界面由 `all_day_recording` SSE 更新，不轮询业务状态。

手机新增 `PUT /api/resource-cache/data/recording-events`，仅受信 resources 隧道调用。正文为 `{id,startedAt,endedAt,text,chunks}`；时间为毫秒，文字最大 100000 字符，最多 16 个 1 MiB 内容哈希块。每块必须已属于同一认证来源并通过校验；成功回 `{durable:true}`。相同来源/事件 ID 重试幂等；400 为数据/资源错误，403 为授权/只读限制，404 为旧电脑未支持。手机稍后使用同一冻结队列项重试。

列表只渲染可视区域附近最多 24 行；宽时间范围内同来源的密集事件按 0.5% 刻度分组合并，点击可放大并选中事件。后台刷新合并为一个待处理请求，不取消正在完成的读取；隐藏页面暂停自动刷新，返回后补一次。刷新保留已有内容与浏览位置。十万条前端合成数据测试不代表同规模 NAS 查询吞吐。

进入页先显示可用的人格预览，再独立读取状态、最近事件和轻量日期目录。首屏只请求当前时间范围及两侧各至少 15 分钟的预取，不逐日读取全部历史；滚动按稳定游标每页读取最多 100 条，时间轴按当前范围查询。列表仅渲染最多 24 行，标签页事件缓冲最多 2000 条，浏览锚点周围保留窗口；淘汰后可重新从服务器查询，原始记录不删除。新记录不会打断回看位置。

浏览器在 IndexedDB 中按人格保存展示元数据预览，有效期 24 小时；标签页内存最多四个人格，每份当前事件缓冲最多 2000 条。localStorage 序列化有界缓冲，大于 2000 条的旧缓存只保留最近 200 条；完整展示缓存写入最多每 30 秒一次，避免每次采样复制整份历史。旧版大缓存恢复后也限制当前窗口。24 小时仅限制缓存有效期，不是原始记录保留期。缓存不证明采集成功；运行状态来自实际会话。历史读取上限 60 秒，状态、最近事件和图片 12 秒，控制写入 45 秒且不自动重放；缓存数据库等待最多 4 秒。

`events-index/YYYY-MM-DD.json` 是当前 Host 写入拥有者维护的可重建日期索引。写原始事件前持久化同日 `.dirty.json` 标记，原始事件和索引均提交成功后才移除标记。缺失或损坏索引在独立读取进程扫描；扫描不占用采集写入队列，拥有者记录扫描期间已提交事件的增量，最终按稳定 ID 合并并串行原子提交索引，较新的同 ID 内容优先。只有最终提交阶段需要日期写锁。有效索引不依赖 NAS 目录时间戳；拥有者之外修改原始文件时，运维恢复必须同时使对应索引失效。

同一日期的并发查询共享读取任务，成功结果缓存五秒，最多八个日期、每个最多两万条事件。拥有者写入成功立即使对应内存缓存失效，失败不缓存。索引和缓存均可重建，原始文件不移动或删除，不使用归档的 24/72 小时窗口。首次索引重建仍随当天文件数增长；日期索引不等于完成服务端游标分页。

慢 NAS 读取通过现有有界读取进程池执行，不占用 Manager 的文件读取线程。`catalog/recent/events/page` 立即返回已有内存快照及 `loading/pendingDays/readError`，冷读取在后台合并相同任务；完成后 `all_day_recording` SSE 携带 `catalogReady/readDay/readFailed`。缺失或损坏日期索引仍使用独立 `index-repair` 请求，拥有者串行重建、最多排队 32 个，通过 `indexDay/indexFailed` 通知。`GET /catalog?day=YYYY-MM-DD&summary=1` 只返回完整性和日期，不传完整当日事件。失败与空历史分别处理，未确认日期不能显示“已到最早记录”；相邻事件等待对应完成通知后继续定位。

索引重建使用采集拥有者持有的单进程队列，仍遵守全局六个读取任务上限，不排在其他启动目录任务后。工作进程内每批最多并行读取 16 份原始事件；拥有者退出时取消重建进程，未完成索引仍保持脏标记，下一代按需恢复。

日期索引正文的并发读取共享同一任务，成功后缓存 30 秒，最多 32 份且序列化正文合计不超过 64 MiB；缺失、损坏与读取失败不缓存。索引拥有者提交新正文前使相应缓存失效，脏标记仍独立检查，已有索引只能证明其已保存部分。当前 Manager 还在内存中维护已读取的采集意图、至多 16 个人格的电脑设置和已发现手机，成功写入同步更新，首次读取失败不缓存；进程重启重新读取持久文件。运行状态仍来自实际采集会话，不能由缓存推导成功。等待读取期间的 SSE 更新合并为一次待处理刷新，在读取结束后执行；历史读取失败与采集状态分别显示。

Manager 读取快照最多保留 32 份、序列化元数据合计 64 MiB；冷读取待完成任务有额外 48 份硬上限。快照五分钟后在下一次请求时异步重读，不使用业务轮询。拥有者正式提交后合并增量，失效时取消旧读取，晚到结果不得回写；重启从持久索引重建。最近预览按来源最多 128 条，最新媒体在内存中最多四份、合计 16 MiB，旧媒体通过读取进程按需加载。这些都是可重建展示缓存，不使用归档 24/72 小时窗口。

## 宽屏回看布局

事件缓冲淘汰后，时间轴仍保留当前查询范围的按来源、刻度聚合标记；点击标记将对应真实事件放回浏览窗口。缩到全天时不会因列表只保留 2000 条而抹去其他时段，相邻事件仍使用服务器游标查找。

进入页面自动选择最近的屏幕画面，没有画面则选择最近的非状态事件。状态与事件独立读取；恢复标签页缓存后立即展示事件，缓存写入延后执行。时间范围查询使用区间索引，保留跨越可视范围的长音频，拖动不再扫描全部缓冲事件。快速导航后延迟 150 毫秒读取图片，旧请求取消且不能覆盖新选择；新图异步解码完成后才替换已有画面。页面内图片缓存最多四张、合计 16 MiB，退出页面释放。音频点击播放才加载；转写先展示 600 字符，按需展开全文（事件响应仍包含全文）。

宽度达到 1000px 时，左侧约 60% 固定显示预览和时间轴，右侧约 40% 为独立滚动的事件列表，两列整体等高。事件数量、来源筛选和刷新放在顶部标题与记录开关之间，空间不足时自动换行；窄屏为上下布局。列表按最新在上排序。时间轴定位列表，列表滚动定位时间，刷新保留正在浏览的事件。


回看只显示成功转录且有非空文字的 **ASR 事件**；纯录音仍保存，但不显示在事件列表和历史时间轴。事件沿用原始采集时间及稳定 ID，不使用转录完成时间。筛选、分页和上一个/下一个事件均在计页前排除隐藏录音。移动端回到实时仍显示麦克风波形。移动端日期、实时、刷新工具栏增加上一个/下一个事件，事件类型（ASR/录像）与设备来源独立筛选。

前后事件导航在完整加载且未裁剪的时间范围内直接定位；范围外才异步分页，显示加载状态并限制等待时间。相同采集时刻的不同事件按稳定 ID 逐条切换，不跳过。


摄像头由当前录制会话的独立常驻进程持有，连续读取以维持自动曝光。首次打开至少预热 2 秒并读取 15 帧后才保存；后续采样读取新帧，不重新开关设备。关闭摄像头来源、切换索引、暂停或正常退出会释放设备。Manager 每 30 秒续租；租约 120 秒无续期或父进程断开时，工作进程自动退出，即使驱动读取阻塞也能回收。采样等待最多 15 秒，超时终止该工作进程并报告错误，下一次采样重新打开并预热。帧只驻留内存，仍按设置间隔保存 JPEG，不保存连续录像；不强改驱动曝光参数。
