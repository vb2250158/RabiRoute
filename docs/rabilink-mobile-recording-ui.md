## 统一日常入口

首页集中配置与启动全天记录，记录页回看，消息页聊天，设备页负责接入；本地保存不要求先连接电脑。

1. 选择“音频 / 音视频 / 仅健康”模式。运行/暂停独立于模式，暂停后保留选择，不再把“暂停”当成第三种媒体模式。
2. 音频选择手机或眼镜，健康设备按能力加入。眼镜录音需要授权与真实连接，健康需要可用 Provider；仅健康不启动麦克风。
3. 选择“仅保存 / 转写 / 交给 Agent”处理策略和上传许可，再明确开始。默认处理策略为转写不等于默认启动；升级 `running=false`，不会自动打开麦克风。
4. 暂停停止当前允许的采集并保存边界；切来源/模式先完成旧输入停止与保存。用户暂停不能被重连、重启或健康回看补采绕过。
5. 音视频继续提供预览、全屏、开播步骤；预览静音，原文件保留收到的声音。视频**停止后**才派生音轨送处理队列，不是实时视频转写。
6. 消息页不再有独立采集系统。普通回复使用可清除消息通知；唯一常驻状态通知由全天记录 owner 维护，点击回记录入口。

## 保存、转写与回看

- `RabiConversationService` 是唯一运行 owner；旧独立本地音频、录像及设备状态 service 已从本轮源码移除。视频由普通 controller 接收，音频统一写 durable spool，健康 controller 服从总许可和允许窗口。
- 新记录冻结 `captureId`、物理来源、Route 与处理策略；切聊天人格不改投排队记录。本地媒体和转写按记录关联，不把当前会话当成历史归属。
- 新转写已按 `captureId` 只读关联；仅人工刷新最近 24 小时、最多 200 条、按 `processedAt` 查询的结果。缺 ID 不猜归属，不能称完整历史回看。健康目前只统一采集/状态，完整历史仍在 PC。
- `autoResume` 无行为 UI 已移除，仅内部保留 false；开机明确暂停，自动恢复采集尚未实现。
- `local_only` 不提交处理；`transcribe` 要求 PC 支持仅转写且不投递 Agent；能力与 worker 围栏已接入源码，最终验收仍待，无支持时保留 `deferred`，不得降级为 Agent 投递。排队、上传确认、转写完成分别显示。
- 一次视频对应一条记录，内部原始分段按顺序回放。分享导出原始分段，不伪称合并文件。旧 WAV、视频、PCM 队列及已收到转写保留，不改写来源。
- 新记录即使收到传输 ACK，也**不会按旧传输缓存保留期限自动删除**。当前尚未实现完整自动滚动删除，不能称全天容量管理已经完成。未确认/隔离数据不静默删除；空间不足停止接收并报告。

## 状态、隐私与设备边界

开始接收不等于眼镜开播，收到视频才计为真实覆盖。授权、连接、实际数据和 PC 处理分别显示。模式切换、设备断线或写入异常的缺口必须可见，服务存活时长不是录音覆盖。

手机暂停不等于已关闭厂商眼镜相机或手表测量。手动乐奇直播仍需在乐奇结束；PC 健康 Companion 未确认停止时要显示远端未确认。允许窗口及历史隐私区间必须阻止恢复后的迟到健康样本补入。

原生乐奇手动直播保留已有真机证据；自有眼镜自动安装/开播仍需单独验收，不使用 CXR-M。旧录像入口如有兼容调用，只能转到统一 owner，不能恢复旧独立 service。

## 故障与验收

采集使用有界队列、单写、持久来源、原子封口和独立上传。队列恢复不应阻塞主线程；保存失败保留证据，强杀/断电不等于正常保存。预览错误不应中止已正常运行的录像。分享使用 FileProvider 临时读授权，卸载前导出需要保留的文件。

本轮最终源码回归已完成 Android 131 项测试、0 失败与 assemble，根 npm run build 通过；开发 APK 为 0.3.23-dev（versionCode 26）。构建通过不等于已安装或真机通过。唯一 owner、通知、来源冻结、隐私窗口、仅转写、视频音轨与健康联动以及 24/72 小时长稳均需按新架构验收。
