# 自动化中的 Agent 投递目标

Agent 端设置定义可用接收者和运行参数；角色自动化规则决定每条消息投给谁。配置主角色、秘书或消息处理池不会改变其他规则的目标。

## 页面配置

在「角色 → 自动化」编辑规则，在「通知 Agent」下选择「投递目标」：

- 主角色：使用当前路线的主角色绑定。
- 计划秘书：使用消息关联计划的秘书绑定。缺少计划或秘书绑定时失败，不选择其他计划的秘书。
- 消息处理 Agent：使用现有消息处理池、任务状态和模型配置。
- 记忆整理 Agent：创建或复用现有整理会话。
- 自定义：依次选择 Agent 端和指定会话。会话下拉支持输入名称或 ID 搜索，列表以名称为主、完整 ID 和工作目录为辅，可继续加载更多。切换 Agent 会清空旧会话；未选齐 Agent 和会话时不能点“完成”。选定后可展开会话详情。

修改后保存。刷新后应看到相同目标。修改主角色绑定会影响之后引用主角色的规则；已选定的自定义会话不随之变化。

消息规则在「通知 Agent」下设置「携带最近消息」和「最近消息条数」（1–200 条）。每条规则独立控制是否附带当前会话最近 N 条消息；关闭只停止附带历史，仍保留聊天记录。当前消息和显式引用仍按原流程交给 Agent。定时任务不自动附带聊天历史。

条数保存在 `automationRules[].action.recentMessageLimit`，`0` 表示关闭。旧规则未填写时继续沿用原消息端条数（默认 12）；编辑该选项后按规则保存。角色配置中的独立「消息上下文」标签页已移除。

## 数据归属

角色 `personaConfig.json` 的 `automationRules[].action.target` 保存目标。引用接收者时仅保存稳定 ID；接收者目录 `agentRecipients` 和现有 Agent 会话、模型及实例参数保存在路线的 Agent 配置中。

```json
{
  "id": "private-to-primary",
  "enabled": true,
  "trigger": { "type": "message", "routeKinds": ["private"] },
  "action": {
    "type": "deliver_agent",
    "target": { "kind": "recipient", "recipientId": "primary" },
    "template": ""
  }
}
```

自定义目标保存 `kind: "session"`、`agentTargetId`、`agentAdapter`、`sessionId`、`sessionName`、`workspace`。同名会话按实例和完整 ID 区分。指定会话接口不会通过名称创建替代任务。

共享角色的规则可用 `sourceRouteIds` 限定适用路线；未设置时适用于所有引用该角色的路线。默认规则只在初始化或迁移时产生，读取已保存规则不会补回删除项。

## 升级与恢复

升级前先预览受影响角色；每次传入引用该角色的完整路线目录：

```powershell
node --import tsx scripts/migrate-agent-delivery-targets.ts --persona data/roles/Example/personaConfig.json --routes data/route
# 核对预览后执行同一命令并添加 --apply
```

迁移器将旧消息池、记忆整理开关的投递范围转换成显式规则。同一角色在不同路线上的旧行为不同时，生成带路线条件的规则。原会话 ID、秘书绑定、模型、池状态和其他角色字段保持原值。转换前保存原始文件快照，写入前检查并发修改，写入后逐文件回读；失败则恢复已写文件，遇到外部修改时保留快照并报告冲突。版本标记防止重复迁移。旧目录格式可通过 `ManagerConfigRepository.migrateLegacyConfigs()` 的显式维护流程转换；Manager 启动不执行全目录同步迁移。

运行时缺少目标的旧规则会失败，需先迁移，不能依靠旧开关再次选目标。运行代码中已退出消息池和记忆整理的隐式目标选择。旧字段仅供迁移识别；计划系统自身使用的配置仍按原合同工作。

失败记录保存原规则、接收者目录及已解析的会话。批量重试分别保留原投递身份，不合并成新的主角色消息。原绑定失效时失败；无目标快照的历史记录不能自动重试。指定会话投递保存待确认状态和回执；结果不确定时查询原会话，未确认前不重复发送。

## 验证范围

单元和集成测试覆盖目标选择、并发隔离、原回执恢复、迁移回滚、保存和规则投影。部署验收还需确认新页面资源和 Manager 版本，以及本地、远端目标会话的实际回执。构建通过不代表真实投递已通过。


## Agent 完成结果的文件附件

「自动投递包括文件」下有三个默认勾选、可独立关闭的选项：

- **MD附件自动转换为图片**：本地 `.md`、`.markdown` 链接渲染成图片发送。
- **图片附件转换为图片**：PNG、JPEG、GIF、WebP、BMP、AVIF 文件直接显示为图片。
- **HTML转换为链接**：`.html`、`.htm` 由本机 HTML 分享插件（`io.rabiroute.manager.html-shares`）在其稳定私有存储目录保存快照，发送 RabiLink GUID 分享链接。相对引用的本地图片、样式及脚本嵌入快照；网络资源沿原 URL 加载。关闭某项后该类型仍作为原文件上传。

规则参数为 `markdownFilesAsImages`、`imageFilesAsImages`、`htmlFilesAsLinks`。缺省或 `"true"` 开启，`"false"` 关闭；父选项 `includeFiles="false"` 时均不执行。

浏览器按现有 **局域网 → P2P → Relay** 顺序自动连接，局域网可用时直接读取，无法直连时使用透明加密中继。HTML 分享插件在 PC 的同一私有存储中持有快照、原 GUID 和内容密钥，服务器只保存 GUID 与目标 PC 的路由信息，不缓存 HTML。密钥放在链接片段（`#` 后），不随 HTTP 握手提交；任何获得完整链接的人都可查看。PC 必须在线；浏览器阻止局域网 WebSocket 或 P2P 不通时自动尝试下一通道。当前没有分享有效期或撤销入口。

PC 与 Relay 需要同时更新分享协议。未升级、未配置连接或转换失败会报告具体附件失败，并继续其他附件，不自动退回原文件。已准备的转换载荷按原投递 ID 冻结，重复处理沿用原内容及回执，即使源文件已更新或删除。安装、外网实机与源码验证分别核对。

部署维护：Relay 的 `/share/*` 页面、握手与 WebSocket 路径需转发到同一 Relay 服务。完整部署模板包含该路由；`RuntimeOnly` 保留已有 Caddy 配置，维护时沿原反向代理发布入口同步此路由。插件资源由同一运行清单复制、备份与恢复。

在「角色 → 自动化 → Agent 钩子 → 事件投递」的 NapCat（QQ）规则中，**自动投递包括文件**默认勾选。旧规则未填写 `destination.params.includeFiles` 时也包含文件；字符串 `"false"` 表示取消，`"true"` 表示明确开启。该选项随角色对应 Agent 的钩子规则保存。

钩子发送完整正文后，按各转换选项将本地 Markdown 链接指向的附件发送到同一 QQ 群或私聊：MD 和图片可作为图片发送，HTML 可作为分享链接发送；相应转换关闭或其它文件类型仍上传原文件。支持绝对路径、`file://`、URL 编码、尖括号包裹的含空格路径、源码行号与锚点；网页链接和代码示例中的链接不作为附件。同一轮、同一目标的同一路径只处理一次，最终发送的文字、图片或文件仍遵守路线对应的输出策略。

正文分段与附件各自保存投递 ID 和持久回执。缺失或被策略阻止的文件不影响其他文件，钩子返回部分失败。待确认及失败回执保留供诊断，不盲目重发。文件须能由 Manager 所在电脑读取，其他电脑的本地路径不会自动传输文件内容。


## 流程图和架构图转图片

NapCat 完成钩子新增 **自动识别流程图/架构图**，默认勾选。`destination.params.renderDiagrams` 保存字符串 `"false"` 表示取消，`"true"` 表示明确开启；未填写时使用默认值。Mermaid 围栏代码块在本机转换为 PNG，再与前后正文按原顺序图文混排发送。未标语言但以 Mermaid 流程图、时序图、类图、状态图、ER 图、架构图语法开头的围栏代码块也会识别；其他代码块保留文字。普通描述和 ASCII 图不作推测转换。

渲染使用随依赖安装的 Mermaid 和本机 Chromium 系浏览器，图表内容不发往外部服务。流程图采用较宽节点和紧凑间距，画布按内容裁切；较长流程图在节点和连线文字之间分成连续图片，标注序号，避免 QQ 缩略图将文字缩得过小。保留原图方向、内容和手动换行；独立 PNG 导出仍返回完整图。其他图形类型和 Markdown 表格保持单图。沿用路线图片发送策略和 Markdown 渲染额度。转换失败时保留源码并标注转换失败，继续发送其余内容。混排消息沿用原投递 ID 和持久回执去重；TTS 仍使用文字。


## 表格转图片

NapCat 完成钩子的 **自动渲染表格** 默认勾选。`destination.params.renderTables` 使用字符串 `"false"` 关闭、`"true"` 开启；旧规则未填写时也默认开启。Markdown 表格在本机渲染成 PNG，保留列对齐、换行和加粗等格式，与前后正文按原位置混排发送。该开关独立于流程图转换；代码块内的表格示例和普通竖线文字仍保留文字，关闭时保留原始表格。渲染沿用 Markdown 图片发送策略与额度，语音仍使用文字。

## 原有图片的图文混排

回复中的 Markdown 图片按原位置与文字混排发送，支持本地绝对路径、`file://`、相对任务工作目录的路径以及 HTTP(S) 图片。关闭图表转换仍会保留原图片。图片不再重复作为文件附件上传；普通文档链接继续遵守文件附件开关。代码示例中的图片语法保留文字。

本机 Codex 任务通过原生线程拥有者取得精确历史文件，只提取本轮成功的 `image_gen.generation` 输出，排除用户输入、工具截图和其他轮次。原生图片按 Desktop 的方式接在最终正文后，用内存图片数据发送，不另建磁盘缓存。已通过本地 Markdown 图片引用展示的同一生图结果不再追加。仍沿用原投递 ID 和回执去重。此原生图片采集依赖本机拥有者历史；远端主机的原生图片需由其拥有者提供媒体，不能把远端路径当成本机文件读取。
