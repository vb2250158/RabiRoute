# デバイスを検査し、アクションをテストする

メッセージ ルートでスマート ホーム → Xiaomi ホーム → デバイス リストを開きます。登録された各デバイスには、その名前、部屋、モデル、公開されたエンティティ数が記載されたカードがあります。名前、部屋、モデルで検索します。デバイスのないシーンとヘルパー エンティティは個別に表示されます。

デバイスカードを開くと、その使用状況が記録されます。次のページのリロードまたはデバイスの更新では、頻繁に開かれたデバイスが最初に表示され、最近開いたデバイスが同じ数だけ最初に表示されます。他のデバイスは元の順序を維持します。クリックしても、現在のリストはすぐには再配置されません。履歴は現在のブラウザーに残り、サイトのデータをクリアするとリセットされます。シーンとヘルパー エンティティは除外されます。

1. カードを開いてクエリ/制御エンティティを選択し、その現在の状態とエージェントの機能を検査します。
2. アドバタイズされたアクションを選択し、そのスキーマに一致する JSON を入力します。数値型、ブール型、配列型を保持します。文書化されていないプロトコル文字列を推測しないでください。
3. プレビューパラメータは、デバイスを操作せずに検証する。テストを実行するとアクションが送信されます。
4. 結果を検査し、その元のレシートをクエリし、必要に応じて新しい状態を読み取る。サービスの受け入れは物理的な完了を確認するものではありません。結果が不明な場合は、再送信せずに受信クエリを実行できます。ブラウザーは最新の受信情報を保持するため、リロード後にクエリを再開できます。

バキュームの詳細には、バージョン 2 レンダリングと 5/10/30 秒のスナップショット更新によるマップと位置が含まれます。ページを非表示にしたり、詳細を閉じたり、タブを切り替えたりすると、読み取りが一時停止されます。 3 回連続して失敗すると、更新が停止され、最後のマップが保持されます。更新時間はダウンロード時間です。ポーズの鮮度は未検証。マップと軌道位置の両方が変更されない場合、レンダリングは変更されません。

マップとエージェントは、同じマップ/軌跡フィードバック API を共有します。使用可能な軌道テールが利用可能な場合、オレンジ色のマーカーは軌道位置を示し、ページには新しいポイントが受信されたかどうかが報告されます。それ以外の場合は、クラウドのスナップショットとその理由が表示されます。マップ ファイルが変更されていない場合でも、軌跡の位置が変更されるとマーカーが更新されます。繰り返されたポイントは再び移動としてカウントされません。デバイスまたはロボット タスクを切り替えると、継続がリセットされます。読み取り時間は、デバイスの位置特定時間、到着、自動ナビゲーションの準備状態を確立するものではありません。

マップはデフォルトで利用可能な幅と高さに適合します。詳細を確認するにはズームイン/ズームアウトを使用し、マップ全体を復元するにはウィンドウに合わせるを使用します。ズームインするとスクロールします。デフォルトでは、マップの詳細と生ファイルのリンクは折りたたまれています。スケーリングでは、ポイントを選択するときにネイティブのマップ座標が保持されます。

マップの右下には、コンパクトな 16:9 ビデオ プレビューが表示されます。デフォルトでは、再生には画像のみが表示されます。クリックするとステータスが表示され、画像内のビデオが更新されて終了します。もう一度クリックするか、Esc キーを押してコントロールを非表示にします。 Tab で画像にフォーカスを合わせ、Enter または Space でコントロールを切り替えます。コントロールを切り替えると、再生が維持されます。狭いマップでは、より小さなプレビューが使用されます。携帯電話などの非常に狭いウィンドウでは、ポイントの選択が妨げられないように、マップの下に右揃えで配置されます。パスワード管理では、ページのライト/ダーク テーマを使用して完全なフォームが表示されます。マップ デバイス セレクターは、水平方向にオーバーフローすることなく狭い幅に適合します。必要に応じて既存の 4 桁の Mi Home PIN を入力し、[ビデオの開始] を選択します。入力はオプションの表示切り替えでマスクされ、送信時にクリアされます。パスワードを記憶する (ローカル) は、デバイスの検証後にのみ暗号化されます。保存すると、デフォルトのビューには保存されたパスワードと入力フォームなしの接続ボタンが表示されます。

PIN の入力、置換、削除が送信、接続、再生中に消えます。終了の受信が確認された後にパスワード管理を復元するには、[ビデオの終了] を選択します。不確実な終了では、削除が公開されるのではなく、セッションとエラーが保持されます。終了後、「パスワードの管理」で置換とローカル削除が開きます。どちらもデバイスの PIN を変更しません。 PIN を再試行または確認する前に、失敗したセッションを終了してください。コントロールは、実際のフレームがレンダリングされた後にのみライブ画像を表​​示します。をインストールします。 [ビデオトランスポートコンポーネント](../vacuum-cloud-map_en.md) まず。ビデオには音声、録音、または動きはありません。再生時間制限はなく、詳細を閉じたり、タブを切り替えたり、ページを非表示にしたりすると停止します。カメラのスイッチ状態は引き続き 5 秒ごとに更新され、コントロールで手動で更新されます。有効なスイッチまたは接続セッションでは、受信したビデオ フレームが確立されません。

ビデオのタイムアウトと接続不能は、その理由を示しています。上流ルーターの背後にある PC または別のサブネット上の PC の場合、Xiaomi クラウドが有効なパラメータを提供し、その接続モードを表示すると、CS2 は実験的なリレー トランスポートを試みます。実際に受信したフレームのみが成功を確立します。リレー障害は、検出、登録、割り当て、デバイスの参加を区別します。一致するインターフェイスがない場合、失敗した LAN 接続にはバキューム アドレスとネットワーク ガイダンスが表示されます。必要に応じて、PC を掃除機ルーターの LAN ポートまたは Wi-Fi に接続します。ネットワーク設定は変更されず、サブネットが一致するだけでは到達可能性は証明されません。デバイスのクエリと制御には引き続きホーム アシスタントが使用されます。マップとビデオは、Xiaomi クラウドの追加機能です。

マップをクリックして座標を選択し、青い破線のパスをプレビューします。壁、立ち入り禁止区域、または不十分なクリアランスにより、明確な理由が生じます。マップが変更された後、再度選択してください。最初は、鮮度が検証されていないクラウドのスナップショットのままです。プレビューは移動コマンドを送信しません。検証済みの座標ナビゲーション ペイロードが利用できないため、[ロボットをターゲットに移動] が有効になっていません。掃除を始めることはナビゲーションではありません。アドバタイズされた開始、一時停止、停止、およびホームに戻るアクションは、「機能とテスト」で利用できます。任意のロボットの音声入力と音声入力は接続されません。

既存の接続認証は、デバイスごとの承認なしで適用されます。カードには、現在公開されているエンティティを持つ登録済みデバイスが含まれています。無効になっているデバイス、または公開されたエンティティのないデバイスは、このディレクトリの外にあります。を参照してください。 [ホーム API](../home-device-agent-api_en.md) そして [マップ接続ガイド](../vacuum-cloud-map_en.md).


マップの下の手動制御は、リモートモードに入る前に一時停止し、アクティブな清掃を確認します。パネルのフォーカスを合わせて、W を前方に、A を左に、または D を右に押し続けます。 Sは立ち止まります。キーを放すかフォーカスを失うと停止が送信されます。このモデルにはリバースコマンドはありません。終了してもクリーニングは再開されず、マップを閉じるとリモート モードが終了します。ビデオに遅延が発生する場合は、物理デバイスを観察してください。 WebGUI とエージェントは同じものを使用します [リモート API](../home-device-agent-api_en.md#shared-manual-remote-control).
