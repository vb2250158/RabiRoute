# PCを区別してインスタンスIDをリセットする



ステータス:0.3.21で導入。インストールされた Windows ホストがリセットを所有します。ソースのみのマネージャーはそれを実行できません。

各PCは、独自のインスタンスIDおよび接続キーを必要とする。表示名、ローカル接続 ID、およびインスタンス ID は別個のフィールドです。名前を変更しても、別の PC からコピーされた ID は修復されません。ローカル ID を共有するリモート PC は、ローカルであるかのようにペルソナ ソースから除外される場合があります。

## ローカル ページを使用する

1. 保持したい構成変更を保存します。リセットでは保存されたデータが使用され、ページの下書きは保存されません。
2. 開く **RabiLink → 設定** をクリックしてください **インスタンス ID をリセットします** インスタンス ID の横にあります。
3. 確認を読み、確認します。アプリケーションは古い ID をバックアップし、現在のランタイムを停止し、新しいインスタンス ID と接続キーを作成して再起動します。
4. 完了して新しく読み取られるインスタンス ID を待ちます。アドレスが変更された場合は、トレイから RabiRoute を再度開きます。ページが一時的に切断されるため、リセットを繰り返さないでください。
5. RabiLink ホームページで両方の PC をチェックし、ペルソナ ソースを更新します。ソース PC はオンラインのままであり、リモート ペルソナをサポートしている必要があります。

リセットは、保存された名前、サーバーURL、アプリケーショントークン、接続ID、ルート、ペルソナおよびメッセージ履歴を保存する。データの消去、リモート エージェント ノード ID のリセット、履歴メッセージ ソースの書き換えは行いません。バックアップは次のランタイム データ ディレクトリにあります。 `data/rabilink/identity-resets/<operation ID>/`。これらにはプライベートな設定とキーが含まれているため、決してアップロードしたりコミットしたりしないでください。

古い公開鍵に対するピン留めされた信頼は、自動的には置き換えられない。別のデバイスが ID の変更を報告した場合は、その接続を確認して再確立します。リセットによって既存のサービス許可が拡張されることはありません。両方の PC が依然として同じローカル接続 ID を共有している場合は、個別の値を設定して保存します。インスタンス ID をリセットすると、このフィールドが保持されます。

## 許可されたリモート エージェント アクセス

アクティブ ノードとエージェント認証および LAN アドミッションが有効になっている、マネージャによって認証されたリモート エージェントは、追加のプロバイダ制限なしで、ローカル アクセスと同じベースでリセットを送信し、動作ステータスを読み取ることができます。 API では引き続き、明示的な確認、現在のインスタンス ID、および固定の操作 ID が必要です。インストールされたホストは引き続き実行者になります。クライアントはコマンドやファイル パスを指定できません。

リモート エージェント プリンシパルのないリクエストは、厳密なローカル エントリ、つまりループバック接続、現在のポートのローカルホスト / ループバック IP、同一発信元リクエスト、および転送なし、リレー マーカーまたはトンネル マーカーを使用する必要があります。無効、無効、または取り消された資格情報は、地方自治体にフォールバックできません。リクエストの待機中にエージェントまたはアドミッションを無効にすると、元のリクエストが無効になります。再度有効にしてもリクエストは復元されません。

オーソリゼーション損失の返品 `403` オペレーションデータや機密性の高いレシートヘッダーを含まない。 `commitState: not_started` は、リセット要求ファイルがこの要求によって書き込まれていないことを意味します。ファイル書き込みまたはホスト呼び出しがすでに開始されている場合、結果は次のようになります。 `unknown`:リセットが発生していないことを証明するものではなく、自動再送信をトリガーしてはなりません。認証を復元し、現在のアプリケーション アドレスを再検出した後、次に何を行うかを決定する前に、元の操作 ID を使用してステータスを読み取ります。

## 別のコピーされたアイデンティティを防止する

アップグレード後、アプリケーションはアイデンティティのローカル所有権を記録します。このマーカーを含む構成またはそのデータ ディレクトリ全体が別の PC にコピーされると、スタートアップは ID を拒否します。チェックを回避するためにマーカーを削除しないでください。ペルソナと履歴を移動するときは、新しい PC 自体の構成と接続キーを保存してください。

レガシー構成には所有権マーカーがありません。最初のアップグレードでは既存の ID が保存およびバインドされるため、以前のコピーを検出できません。すでに複製されている PC は、1 台の PC で明示的にリセットする必要があります。このチェックでは、オペレーティング システムのマシン ID が使用されます。そのアイデンティティを保持する完全な OS クローンでも手動でリセットする必要があります。これはハードウェア認証ではありません。

## リセットが完了しない場合

ページは、「キューに入れられた」ことを承認のみとして扱う。この操作中、最大 45 秒間ステータスをクエリし、完了が確認された後に ID を再度読み取ります。切断またはタイムアウトはリセットの失敗を証明するものではなく、自動再送信をトリガーすることもありません。

ホストは、動作状態、サブプロセスの目的、PID、起動ソース、およびログを記録する。リセットが中断されると、トランザクション記録が残ります。次回の起動時に、ホストはマネージャーを起動する前にそれを回復します。現在のファイルを検証できない場合、またはリカバリに失敗した場合、起動は停止します。参照 [Windowsの起動とパッケージ化](../windows-launcher-and-packaging_en.md#instance-identity-reset) 。
