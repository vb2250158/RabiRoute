# 角色与消息规则

Route 决定消息怎么进入和投给哪个处理端；角色决定处理端以什么身份、背景和判断框架理解消息。两者分开保存，也可以独立复用。

角色配置中的“消息”标签改名为“消息适配器”。“消息记录”位于左侧“计划与记忆”下方，随顶部所选电脑和角色显示记录，不再放在角色配置标签内。

自定义路由变量由内部配置和程序维护，WebGUI 不再提供变量编辑卡片；已有配置及模板引用继续生效。

## 切换电脑和角色

在顶部角色下拉菜单中，先选“本机”或其他电脑，再在第二级菜单选择该电脑上的角色。顶部显示“电脑 → 角色”；仅浏览电脑列表不会切换当前角色。远端电脑的刷新入口也在菜单内，页面不再单独显示来源 PC 区块。

角色配置页直接显示分区标签，不再展示当前角色、消息规则数量、定时任务数量和角色目录概览卡片。角色资料在“基础资料”中查看，规则和定时任务在“自动化”中查看。

## 新增消息规则和定时任务

自动化区域直接显示“消息规则 / Agent Hook”标签，不再显示重复标题、说明和规则总数。

在“角色配置 → 自动化 → 消息规则”选择左侧消息类型，右侧显示该类型的规则与数量。点击“新增消息规则”直接打开编辑界面，默认使用当前类型；也可在编辑界面左侧切换类型。选择“定时任务”后设置固定间隔、每天时间或一次性时间，再选择通知 Agent 或运行脚本。完成后保存角色配置生效。窄屏时类型栏移到顶部，可横向滚动。

列表只显示已有规则的类型，已停用的规则也计入；删除某类型的最后一条规则后，该类型隐藏，并切换到剩余类型。没有规则时仍可点击“新增消息规则”，编辑界面保留全部类型供选择。

## 选择接收消息的 Agent

编辑自动化规则，在「通知 Agent」下选择「投递目标」：主角色、计划秘书、消息处理 Agent、记忆整理 Agent或自定义。自定义时依次选择 Agent 端和已有会话。Agent 端设置保存绑定与运行参数，具体消息去向由规则决定。详见[自动化 Agent 投递](../automation-agent-delivery.md)。

## 选择钩子的 Agent 端

在「角色 → 自动化 → Agent Hook」点击左侧 Agent 标签卡，查看并配置对应端；窄屏时标签卡显示在顶部。每张卡片显示该端的已开启项数。可选端来自绑定当前角色、已启用消息路线中添加的端，并只显示支持生命周期钩子的端。未添加时，前往 Agent 端设置添加；安装或发现软件本身不会增加选项。

各 Agent 独立配置，可同时生效；切换标签卡只切换查看的设置。点击当前 Agent 标题右侧的“触发与上下文”按钮，在弹窗中设置会话上下文、工具刷新、完成通知和通过 Rabi 投递 Agent 消息。关闭弹窗保留当前编辑，仍需点击页面顶部保存生效；「自动追问」与「事件投递」默认折叠，展开后编辑参数。修改后点击保存生效。

旧角色配置继续作为尚未单独设置的端的默认值。项目和会话条件只读取所选端的候选。读取计划标记失败时可以重新读取，不会自动重放保存或发送操作。

## 配置事件投递条件

在「角色 → 自动化 → Agent Hook → 事件投递」展开规则，点击「添加条件」打开弹窗。第一个字段是「条件类型」，随后显示详细说明和对应参数。已有条件通过「编辑条件」在同一弹窗修改；确认更新当前草稿，取消不改动原条件，最后仍需点击页面顶部「保存」才能生效。

| 条件类型 | 含义与参数 |
| --- | --- |
| 限定项目 | 填写绝对项目目录，或读取所选 Agent 端的项目候选。同一 Git 项目的工作树可匹配，项目内不同子目录不会自动视为相同。 |
| 必须绑定计划 | 当前任务必须绑定当前角色的计划，按任务 ID 核对，无需额外参数。 |
| 限定聊天会话 | 多选允许投递的会话；命中其中任意一个即可满足此条件，按 ID 匹配，改名不影响。 |
| 排除聊天会话 | 多选不允许投递的会话；与限定列表重叠时排除优先，按 ID 匹配。 |
| 排除心跳类型的任务 | 无需额外参数。跳过本轮回复为完整 `<heartbeat>` 控制消息的结果，包括 `DONT_NOTIFY` 和 `NOTIFY`；本规则不发群、不播报。普通回复及正文中引用的心跳示例不受影响。 |

同一规则中的条件必须全部满足，其他规则仍独立匹配。完整 `DONT_NOTIFY` 心跳消息始终保持静默；新增排除条件还会跳过完整 `NOTIFY` 心跳结果。这里按本轮回复识别心跳，不按任务名称猜测，也不会永久排除该会话。残缺、格式无效或被引用的心跳文本仍作为普通内容处理。

## 配置任务结束后的追问

在「角色 → 自动化 → Agent Hook」选择 Agent，再展开「自动追问」。默认关闭；开启后添加规则，选择当前角色的计划状态并填写追问内容，再保存角色配置。多个规则按顺序匹配第一条，不选择状态或不填写内容的规则不会触发。

追问只作用于唯一绑定该计划的所选 Agent 任务，不会发送给其他人，也不会自动修改计划状态。可设置两次追问的最短间隔；同一轮最多追问一次，步骤、下一动作、等待说明和规则没有变化时不重复追问。冷却时间不是定时唤醒。完成、关闭、已归档计划不会追问；Manager 不可用时保留诊断，不使用旧配置补造追问。

首次使用或升级追问功能后，在 Agent 端点击「更新 Hook 到 Agent」。此后调整规则只需保存角色，无需重新安装 Hook。旧的独立本机执行守卫若会阻止结束，需要将其固定追问改为提示，避免绕过角色开关。

## Route 和角色的边界

| 内容 | 归属 |
| --- | --- |
| 消息端、端口、处理端、工作目录、pipeline | Route |
| 指向哪个角色 | Route 的 `agentRoleId` |
| 角色头像、正文、规则、计划、记忆和技能 | 角色目录 |
| 桌宠动作素材 | 角色目录中的 `desktop-pet/` |
| 是否在本机显示桌宠、大小、位置和窗口行为 | 当前电脑的桌面设置 |
| 规则服务哪条 Route | 规则中的 `configName` |

一个角色可以服务多条 Route。修改角色正文或规则会影响所有绑定到它、且命中对应 `configName` 的 Route。

## 配置角色

打开“角色配置”，在顶部菜单选择电脑和角色，再使用分区标签编辑资料：

- **基础资料**：角色绑定、头像和 `persona.md` 摘要。
- **消息适配器**：选择消息路由，配置消息端和处理 Agent。
- **表达与语音**：语言风格校验、角色 TTS 配置和语音唤醒词。
- **虚拟形象**：当前角色的桌宠动作素材，以及这台电脑是否显示桌宠。
- **身份关系**：已识别身份、未识别账号和声纹归类。
- **消息上下文**：各消息端的最近消息额度。
- **自动化**：收到消息时、定时任务和可用模板变量。
- **消息记录（左侧导航）**：汇总当前角色各任务通过 Hook 捕获的最终回复，以及线程接口的 Agent 互投消息，按接收时间从新到旧显示，可加载更早的回复、查看来源任务名称并点击定位到 Codex 对应任务，或手动刷新；新回复到达时增量插入列表顶部，保留已加载记录、展开状态和阅读位置。

没有选择角色时，“表达与语音”“虚拟形象”“身份关系”和“消息记录”不可用；基础资料与默认消息规则仍可查看和配置。

消息记录从此功能启用后收到的 Hook 最终回复开始积累，不补录安装前的历史。在 Agent 端安装 Hook，并将任务绑定到角色或该角色的 Route/计划后即可记录；没有明确角色归属的任务不会被收进任何角色。记录保留 Hook 提供的完整正文，并按 Markdown 预览显示标题、加粗、列表、代码块和表格。网页链接可打开；本地路径链接仅显示文字，正文中的 HTML 不执行。重复回调只显示一次，同一轮后续产生的不同回复仍会保留。“计划任务会话完成通知”开关只控制通知，不影响已收到的最终回复记录。

消息记录同时显示来源和目标任务名称。远端任务另标注“远端节点”和电脑名称（名称不可用时显示节点 ID），不会生成指向本机 Codex 的错误链接。旧记录按原投递 ID 补充名称与节点信息；节点离线时保留记录中的名称，无法确认名称时显示任务 ID 和“任务名称暂不可用”。展开 ID 可核对完整任务与节点标识。

在计划反馈中点击“提交并投递”，实际发给绑定任务或计划秘书的用户内容也会出现在消息记录中：左侧显示“来自用户”和计划名称，右侧显示目标任务，本机 Codex 任务可点击定位。正文保留提交的回答和附件名称；仅点击“提交”保存的内容不显示。未确认送达的消息会标明记录时的状态，重复投递同一反馈不会重复新增。

选择角色后，可以在同一张配置卡中设置或更换头像。支持 PNG、JPEG、WebP、GIF，单文件上限 5 MB。头像会跟随角色显示在选择器、Route 总览、语音角色选择和本地角色面板；没有头像时显示角色 ID 首字。头像属于角色目录，不需要为每条 Route 重复上传。

如果需要编辑完整正文，点击“打开角色配置”。运行语义文件不应机械翻译；改变语言、措辞和约束可能改变 Agent 行为。

## 配置虚拟形象

打开“虚拟形象”，为当前角色选择或导入 GIF、PNG、ZIP 动作素材，再打开“在本机启用”。没有选定可运行素材时，开关保持不可用，也不会显示空窗口。每个启用的角色各有一个桌宠；启用几个角色就显示几个，关闭某个角色只会移除它自己的桌宠。窗口名称使用角色名称。

动作素材保存在当前角色的 `desktop-pet/packs/`；同步功能退役不删除这些素材。大小、位置、透明度、置顶、鼠标点透、锁定、全屏隐藏、结果气泡和动画帧率属于这台电脑的显示偏好，不属于角色数据。

选择动作包后，页面列出动作总数、动画条目数和静态图片数，并按待机与休眠、任务与连接反馈、鼠标交互、空闲随机动作及其他动作分组。每项显示触发用途、素材格式、循环方式；PNG 序列还显示帧数与帧率。统计按可用动作条目计算，单帧 PNG 单独计为静态图片，GIF 不显示未经解析的帧数。

点击动作旁的“预览”，再点击“播放预览”，可以在本页查看、重播或停止素材。PNG 序列按动作包中的帧率和循环设置播放；GIF 按文件自身的设置预览。预览不会触发桌宠动作或修改绑定，切换动作包或角色后关闭。未配置自动触发的动作列为手动播放。

## 让角色互相联系

开启相关 Route 后，Agent 可以查询当前有哪些角色可以接收消息，再向另一个角色单向投递。你不需要把对方复制成自己的规则，也不需要新增一种网络消息端。RabiRoute 会校验消息确实来自当前 Route 绑定的角色，并在目标处理端接收后才显示发送成功。

目标角色的普通回复不会自动回到来源角色。需要答复时，它必须明确再发一条跨角色消息；系统会保留同一段联系的会话关联，并限制连续互投次数。网络超时后，Agent 会先按原投递编号查询结果，不能换新编号盲目重发，因此不会因为一次响应丢失就重复创建目标任务。

界面和用户文档统一称“角色”。`roleId`、`/api/roles/*` 和 `data/roles/` 是为兼容现有配置保留的内部名称，不要求迁移目录。

## 在其他电脑访问角色

角色数据同步已退役，这是删除功能，不是默认关闭的开关。旧“多电脑角色同步”、Changed Files、“拉取并同步”和冲突解决工作台不再作为操作入口；后台也不再自动合并角色文件。

需要使用其他电脑上的角色、Agent 或数据时，进入 [RabiLink](interface-and-status.md#rabilink-主页远端智能体与配置)，在目标电脑上访问，不建立一份同步副本。远端访问仍受目标端权限和连接状态限制，不等于允许任意写入。

已有的角色、计划、记忆、聊天、桌宠素材、历史同步归档和冲突证据全部保留，不需要为退役操作删除或搬迁数据。旧版本说明见[同步退役与数据保留](../persona-data-sync.md)。本页说明源码边界，不代表安装包已更新或远端链路已完成实机验收。

## 认识联系人和整理不同账号

选择角色后，“身份定位”分成两个卡片：

- **已识别身份**按人整理。一个人的名字、QQ、微信、声纹和其它已经确认的账号放在同一张人物卡中。点击整张人物卡，会打开统一的身份详情；基本信息、消息端账号、说话习惯和关系都在这里查看和编辑，不再通过三点菜单分别进入不同弹窗。
- **未识别身份**按 QQ、微信、声纹等消息端整理。账号还不知道对应谁、候选尚未指向已识别人物或证据存在冲突时，都会留在这里，不按同名昵称自动合并。

身份详情中的“关系”统一记录这个人与其他人、组织或项目的关系，不再分成长期关系和短期关系。当前消息里“谁提出了方案、谁正在回复谁”等临时角色由系统自动生成的情景记录表示，不需要手工建立另一类关系。基本信息和说话习惯一起保存；账号和关系分别在各自区域保存，因此一次失败不会让页面误报为全部写入成功。

当消息端能够提供不会随昵称变化的账号标识，而且消息命中当前角色的消息规则时，陌生账号会自动出现为“待认识”候选。这一步只说明“以后可以继续积累这个账号的线索”，不说明系统已经知道对方是谁。确认后，账号才会进入对应的人物卡。

一个人自报姓名、别人转述、临时昵称，以及词汇、句式或回复节奏长期相似，都可以帮助核对候选，但不能单独确认身份。如果身份说法只出现在转发、引用或附件文字里，或者消息端无法提供稳定账号标识，系统会继续显示未识别，不会自动关联到现有人物。

同一个账号可能由多人使用。已知使用者范围时，应把账号同时关联到这些人的身份卡并标记“共用”；这只说明谁可能使用该账号，不说明当前这一条是谁发的。系统需要结合明确自称、回复链、正在延续的事情和说话习惯一致性判断本条消息，并保留置信度；不要因为其中一人最近说得更多，就把整个账号永久归给他。纠正身份时应保留真实账号，把由昵称误建的人物关联标记为不再使用，这样历史记录仍然可追溯。

## 在身份定位中归类语音账号

选择角色后，“身份定位”会把 QQ、企业微信等文字账号和“语音消息端账号”放在同一区域。每个“处理主机 + 声纹 ID”相当于一条语音账号；同一段多人录音可以同时关联多个账号。语音区域会显示最近 24 小时的归类覆盖率、我的发言、其他人、未判断/冲突分段，以及当前角色已经保存的语音账号归类。这里的“这是我”只代表当前角色对该处理主机声纹的明确解释；RabiSpeech 和 RabiRoute 主机不会替角色判断谁是谁，也不会默认把任何声纹设为用户。

对未解决声纹可以选择：

- **这是我**：把当前 `sourceHostId + voiceprintId` 关系记为当前角色认定的用户。
- **其他人**：明确记为非用户。
- **清除判断**：保留语音账号归类事件，但取消 `isUser` 结论，重新回到未判断状态。

页面只请求统计、声纹缩写、时长、最后出现时间和关系，不请求或显示转写正文。新录音和本机关系修正通过事件触发一次刷新；事件流断线重连后会补查一次，不会固定间隔轮询覆盖率。当前版本继续使用角色自己的 `voice/voice-identities.jsonl` 保存既有语音归类数据，并在“身份关系”页面中统一呈现；后续统一身份数据时应提供兼容迁移，不能让旧归类消失。历史遗留的语音归类冲突会明确显示，后续再次确认可收敛冲突分支。

第一次使用时，如果不透明声纹 ID 无法辨认，点击“标记下一段”，然后用准备归类的电脑、手机或眼镜，在尽量安静的环境里只让本人连续说一句。下一次录音事件完成后，本次新出现的未归类声纹会移到列表前面并标记“本次出现”。这个流程只是帮助缩小候选：它不会启动第二套录音、不会自动认人，也不会因为只出现一个候选就直接设为用户；如果现场同时有人说话，应只确认能够确定属于本人的声纹，或者重新捕获。

## 角色自动化怎样组成

每条规则只回答两个问题：什么时候触发，以及触发后做什么。

触发方式有两种：

- **收到消息时**：选择一个或多个消息来源，还可以按消息内容、群和说话人继续筛选。
- **定时任务**：选择固定间隔、每天某时或一次性日期时间。

动作也有两种：

- **通知 Agent**：把当前消息或定时任务交给这个角色处理；可填写额外判断要求，不需要重新拼完整消息。
- **运行脚本**：运行当前角色 `scripts/` 目录内的 `.cmd`、`.bat` 或 `.py` 文件。

因此，同一套规则可以表达“私聊到达后通知 Agent”“每天九点通知 Agent”“收到指定消息后运行脚本”和“每隔十分钟运行脚本”。以后新增触发来源或动作时，也不需要再增加一套独立的规则页面。

界面把规则分为“收到消息时”和“定时任务”两个标签。消息规则再按聊天消息、语音与设备、手动与系统消息、其他来源分组。编辑时先选触发方式，再选动作；页面只显示当前选择需要的参数，减少一屏同时出现无关字段。

## 常用路由类型

| 类型 | 什么时候使用 |
| --- | --- |
| `private` | QQ 私聊 |
| `direct_at` | 群里直接 @ 当前账号 |
| `direct_reply` | 直接回复当前账号或角色参与的消息 |
| `indirect_reply` | 更宽的回复链观察，容易产生噪声 |
| `group_message` | 普通群消息，建议搭配窄正则 |
| `heartbeat` | 定时计划和手动验证 |
| `manual_trigger` | 只在用户或 API 明确触发时运行 |
| `role_panel_message` | 内置角色消息；本地角色面板与跨角色投递共用 |
| `plan_feedback` | 独立计划审批系统事件；不带最近消息 |
| `voice_transcript` | RabiRoute/RabiSpeech、本地桥接或 FenneNote 兼容转写 |
| `wecom_message` | 企业微信群消息 |
| `rabilink` | RabiLink 事件 |

界面会按当前 Route 已添加的消息端组织可选类型。消息规则没有选择任何来源时会匹配全部收到的消息，页面会明确提示。每条规则都可以单独启停和编辑；先从私聊、直接回复或窄关键词开始，再逐步增加更宽的群消息规则。

## 正则应该多窄

普通群消息不要使用空正则全量转发。先从能解释业务意图的关键词开始，例如：

```text
需求|报错|构建失败|提醒|请记录
```

正则只决定是否命中，不决定最终是否回复。角色模板仍应要求处理端先看上下文，区分新事实、任务、风险、普通确认和礼貌回应。

## 定时任务

定时触发支持：

- 每隔一段时间。
- 每天指定时间。
- 某一天指定时间。

定时任务需要当前 Route 启用“定时任务”入口。通知 Agent 时，事件只携带当前任务、角色/计划/记忆索引和必要路径，不自动输入聊天历史。脚本动作直接进入本机脚本执行器，不经过 Agent。

## 运行脚本前的限制

配置好的本机脚本可以直接运行，无额外 Route 权限开关；脚本只能来自所属角色的 `scripts/` 目录，远端角色脚本在所属电脑执行。

- 脚本必须位于当前角色的 `scripts/` 目录，符号链接或 `..` 不能越过该目录。
- 只支持 `.cmd`、`.bat` 和 `.py`，不接受任意命令文本。
- Manager 的 token、密码和消息正文不会作为环境变量传给脚本。
- 同一 Route 的同一规则不会重叠执行；超时后会停止对应进程树。
- 脚本执行与 Agent 投递分别记结果，任何一方成功都不会代替另一方成功。

脚本路径在界面中填写相对于角色 `scripts/` 目录的位置，例如 `daily-check.py` 或 `tools/check.cmd`。参数每行一个。先在测试角色和无破坏性的脚本上验证，再用于会修改文件或调用外部系统的任务。

## 模板写什么

模板适合补充“如何判断”，不需要重复拼完整消息。RabiRoute 已经注入事件、角色路径、日志路径、知识索引和回复上下文；普通消息端还会按额度注入最近消息，Heartbeat 不会。

工作型模板可以简短写成：

```text
先判断消息是信息、问题、任务、风险还是决策。
只有出现新增事实、阻塞或待办变化时才推进动作。
需要向外部消息端发送时，使用注入的 RabiRoute 发送模板，确认渠道和目标参数后再提交。
```

绑定角色的 AgentPacket 还会自动附加“本轮工作契约”：区分事实、推断、未知和待用户完成的最小一步；只推进一个可验证动作；没有新价值时保持安静；外部动作继续遵守 Action Gate。角色模板只补充当前入口的判断重点，不要重复这段公共收口。

RabiLink 的固定线程主动审阅另有一层连续反思模板：它会先读取当前账本及其历史索引，再按需恢复计划、记忆和最近工具结果。角色目录若提供 `prompts/rabilink-proactive-review.md`，优先使用它；否则回退到 `prompts/proactive-review.md`。反思入口可以在用户明确允许、且角色目录提供有界工具时，每轮短时读取一帧屏幕、一帧摄像头和已经运行的本机语音摘要；原始材料只在本轮查看，随后删除并核对清理，不写入记忆、日记或外发消息。没有新记录不等于用户不在场，取证失败也只能降低证据置信度，不能冒充“没有变化”。

不要只靠自然语言模板授予外部发送权限。实际发送仍受消息端发送策略控制，来源聊天记录也不会自动成为目标。

## 保存与验证

完成规则编辑后关闭对话框，再点击顶栏“保存配置”。下一条消息或下一次定时触发时生效。旧版消息模板规则会自动显示在新界面中；保存后，角色配置会改写为新的 `automationRules` 结构。

当前 WebGUI 没有无副作用的 RouteDecision / AgentPacket 预览。验证规则请使用日志诊断的手动触发，并明确知道它会进入真实投递链。
