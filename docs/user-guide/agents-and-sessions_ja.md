# エージェント、プロジェクト、およびタスク

メッセージアダプタは、イベントがどこに入るかを決定する。エージェント アダプタは、どのハンドラがそれを受信するかを決定します。ハンドラーは、回答、コード、ツール、およびプライベート タスクの状態を所有します。

## 現在のハンドラー

|ハンドラー |ステータス |実際の境界 |
| --- | --- | --- |
|Codex |検証済み |デスクトップ IPC を介して、選択した Codex/ChatGPT デスクトップ タスクに配信します。
|コパイロット CLI |実験的 |独自のセッション名とワークスペースを使用してローカル CLI を呼び出します。
|アストラボット |実験的 | Dashboard/ChatUI プロジェクトとセッションをバインドします。環境の受け入れが必要 |
|マービス |手動ハンドオフ |プロンプトを作成してコピーし、アプリを開きます。信頼できる自動送信がない |

セレクタの成熟度は、現在のスキャンから得られる。インストールされたことは認証されたことを意味するものではなく、認証されたことは正しいタスクにバインドされたことを意味するものでもありません。

## プライマリ エージェントを選択してください

ルートはローカル Codex、DSH、および複数のリモート Codex ターゲットを一緒に保持できますが、一致したメッセージは 1 つのプライマリ エージェントにのみ送信されます。ハンドラー リストの上にある特定のローカルまたはリモート エージェントを選択します。他のプロジェクト、タスク、サービスの設定は、デフォルトの配信を受信せずに保存されたままになります。リモート ターゲットを追加しても、同じプロバイダーのローカル カードが置き換えられることも、プライマリ カードが変更されることもありません。

保存されたプライマリのない古いルートは、元の最初のエントリを保持します。既存のリモート プライマリは同じターゲットを保持します。現在のプライマリを削除するには、ローカルまたは別のエージェントに自動的に切り替えるのではなく、明示的に新しい選択を行う必要があります。プライマリがなければエージェント配信は行われません。

プライマリエージェントの配信が失敗した場合、RabiRouteは失敗を記録し、別のエージェントに切り替えません。これにより、2 つのハンドラーが同じ外部アクションに応答したり実行したりすることが防止されます。

プライマリは、アプリケーションに対してグローバルに選択されるのではなく、ルートごとに選択されます。メッセージがエージェントに到達した理由を調査するときは、まずルート ID を確認し、次にそのルートのプライマリを確認します。独立したメッセージ処理エージェントが有効になっている場合、メッセージは最初にプライマリのプロバイダーの処理セッションに到達する可能性があります。これにより、プライマリが変更されたり、別のプロバイダーへの配信が許可されたりすることはありません。

## Codexの 3 つの要件

Codexパスには、次の 3 つすべてが必要です。

1. Codex/ChatGPT デスクトップが実行中です。
2. ルートには、正しいプロジェクト ワークスペースが保存されます。
3. ルートは正確なタスク ID をバインドし、次のターンにプロジェクト ワークスペースを使用します。

RabiRouteは、隠れたCLI、共有ポート、またはフォールバックランタイムを介して実際のメッセージを実行しない。デスクトップは、メッセージが表示される表示タスクを所有します。

## プロジェクトとタスクをスキャンする

「ペルソナ設定 → メッセージアダプター」を開き、展開します **エージェントハンドラー**、Codexを選択し、スキャンまたは再スキャンを実行します。

スキャンにより、利用可能なワークスペースおよびアーカイブされていないタスクがリストされる。セレクターは、認識のために内部 ID を公開する代わりに、タスク名と最後のアクティビティ時間を表示します。


## ワークスペースを選択してください

ワークスペースは次の目的で使用されます。

- 保存されたタスクが期待されるプロジェクトに属していることを検証する。
- 同じ名前のタスクを区別する。
- 新しいタスクが作成される場所を選択する。
- 別のリポジトリのタスクへの配信を防止する。

候補が表示されない場合は絶対パスを入力し、保存します。例、問題、スクリーンショットでプライベート ユーザー名やマシン パスを公開しないでください。

## 既存のタスクを選択してください

セレクタから既存の項目を優先する。 RabiRoute は完全なタスク ID を保存します。タスクの保存されたデフォルト cwd とは別に、次のターンのワークスペースを選択することもできます。

ID が有効なままで、要求されたワークスペースが許可されている間は、これらの変更によってタスクは作成されません。

- デスクトップのタイトル変更。
- 一時的に古くなったローカルインデックスタイトル。
- 完了したタスクの目標。
- 新しいタイトルを観察する再スキャン。

固定ターゲットがアーカイブされる場合、次の実際の配信では新しいタスクが作成され、置換バインディングが自動的に永続化されます。メッセージはアーカイブされた履歴には記録されず、RabiRoute は別の同じ名前のタスクを再利用しません。ターゲットが削除、移動されているか、別のアカウントに属している場合は、有効なタスクを選択して再度保存します。

## タスクを作成する

セレクタに新しい名前を入力し、保存します。プロジェクトに固定されたアプリサーバーは、空のタスクを作成して名前を付けるだけです。実際のプロンプトは依然としてデスクトップ所有者に送られます。

いくつかのタスクが正確な名前およびワークスペースを共有する場合、RabiRouteは、そのタスクを固有の最新アクティビティ時間に自動的にバインドする。最大時間が制限されているか使用できない場合は、セレクターのアクティビティ時間とワークスペースを使用して選択するか、最初にデスクトップで名前を整理します。このあいまいなケースでは、別のタスクが作成されることはありません。

## 自動ペルソナ初期化

もし **タスクを自動的に初期化します** が利用可能である場合、まず安定したバインディングを保存し、次に正式なAgentPacketパスを介して同じデスクトップタスクにペルソナマテリアルを送信します。

初期化が失敗しても 2 番目のタスクは作成されません。再試行する前に、バインドまたはデスクトップの状態を修復してください。

## モデル、ツール、承認

ターゲットデスクトップタスクは、そのモデル、ツール、サンドボックス、ファイルアクセス、およびネットワーク承認を所有する。互換性 `agentModel` フィールドはそれらをオーバーライドしません。

デスクトップコマンドの承認は、エージェントの実行のみを許可する。 QQ、ドキュメント、デバイス、または外部 API への書き込みは許可されません。 RabiRoute 送信ボックス ポリシーは依然としてこれらのアクションをゲートします。

## ハンドラー配信がありません

順番にチェックしてください:

1. あります `agent-packets.jsonl` 配送は含まれますか?そうでない場合は、まずルールを調べてください。
2. ログ診断は、Codex Desktop IPCを報告しますか?
3. デスクトップは開いており、タスクに入ることができますか?
4. 要求されたワークスペースは、現在処理しようとしているプロジェクトですか?
5. 最後のエラーに言及していますか? `no-client-found` それともタスクがありませんか?

参照 [操作、ログ、トラブルシューティング](operations-and-troubleshooting_ja.md) フルパス。
