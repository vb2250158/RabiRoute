# ルートとメッセージアダプタ

ルートは、独立して制御されるメッセージフロー構成である。これは、メッセージ ソース、ハンドラー、ワークスペース、ペルソナ バインディング、および出力インテントを組み合わせます。

「ペルソナ設定 → メッセージアダプター」でルートを管理します。基本情報の次にある二番目のタブです。ペルソナを選択してから、そのメッセージルートを選択または追加します。新規ルートは現在のペルソナと取得元 PC を自動的に参照します。サイドバーには独立したルート設定項目を置きません。ペルソナのルールはペルソナ設定、接続先と処理 Agent は各ルート設定が所有し、ペルソナ ID と取得元 PC で関連付けます。旧設定は[アップグレードスクリプト](../persona-message-config-upgrade_en.md)で確認してから移行してください。

```text
Message adapter -> Route rules -> persona and context -> Agent handler -> Outbox / reply
```

## いつ別のルートを作成するか

別個のルートは、次の場合に役立ちます。

- メッセージは異なるプラットフォームまたはアカウントから送信される。
- 作業には、異なるプロジェクトまたはデスクトップタスクを入力する必要があります。
- 異なるペルソナまたはルールセットが適用される。
- 出力ポリシー、ペイロードタイプ、またはファイルルートが異なる。
- 独立したライフサイクルと診断が必要です。

いくつかのルートは、1つのペルソナを再利用することができる。メッセージ ソースが変更されたという理由だけでペルソナを複製しないでください。

クロスペルソナ配信は、別の種類のルートまたはメッセージアダプタを必要としない。 Manager のペルソナ ディレクトリからターゲットを選択し、ターゲットの既存の組み込みペルソナ メッセージ パスを再利用します。ソースルートとターゲットルートの両方を有効にする必要があります。

## 用途に合わせて入力を選ぶ

通信とスマートデバイスは同じ階層の分類です。スケジュール、ロールパネル、Webhook はデスクトップや自動化に使います。

| 分類 | メッセージ入力 | 状態 | 用途と依存関係 |
| --- | --- | --- | --- |
| 通信 | QQ（NapCat / OneBot） | 検証済み | グループと個人メッセージ。NapCat、QQNT、OneBot の設定が必要です。 |
| 通信 | 個人微信（Weixin） | 実験的な試作 | iLink による文字の送受信。受信メディアは記録のみで、長期接続と実アカウントの安定性は未検証です。 |
| 通信 | WeCom | 実験的 | Bot のグループ送受信。実際の Bot ID / Secret が必要です。 |
| 通信 | Feishu | ローカル実装は検証済み、実認証情報での連携待ち | アプリのイベント受信と文字返信。認証情報、公開 HTTPS、イベント購読が必要です。 |
| スマートデバイス | Xiaomi Home | 実験的 | Home Assistant の状態、操作、カメライベント録画。入力の Setup 画面で接続を設定します。 |
| スマートデバイス | RabiLink のスマートフォン / 眼鏡 | 実験的 | 音声、返信、能動的な配信。Relay の設定と実機検証が必要です。 |
| スマートデバイス | スマートウォッチ / バンド | 実験的、一部 Xiaomi 実機経路は検証済み | 心拍、睡眠、健康イベント。利用できる指標は収集元によって異なります。 |
| デスクトップと自動化 | スケジュール起動 | 検証済み | 初回配信、定期タスク、巡回確認。外部アカウントは不要です。 |
| デスクトップと自動化 | ロールパネル | 検証済み | トレイ、ローカルメッセージ、認証済みロール間配信。ネットワーク待受は不要です。 |
| デスクトップと自動化 | 汎用 Webhook | 実験的 | 専用アダプターのないシステムから POST を受信します。到達可能なコールバックが必要です。 |

アカウント、ネットワーク、実機は各環境で検証してください。詳細は [現在の機能（英語）](../current-capabilities_en.md) を参照してください。FenneNote と旧 XiaoAI メッセージ入力は廃止されています。古い入力を削除し、家庭用デバイスには必要に応じて Xiaomi Home を使います。遠端 Agent は [遠端コンピューターの接続（英語）](../lan-rabi-agent-bootstrap_en.md) で実行先として設定し、メッセージ入力には追加しません。

## メッセージアダプターを追加します

開く **メッセージアダプター** の下にエントリを追加します **メッセージソース**。このカタログには、ローカル デスクトップ、リアルタイム チャット、リモート デバイス、内部トリガー、音声、外部インターフェイスがグループ化されています。

各アダプタは、成熟度、接続状態、依存関係チェック、および独自の設定を示します。別のソースを追加する前に、1 つのソースを安定させてください。

ホーム アシスタントのアドレス、イベント モニター、デバイス制御ゲート、カメラ オプションを内部で設定します。 **Xiaomi ホーム** メッセージエンドポイント。ホスト全体では再び表示されません **設定** ページ。許可された LAN WebGUI は、この構成を維持できます。グローバル エージェント アドミッションが有効になり、ノードとエージェントの認証が成功すると、リモート エージェントもローカル呼び出し元と同じパブリック デプロイメント、デバイス、および録音 API を使用できるようになります。デバイス制御スイッチ、バージョンの前提条件、および個別の記録読み取りトークンは引き続き適用されます。認証されていないアクセスは許可されません。

現在のルートの完全な配信パスを検査するには、次を選択します。 **チャンネルチェック** ページの上部にあります。このダイアログでは 3 つの列が使用されます。 **メッセージ入力 → マネージャー → エージェント ハンドラー**。左側には追加されたメッセージ入力のリストが表示され、中央には現在のルートのマネージャーの状態が表示され、右側にはプライマリまたはセカンダリのペルソナを持つ設定済みのエージェントがリストされます。メッセージ ノードを選択するか、 **ビュー設定** 設定に戻る。 **もう一度確認してください** は、メッセージ入力とエージェントのステータスの両方を更新します。

各エージェントノードが提供するのは、 **配送テスト**。ルートを保存し、ボタンを選択して、UUID テスト ID を含む実際のメッセージをそのエージェントの設定済みセッションに送信します。 UI は、アダプターが受信を確認した後にのみ成功を報告します。 Codex はさらに、ID がターゲットのデスクトップ タスクに表示されることを検証します。テストはエージェントの回答を待たず、QQ、WeChat、または別の外部プラットフォームに送信しません。 Marvis は現在、手動コピー/オープン ハンドオフのみをサポートしているため、このテストを実行できません。

ドキュメントサンプルのRouteはスクリーンショットのために一時停止されたが、NapCatおよびスケジュールされたトリガーはその入力リストに表示されたままである。ルートを有効にする前に、入力とプライマリ エージェントを確認してください。

## 入力と出力は別個のゲートである

アダプタポリシーは以下を区別します。

- **メッセージを受信する**:このソースがRabiRouteイベントを作成できるかどうか。
- **返信/送信を許可します**:エージェントがRabiRouteのアウトボックスを介して送信できるかどうか。
- **サポートされる出力**:テキスト、画像、音声、ファイル、またはより小さなセット。
- **許可されたファイルルート**: ファイルのアップロードが許可されたローカル ディレクトリ。

入力を無効にしても履歴は削除されません。出力を無効にしても、ハンドラーがタスクで結果を生成できなくなるわけではありません。プラットフォームの送信をブロックします。

## 最小限の QQ / NapCat セットアップ

NapCat は 2 つの接続を使用します。

- WebSocket クライアントは、通常、QQ イベントを RabiRoute に送信します。 `ws://127.0.0.1:8789`.
- OneBot HTTP Server は、通常、ヘルスと応答をサポートします。 `http://127.0.0.1:3000`.

RouteのNapCatパネルで、インスタンス、RabiRoute WSポート、HTTPアドレス、およびWebUIアドレスを確認する。スキャンは読み取り専用です。開始、ログイン、修復のアクションには明示的なクリックが必要です。エンドポイント プローブは、1 つのスキャン期限内に同時に開始されます。タイムアウトしたプローブは、他のエンドポイントからの部分的な結果を保持し、オフラインとは解釈されません。

QQ/NapCatおよび個人のWeixinは、完全に独立したログイン状態を有する。 QQ は、ライブ OneBot 接続とヘルス結果からのみ使用可能とマークされます。到達可能な NapCat WebUI は、診断/構成画面が到達可能であることのみを証明します。 QQ がログインしていること、または送受信できることを証明するものではありません。ログアウトされた個人 Weixin アダプターはそのアダプターにのみ影響し、オンライン QQ やすべてのメッセージ エンドポイントがオフライン状態になることはありません。

RabiRouteは、QQパスワード、CAPTCHA、デバイス確認、またはリスク制御を保存したりバイパスしたりしない。 NapCat/QQNT で最初のログインと例外的な検証を完了します。

参照 [無人 NapCat とログインの安定性](../napcat-unattended_en.md) 。

## スケジュールされたトリガー

スケジュールされたトリガーを有効にした後、 `heartbeat` 個人ルールのスケジュール。スケジュールでは、間隔、毎日の時刻、または 1 回限りの日時を使用できます。

Codex Message Agent モードがオフの間、 **タスクがビジー状態の間はハートビートをスキップします** 固定Codexタスクがアクティブな場合、ハートビートにのみ影響します。メッセージ エージェント モードがオンの場合、ハートビートはすぐに独立したメッセージ エージェントに送られ、ビジー スキップ オプションは非表示になります。 QQ、プライベート、およびその他のリアルタイム メッセージは、この設定では破棄されません。

## Webhook と名前付きアダプター

名前付きアダプタが存在する場合は、それを優先します。通常、より正確なステータス、ログ、テンプレート値、および応答セマンティクスが保存されます。

汎用Webhookは、専用の統合を持たないPOSTソース用である。パブリック構成では、ローカルホスト、プレースホルダー ドメイン、およびサニタイズされたトークンを使用する必要があります。

ネイティブ Lingzhu エージェント、AIUI、およびネイティブ アプリの選択については、 [RabiLink メガネの 3 ルート比較](../rabilink-glasses-route-comparison_en.md).

## 保存して適用

アダプタを追加、削除、有効化、または編集した後、 **設定の保存**。マネージャーはルートを同期またはリロードする場合があります。

次に、実行時状態を検証します。 **ログ診断**。外部システムには、NapCat WebSocket、WeCom 認証、Relay の存在などのプラットフォーム側のチェックも必要です。

## 続行

- ハンドラとタスクを選択します。 [エージェント、プロジェクト、およびタスク](agents-and-sessions_ja.md).
- どのメッセージが一致するかを決定する: [ペルソナとメッセージのルール](personas-and-rules_ja.md).
- 入力は機能するが、配信は失敗する。 [操作、ログ、トラブルシューティング](operations-and-troubleshooting_ja.md).
