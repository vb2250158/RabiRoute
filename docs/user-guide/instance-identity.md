# 区分两台电脑与重置实例 ID

[English](instance-identity_en.md) | 简体中文

状态：0.3.21 新增实现。安装版 Windows Host 提供重置；源码 Manager 没有此按钮的执行能力。

两台电脑应有独立的实例 ID 和连接密钥。显示名称、本机连接标识和实例 ID 是不同字段；只改名称不能修复从另一台电脑复制过来的身份。远端电脑与本机共用 ID 时，远端人格来源可能被当作本机过滤。

## 在本机页面操作

1. 保存需要保留的配置修改；重置使用已保存的数据，不替你保存页面草稿。
2. 打开 **RabiLink → 配置**，在“实例标识”旁点击 **重置实例 ID**。
3. 阅读确认窗口，再确认重置。应用会备份旧身份，停止当前运行，生成新的实例 ID 和连接密钥，然后重新启动。
4. 等待页面显示完成并读到新的实例 ID。如果连接地址变化，从托盘重新打开 RabiRoute；不要因为页面短暂断开而重复点击。
5. 到 RabiLink 主页核对两台电脑，刷新人格来源。来源 PC 仍需在线并支持远端人格功能。

重置保留已保存的名称、服务器地址、应用令牌、连接标识、路由、人格和消息记录。它不清空数据、不重置远端 Agent 节点身份，也不改写旧消息中的来源事实。备份位于运行数据目录 `data/rabilink/identity-resets/<操作 ID>/`，含私有配置与密钥，不能上传或提交。

旧公钥的固定信任不会自动替换。其他设备如提示身份改变，需要核对并重新建立该连接；应用不会通过重置扩大既有服务权限。若两台电脑还使用相同的“本机连接标识”，分别设置不同值并保存，实例 ID 重置本身保留这个值。

## 避免再次复制身份

升级后，应用为身份保存本机归属标记。复制包含该标记的配置或整个数据目录到另一台电脑时，启动会拒绝使用外机身份；不要删除标记来绕过检查。搬迁人格和记录应保留新电脑自身的配置和连接密钥。

旧版本配置没有归属标记，首次升级会保留并绑定现有身份，不能判断它过去是否被复制。因此，已经发生身份重复的两台电脑需要在其中一台显式重置。检查使用操作系统的机器身份；完整克隆操作系统且保留相同机器身份仍需人工重置，这不是硬件认证。

## 重置未完成

页面只把“已排队”当作请求受理。在本次操作期间，它最多查询状态 45 秒，并在确认完成后重新读取实例 ID；连接丢失或超时不等于重置失败，也不自动重发请求。

Host 记录操作状态和子进程用途、PID、启动来源与日志。重置中断后保留事务记录，Host 再次启动时先恢复该事务，再启动 Manager；不能核对当前文件或恢复失败时停止启动。故障状态下的正式 Host 恢复入口见[Windows 启动与打包](../windows-launcher-and-packaging.md#实例身份重置)。
