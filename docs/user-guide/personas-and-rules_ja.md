# ペルソナとメッセージルール

ルートは、メッセージがどのように入ってくるか、およびどのハンドラがメッセージを受信するかを決定する。ペルソナは、アイデンティティ、背景、意思決定の指針を提供します。これらは個別に保存され、個別に再利用できます。

## メッセージルールとスケジュールされたタスクを追加する

[ペルソナ] → [オートメーション] → [メッセージ ルール] で、左側のメッセージ タイプを選択して、そのルールと数を表示します。 [メッセージ ルールの追加] を選択すると、そのタイプが選択された状態でエディターが直接開きます。エディタでは、左側でタイプを切り替えることもできます。 [間隔、毎日、または 1 回限りのスケジュールされたタスク] を選択し、[エージェントに通知] または [スクリプトの実行] を選択します。編集を終了し、ペルソナを保存して変更を適用します。幅の狭い画面では、タイプ バーが上部に移動し、水平にスクロールします。

リストには、無効なルールを含む既存のルールを持つタイプのみが表示されます。タイプの最後のルールを削除すると、そのタイプが非表示になり、残りのタイプが選択されます。ルールが存在しない場合でも、「メッセージの追加」ルールは引き続き利用可能です。エディターはあらゆるタイプを提供します。

## 受信エージェントを選択してください

自動化ルールで、次を選択します。 **配送対象** 下 **エージェントに通知する**。プライマリ ペルソナ、プラン セクレタリー、メッセージ処理エージェント、メモリ統合エージェント、または **カスタム**。カスタム選択には、エージェント インスタンスと既存のセッションのドロップダウンが含まれます。エージェント設定には受信者のバインディングとパラメータが保持されます。ルールは配信の選択を所有します。参照 [エージェント配信ターゲット](../automation-agent-delivery_en.md).

## フックのエージェント側を選択してください

[ペルソナ] → [自動化] → [エージェント フック] で、左側のエージェント カードを選択して、その設定を表示および編集します。幅の狭い画面では、カードは設定の上に表示されます。各カードには、エージェントの有効な項目数が表示されます。選択肢は、このペルソナにバインドされた有効なローカル ルートに追加された端から取得され、ライフサイクル フック機能によってフィルターされます。エージェント設定に欠落している末尾を追加します。ソフトウェアをインストールまたは検出するだけでは、選択肢は追加されません。

各エージェントは独立して構成され、複数のエージェントの設定を同時に有効にすることができます。カードを切り替えると、表示される設定が変更されるだけです。セッション コンテキスト、ツール コンテキストの更新、完了通知、Rabi を介したエージェント メッセージの送信は、右側にスイッチとして表示されたままになります。計画タスクのフォローアップとイベント配信は、デフォルトでは折りたたまれています。展開してパラメータを編集します。 「保存」をクリックして変更を適用します。

既存のペルソナ設定は、上書きされずにエンドのデフォルトのままになります。プロジェクトとセッションの条件は、選択された終了のみを読み取ります。失敗したプラン ステータスの読み取りでは、保存や配信を再実行せずに明示的に再試行できます。

## イベント配信の条件を設定する

ペルソナ → オートメーション → Agent Hook → イベント配信でルールを開き、「条件を追加」を選びます。条件の種類を選ぶと説明とパラメーターが表示されます。確定すると編集中の設定に反映され、キャンセルすると元の条件が残ります。適用するにはページ上部の保存を押してください。

| 条件 | 内容 |
| --- | --- |
| プロジェクトを限定 | 絶対パスを入力するか、選択した Agent から候補を取得します。同じ Git プロジェクトの worktree は一致できますが、別のサブディレクトリを自動的に同一とはみなしません。 |
| 計画との紐付けを必須にする | 現在のタスク ID が、このペルソナの計画に紐付いていることを確認します。追加のパラメーターはありません。 |
| チャットを限定 | 許可するチャットを複数選択します。ID で照合するため、名前の変更は一致判定に影響しません。 |
| チャットを除外 | 配信しないチャットを選択します。限定条件と重複する場合は除外を優先します。 |
| ハートビートのタスクを除外 | 追加のパラメーターはありません。完全な `<heartbeat>` 制御メッセージ（`DONT_NOTIFY` と `NOTIFY` を含む）を、このルールのグループ配信や音声出力から除外します。通常の返信や引用した例には影響しません。 |

同じルール内の条件はすべて満たす必要があります。他のルールは独立して判定されます。完全な `DONT_NOTIFY` は常に通知せず、追加した除外条件は完全な `NOTIFY` も対象にします。現在の返信だけを判定し、タスク名から推測したり、会話を恒久的に除外したりしません。不完全な形式、無効な形式、引用されたテキストは通常の内容として扱います。

## タスク終了時のフォローアップを設定する

ペルソナ → オートメーション → エージェント フックを開き、エージェントを選択して、タスク フォローアップの計画を展開します。これはデフォルトではオフになっています。ルールを追加し、このペルソナのカタログからステータスを選択し、フォローアップ テキストを入力して保存します。最初に一致する有効なルールが優先されます。空のステータス選択またはプロンプトはトリガーされません。

選択されたエージェント側の一意にバインドされた計画タスクのみがフォローアップを受け取ります。他の人に連絡したり、プランのステータスを変更したりすることはありません。フォローアップ間のクールダウンを設定します。各ターンは最大 1 つを受け取り、変更されていないステップ、次のアクション、待機中の詳細、ルールは再度トリガーされません。クールダウンではウェイクアップはスケジュールされません。ターミナルプランまたはアーカイブプランは除外されます。 Manager が使用できない場合は、キャッシュされた構成からフォローアップを作成せずに診断をレポートします。

この機能を初めて使用するときは、エージェント ページからフックをインストールまたは更新します。後続のルール変更では、ペルソナを保存するだけで済みます。独立してインストールされたローカル実行ガードは、ペルソナの切り替えをオーバーライドできないように、固定 Stop ブロックの代わりにアドバイザリ出力を使用する必要があります。

## ペルソナを構成する

「ペルソナ設定」を開き、独立した選択欄から既存のペルソナを選びます。ルートへの関連付けは不要です。各タブで次の内容を管理します。

- **プロフィール**: 基本情報、アバター、および `persona.md` の概要。
- **メッセージアダプター**: メッセージルート、メッセージ端、処理 Agent。
- **表情と声**:言語スタイルの検証、ペルソナTTS設定、および音声ウェイクアップキーワード。
- **仮想アバター**:現在のペルソナのデスクトップペットアニメーション資産、およびこのPCがペットを表示するかどうか。
- **アイデンティティ関係**:認識されたアイデンティティ、認識されないアカウント、および声紋の分類。
- **メッセージコンテキスト**:エンドポイントおよびルート変数ごとの最近のメッセージ制限。
- **自動化**:メッセージトリガー、スケジュールされたタスク、および利用可能なテンプレート変数。
- **チャットログ**: このペルソナのタスクからフックによってキャプチャされた最終応答と、マネージド スレッド インターフェイスを通じて送信されたエージェント間メッセージ。最新のものから順に受信されます。以前の返信をロードし、ソース タスク名を確認してクリックして Codex 内で見つけるか、手動で更新します。新しい返信は、ロードされたレコード、展開された詳細、および読み取り位置を保持したまま、先頭に挿入されます。

ペルソナがない場合は左下の「ペルソナを追加」で作成します。既存の未関連ルートは、メッセージアダプターからペルソナに関連付けられます。

歴史は、この機能が利用可能になった後に受信されたフック応答から始まる。以前の会話はインポートされません。エージェント フックをインストールし、タスクをペルソナまたはそのルート/プランにバインドします。明確なペルソナ所有者のないタスクは、どのペルソナにも記録されません。フックによって提供される完全な本文は保持され、見出し、強調、リスト、コード ブロック、表を含むマークダウン プレビューとして表示されます。 Web リンクを開くことができます。ローカルパスのリンクはテキストのままであり、埋め込まれた HTML は実行されません。再生されたコールバックは 1 回表示されますが、同じターン内のその後の別の応答は保持されます。計画タスク完了通知スイッチは通知のみを制御します。受信した最終応答の記録は無効になりません。

を選択すると **提出して納品する** 計画フィードバックでは、バインドされたタスクまたは計画秘書に送信されたユーザー コンテンツもチャット ログに表示されます。左側に表示されているのは、 **ユーザーから** とプランのタイトル。右側は宛先タスクへのリンクです。本文には、送信された回答と添付ファイルの名前が含まれます。保存のみの投稿は除外されます。未確認の配信には記録時のステータスが表示され、同じフィードバックを再試行しても重複したエントリは追加されません。

ペルソナを選択した後、同じ構成カードを使用してそのアバターを設定または置き換える。最大 5 MB の PNG、JPEG、WebP、および GIF 画像がサポートされます。アバターは、セレクター、ルート概要、音声ペルソナ選択、およびローカルペルソナパネルへのペルソナに従います。ペルソナ ID の最初の文字はフォールバックとして使用されます。画像はペルソナ ディレクトリに属しているため、ルートごとに再度アップロードする必要はありません。

使用 **オープンロール設定** 全文を編集します。ランタイムセマンティックファイルを機械的に変換しないでください。言語や表現を変更すると、エージェントの動作が変わる可能性があります。

## 仮想アバターを構成する

開く **仮想アバター**、現在のペルソナの GIF、PNG、または ZIP アニメーション パックを選択またはインポートし、オンにします **この PC で有効にする**。実行可能なパックが選択されるまでスイッチは使用できず、空のウィンドウは表示されません。有効な各ペルソナは独自のペットを取得します。複数のペルソナを有効にすると複数のペットが表示され、1 つを無効にするとそのペルソナのペットのみが削除されます。ウィンドウ名にはペルソナ名が使用されます。

アニメーション アセットは現在のペルソナの下に存在します `desktop-pet/packs/` ディレクトリは、同期が解除された後も保持されます。サイズ、位置、不透明度、常に最前面に表示、クリックスルー、ロック、全画面非表示、結果バブル、およびフレーム レートは、ペルソナデータではなく、この PC の表示設定です。

パックを選択した後、ページには、アイドルとスリープ、タスクと接続フィードバック、マウスインタラクション、ランダムアイドルアクション、およびその他のアクションによってグループ化されたアクション、アニメーションエントリ、および静止画像の総数がリストされる。各エントリは、そのトリガー、形式、ループ動作を示します。 PNG シーケンスには、フレーム数とフレーム レートも表示されます。カウントは、利用可能なアクション エントリを指します。単一フレームの PNG エントリは静止画像としてカウントされます。 GIF フレーム数は推測されません。

クリック **プレビュー** アクションの横に、 **プレビューを再生** このページ上のアセットを表示、再生、または停止します。 PNG シーケンスはパックのフレーム レートとループ設定に従います。 GIF プレビューは、ファイル独自の設定に従います。プレビューはデスクトップ ペットをトリガーしたり、そのバインディングを変更したりすることはなく、パックやペルソナを切り替えるときにプレビューを閉じます。自動トリガーのないアクションは、手動で再生されるものとしてリストされます。

## ペルソナを相互に連絡させます

関連するルートが有効になった後、エージェントは、どのペルソナがメッセージを受信できるかを発見し、別のペルソナに一方向メッセージを明示的に送信できる。ターゲットをローカル ルールにコピーしたり、別のネットワーク アダプターを追加したりする必要はありません。 RabiRoute は、メッセージが現在のルートにバインドされているペルソナから送信されたものであることを検証し、ターゲット ハンドラーがメッセージを受け入れた後にのみ成功を報告します。

ターゲットペルソナの通常の応答は、ソースに自動的に返されない。応答するには、別のクロスペルソナ メッセージを明示的に送信する必要があります。 RabiRoute はその交換の相関関係を維持し、繰り返される往復ホップを制限します。タイムアウト後、エージェントは、新しい配信 ID でやみくもに再送信するのではなく、元の配信 ID で結果をチェックします。これにより、失われた応答によって重複したターゲット作業が作成されるのを防ぎます。

ユーザー向けコピーの用途 **ペルソナ**。既存の `roleId`, `/api/roles/*`、および `data/roles/` 名前は互換性内部のままである。ディレクトリの移行は必要ありません。

## 別の PC 上のペルソナにアクセスする

ペルソナ データの同期は廃止されます。この機能は削除されますが、デフォルトでは無効ではありません。 **マルチ PC ペルソナ同期**、変更されたファイル、 **プルして同期する**、および競合解決ワークスペースは、もはやエントリ ポイントとして機能していません。バックグラウンドでのペルソナファイルのマージは残りません。

使用 [RabiLink](interface-and-status_ja.md#rabilink-ホームリモート-エージェントおよび構成) 同期コピーを作成せずに、ターゲットPC上のペルソナ、エージェント、およびデータにアクセスする。リモート アクセスは、ターゲットのアクセス許可と接続状態の影響を受け続けます。任意の書き込みは許可されません。

既存のペルソナ、計画、記憶、会話、ペット資産、履歴同期アーカイブ、および競合証拠が保持される。廃止時にユーザー データの削除や再配置は必要ありません。参照 [同期のリタイアとデータ保持](../persona-data-sync_en.md)。これは、インストールされたアップデートや完了した物理デバイスの受け入れではなく、ソース境界を表します。

## エンドポイントアカウント全体で個人を認識する

ペルソナを選択した後、 **アイデンティティのポジショニング** は 2 枚のカードに分かれています:

- **認識されたアイデンティティ** は人ごとにまとめられています。 1 人の名前と確認済みの QQ、Weixin、音声、その他のエンドポイント アカウントが同じ人物カードに表示されます。カード全体を選択すると、1 つのアイデンティティ ワークスペースが開き、個別の 3 点メニュー ダイアログを表示せずに、基本的な詳細、エンドポイント アカウント、話し方の習慣、および関係を表示および編集できます。
- **認識されないアイデンティティ** はエンドポイント タイプごとに編成されます。アカウントは、その人物が不明である場合、候補者がまだ認識されている人物を指していない場合、または証拠が矛盾している場合にここに残ります。表示名が一致しても、アカウントは自動的に結合されません。

The **関係** セクションでは、人、組織、プロジェクトに対して 1 つの関係モデルを使用します。レコードは長期タイプと短期タイプに分割されません。現在のメッセージ内の一時的なペルソナ (誰がアイデアを提案したか、誰が誰に返信しているかなど) は、手動で維持される別の関係タイプになるのではなく、自動的に作成されるシチュエーション レコードに残ります。基本的な詳細と話し方の習慣は一緒に保存されますが、アカウントと関係はそれぞれのセクション内に保存されるため、部分的な失敗は一括更新の成功として表示されません。

エンドポイントがその表示名とともに変化しないアカウント識別子を供給し、メッセージが現在のペルソナのルールと一致する場合、馴染みのないアカウントが「知り合いになる」候補として自動的に表示される。これは、ペルソナがアカウントの手がかりを蓄積できることのみを意味します。 RabiRoute がすでにその人物を知っているという意味ではありません。アカウントは確認後にのみ個人カードに移動します。

自己申告の名前、他人の主張、一時的な表示名、語彙、文型、応答リズムの長期的な一貫性は、候補者の検討に役立つ可能性がありますが、単独で身元を確認できるものはありません。転送、引用、または添付されたコンテンツにのみクレームが存在する場合、またはエンドポイントが安定したアカウント ID を提供できない場合、システムはアカウントを既存のユーザーに自動的に添付するのではなく、認識されないままにします。

複数の人が 1 つのアカウントを使用する場合があります。許可されたユーザー セットがわかったら、そのアカウントをすべての関係者カードに添付してマークします。 **共有**。これにより、現在のメッセージを書いた人ではなく、アカウントを使用できる人が識別されます。このシステムは、自信と不確実性を維持しながら、明示的な自己識別、応答チェーン、タスクの継続性、およびメッセージごとの帰属のための話し方の一貫性を組み合わせることができます。 1 人のユーザーによる最近のアクティビティによって、アカウント全体が永久アカウントに変わってはなりません。 ID を修正する場合は、実際のエンドポイント アカウントを保持し、ニックネームから作成された架空の人物レコードをすべて破棄して、履歴を追跡できるようにします。

## ID ポジショニングの下で音声アカウントを分類する

ペルソナが選択された後、 **アイデンティティのポジショニング** QQ や WeCom などのテキスト アカウントを一緒に提示します。 **音声エンドポイントアカウント**。処理ホストと声紋 ID の各ペアは 1 つの音声アカウントであり、複数の話者による録音では複数のアカウントが参照される場合があります。音声セクションには、最新の 24 時間の分類カバレッジ、ユーザーに起因する音声、他の人に起因する音声、不明または矛盾するセグメント、およびこのペルソナによって既に保存されている関係が表示されます。 **これが私です** は、処理ホスト上の現在のペルソナによる声紋の明示的な解釈にすぎません。 RabiSpeech も RabiRoute ホストも、ユーザーが誰であるかを決定したり、デフォルトでユーザーに声紋を割り当てたりすることはありません。

未解決の声紋の場合は、次を選択します。

- **これが私です**: 現在のマークを付けます `sourceHostId + voiceprintId` このペルソナによるユーザーとしての関係。
- **別の人**: ユーザーではないことを明示的にマークします。
- **判定を解除**: 元の関係イベントを保持したまま `isUser` の判定だけを不明に戻します。

このページは、統計、短縮された声紋、継続時間、最後に見た時間、および関係性のみを要求する。トランスクリプトのテキストを要求したり表示したりすることはありません。新しい記録とローカル関係の修正は、それぞれ 1 つのイベント駆動型リフレッシュをトリガーします。イベント ストリームを再接続すると、固定間隔のカバレッジ ポーリングの代わりに 1 つのキャッチアップ クエリが実行されます。現在のバージョンでは、ペルソナの既存の音声分類が保持されます。 `voice/voice-identities.jsonl` を ID 関係内に提示しながら。後の統合データ移行では、これらの分類を保持する必要があります。過去の音声分類の競合は、後の明示的な確認によって分岐が収束するまで、目に見えるままになります。

初めて使用するときは、不透明な声紋 ID を認識できない場合があります。選択 **次の録音をマークします**を選択し、できれば静かな環境で、分類したい PC、電話、またはメガネを通して自分で 1 つの連続した文を話します。次の録音イベントが完了すると、その試行中に新たに観察された未解決の声紋が先頭に移動し、 **今回観測されました** マーカー。これは候補を絞り込むだけです。2 番目のレコーダーを起動したり、自動識別を実行したり、候補が 1 つ現れたからといってユーザーを割り当てることはありません。他の人が同時に話した場合は、自信を持って識別できる声紋のみを確認するか、再度キャプチャしてください。

## ペルソナ自動化の構成方法

各ルールは、いつ実行されるか、そして次に何が起こるかという 2 つの質問に答えます。

トリガーは次のとおりです。

- **メッセージが届いたとき**: オプションのテキスト、グループ、スピーカー フィルターを使用して、1 つ以上のメッセージ ソースを選択します。
- **スケジュールされたタスク**:固定間隔、毎日の時刻、または 1 回限りの日時を使用します。

アクションは次のとおりです。

- **エージェントに通知する**: 現在のメッセージまたはスケジュールされたタスクを、オプションの追加の決定ガイダンスとともにこのペルソナに送信します。
- **スクリプトを実行します**: を実行します `.cmd`, `.bat`、または `.py` ファイル `scripts/` ディレクトリ。

したがって、同じモデルは、メッセージからエージェント、スケジュールからエージェント、メッセージからスクリプト、およびスケジュールからスクリプトのルールをカバーする。新しいトリガーまたはアクション タイプは、別の独立したルール画面を作成せずに、このモデルを拡張できます。

インターフェースが分離します **メッセージが届いたとき** から **スケジュールされたタスク**。メッセージ ルールは、チャット、音声とデバイス、マニュアルとシステム、その他のソースにグループ化されます。エディターは最初にトリガーを要求し、次にアクションを要求し、現在の選択に関連するフィールドのみを表示します。

## 共通ルートの種類

|種類 |用途 |
| --- | --- |
| `private` | QQ プライベート メッセージ |
| `direct_at` |グループへの直接の言及 |
| `direct_reply` |アカウントまたはペルソナの会話に対する直接の返信 |
| `indirect_reply` |より広範な応答チェーンの観察。ノイズが発生する可能性があります |
| `group_message` |アンビエント グループ メッセージ。通常は狭い正規表現を使用します。
| `heartbeat` |スケジュールと手動検証 |
| `manual_trigger` |明示的な UI または API トリガーのみ |
| `role_panel_message` |ローカルペルソナパネルとクロスペルソナ配信によって共有される組み込みのペルソナメッセージ |
| `plan_feedback` |最近のメッセージのない独立した計画承認システム イベント |
| `voice_transcript` | RabiSpeech などの音声文字起こし |
| `wecom_message` | WeComグループイベント |
| `rabilink` |RabiLinkのイベント |

インターフェースは、現在のルート上のアダプタごとに利用可能な種類をグループ化します。ソースが選択されていないメッセージ ルールは、受信したすべてのメッセージと一致し、ページに警告が表示されます。より広範なグループ メッセージの一致を追加する前に、プライベート メッセージ、直接返信、または絞り込んだキーワードから始めてください。

## 正規表現に焦点を当て続ける

空の正規表現を含むすべてのアンビエント グループ メッセージを転送しないでください。対象とする作品を表す用語から始めます。例:

```text
requirement|error|build failed|reminder|please record
```

Regex は、エージェントが応答する必要があるかどうかではなく、ルールが一致するかどうかを決定します。ペルソナガイダンスでは、新しい事実、タスク、リスク、謝辞、丁寧な対応を区別する必要があります。

## スケジュールされたタスク

スケジュールトリガーは以下をサポートします。

- 繰り返し間隔。
- 毎日の時間。
- 1 回限りの日付と時刻。

スケジュールされたタスクには、ルートのスケジュールされたタスクの入力が必要です。エージェントのアクションには、現在のタスク、ペルソナ/プラン/メモリ インデックス、および自動チャット履歴なしで必要なパスが含まれます。スクリプト アクションは、エージェントを経由せずに、ローカル スクリプト実行プログラムに直接送られます。

## スクリプトの制限

設定されたローカルスクリプトは、別のルート許可スイッチなしで実行され、その所有ペルソナのスクリプトディレクトリに残ります。リモート ペルソナ スクリプトは、自身の PC 上で実行されます。

- スクリプトは現在のペルソナ内に物理的に存在する必要があります `scripts/` ディレクトリ。リンクと `..` からは逃れられません。
- のみ `.cmd`, `.bat`、および `.py` は受け入れられます。任意のコマンド テキストは使用できません。
- マネージャトークン、パスワード、およびメッセージ本文は、スクリプト環境変数として公開されない。
- 同じルールは同じルート上で重複できず、タイムアウトによりプロセスツリーが停止します。
- スクリプトの実行とエージェントの配信は別々の結果を保持する。一方が他方の成功を真似ることはできません。

ペルソナに関連するパスを入力してください `scripts/` ディレクトリ、たとえば `daily-check.py` または `tools/check.cmd`。 1 行に 1 つの引数を入力します。ファイルを変更したり外部システムを呼び出したりするタスクを使用する前に、テスト ペルソナを使用して非破壊スクリプトを検証してください。

## テンプレートに含まれるもの

テンプレートは、イベント全体を再構成するためではなく、意思決定のガイダンスとして使用する。 RabiRoute は、イベント、ペルソナ、ログ パス、ナレッジ インデックス、および応答コンテキストをすでに挿入しています。通常のエンドポイントは、設定された最近のコンテキストを受信することもあります。Heartbeat では最近のチャット履歴を注入しません。

簡潔な作業テンプレートでは次のように言えます。

```text
Classify this as information, question, task, risk, or decision.
Act only when facts, blockers, or next actions changed.
Use the injected RabiRoute reply interface for external output.
```

会話の文言だけでは送信許可を与えることができない。パイプラインとメッセージ アダプター ポリシーは依然として実際の出力をゲートします。
