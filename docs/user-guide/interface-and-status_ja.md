# インターフェースとステータス

RibiWebGUIは、RabiRouteのローカル制御コンソールである。構成を編集し、マネージャーのアクションを呼び出し、診断を表示します。ローカル ファイルと実行時の状態は、基礎となる信頼できる情報源のままです。

## LANからWebGUIにアクセス

Rabi PC上のマネージャは、RibiWebGUIの完全なHTTPバックエンドである。オペレーティング システムは、使用可能なポートを Manager の各世代に割り当てます。トレイから現在の WebGUI を開くか、読み取ります `managerBaseUrl` スルー `RabiRouteHost.exe --command status --json`。別のデバイスでは、 `127.0.0.1` は、Rabi PCではなく、そのデバイスを指します。

Rabi PC で、次のコマンドを開きます。 **設定 → ディレクトリ構成 → LAN WebGUI アクセス**アクセスを可能にし、キーを生成する。 Manager を再起動した後も、WebGUI は引き続きローカルで開かれました。 `localhost/127.0.0.1` 現在のルート、ページ、認証を維持しながら、優先LAN IPに自動的にリダイレクトします。生成されたリンクをコピーすることもできます。例:

HTTP LANページは、安全なブラウザのクリップボード許可を受け取らない場合がある。リンクのコピー、キーのコピー、およびその他の WebGUI のコピー アクションは、最初にクリップボード API を試行し、その API が使用できないか拒否された場合は、自動的にページ内コピー操作に戻ります。手動コピー メッセージは、ブラウザが両方のメカニズムを拒否した場合にのみ表示されます。

```text
http://<Rabi-PC-LAN-IP>:<current-manager-port>/#/routes/<Route-config-name>/overview?webgui_token=<access-key>
```

サイドバーの主な入口はペルソナ設定と計画・メモリです。独立したペルソナ選択には、ルートのないペルソナも含め、アーカイブされていないものが表示されます。「ペルソナ設定 → メッセージアダプター」は基本情報の次にある二番目のタブで、そのペルソナのルート、メッセージ端、処理 Agent を管理します。複数のルートを切り替えたり、未設定のルートを関連付けたりできます。左下の「ペルソナを追加」で作成画面を開きます。

正式なリンクは `#/roles/<RoleId>/config`、`#/roles/<RoleId>/config?tab=messages`、`#/roles/<RoleId>/document`、`#/roles/<RoleId>/knowledge` です。既存の `#/routes/<Route-config-name>/adapters` は対応するペルソナのメッセージタブに移動し、元のルートを選択します。未設定のルートには関連付け用の旧編集画面が残ります。パフォーマンス、RabiLink、設定は本機共通です。旧データは[設定アップグレード](../persona-message-config-upgrade_en.md)を参照してください。

サイドバー ページのラベルをクリックすると、最初に選択された状態、トップ タイトル、URL が更新され、すぐに表示されます。 **ページが切り替わりました。コンテンツを読み込み中…**。コンソール、メッセージ アダプタ、ペルソナ構成、プランとメモリ、音声サービス、パフォーマンス、ランタイム診断、および設定は、完全なページの準備ができるまでタブの切り替えを遅らせるのではなく、ページ コードとデータを非同期的に読み込みます。ページ チャンクのロードに失敗した場合、WebGUI は 1 回更新され、意図したページが復元されます。

```text
http://<Rabi-PC-LAN-IP>:<current-manager-port>/#/roles/<RoleId>/knowledge?webgui_token=<access-key>
```

ブラウザURLは、選択されたペルソナまたはルートおよびページを識別する。更新、ブックマーク、ブラウザ履歴により、その選択が復元されます。ペルソナ ページにはルート バインディングは必要なく、ペルソナを選択してもルート参照は書き換えられません。

ルート設定名は URL エンコードされています。 Route スコープのリンクは、ページをレンダリングする前にその Route を選択します。サイドバーのルートを切り替えると、現在のブラウザ セッションが新しいルートで同じページ タイプに更新されます。ブックマーク、再度開く、または同じ LAN 上の承認されたデバイスとショートカットを共有するには、WebGUI がキーを削除した後、アドレス バーではなく完全なキー付きリンクを使用します。

WebGUIは、現在のブラウザセッションにURLキーを保持し、それをHTTP、SSE、およびペルソナアバターリクエストに自動的に適用し、その後のスクリーンショットでURLキーが公開され続けることのないようにアドレスバーから削除する。キーをローテーションすると、古いリンクはすぐに無効になります。ローカル接続または認証された接続は、別の管理権限を付与せずにスイッチとキーを管理できます。リンクがタイムアウトした場合は、ホスト ステータスで現在のポートを確認し、Windows ファイアウォールがプライベート/ドメイン ネットワーク上でこの世代の RabiRoute Manager を許可しているかどうかを確認します。公開チャット、ログ、またはリポジトリでリンクを決して公開しないでください。また、前世代の動的ポートを永続的なアドレスとしてブックマークしないでください。

Rabi PCからその自身のLANアドレスへのリクエストは、引き続きローカルリクエストとして扱われる。したがって、LAN アクセスを有効にしても、同じ PC 上のメッセージ送信、トレイ、またはローカル ツールに WebGUI キーが必要になることはありません。他のデバイスは引き続き、有効なキーを持つ完全なリンクを使用する必要があります。

## RabiLink 経由で WebGUI にリモートでアクセスします

Rabi PC でグローバル RabiLink Relay 接続が有効になっており、現在の Relay アカウントに属している場合は、次の URL でサインインします。 `https://relay.example.com/manage`を開き、次のようにします。

```text
https://relay.example.com/manage/<account>/<RabiGUID>/#/roles/<RoleId>/knowledge
```

リモートエントリは同じルートページ名を使用する。交換する `knowledge` 付き `overview`, `adapters`, `persona`, `speech`、または `runtime` 。設定はホスト全体で使用されます `#/settings` パス、パフォーマンスはホスト全体のパスを使用します `/performance` パス。

最終ページを次のように置き換えます `overview` または必要に応じて別の WebGUI ルート。このリモートエントリはLANを使用しません `webgui_token`;ブラウザのリレー管理ログイン Cookie を使用しますが、PC ワーカーはアプリケーション トークンを使用して個別に認証します。通常の API、画像、添付ファイル、オーディオ、ダウンロード、およびバイト範囲のビデオ再生は、選択した PC のループバック マネージャーに戻り、マネージャー イベントはリモート SSE を通じて更新されます。シェルは開くが、データ、添付ファイル、またはライブ ステータスが開かない場合は、ターゲット PC が Relay でオンラインであること、RabiGUID が正しいこと、および Relay スクリプトが正しいことを確認してください。 `ribiwebgui/dist` を合わせて出版しました。ローカル Manager のみを再起動しても、パブリック Relay は更新されません。

## RabiLink ホーム、リモート エージェント、および構成

以前のリモート エージェント サイドバー エントリは現在、 **RabiLink**、ホーム、リモート エージェント (中国語では远端智能体)、および構成を含む `#/rabilink?tab=home`, `#/rabilink?tab=agents`、および `#/rabilink?tab=config`。レガシー `#/lan-agents` [リモート エージェント] タブにリダイレクトされます。

構成では、インスタンス GUID が表示され、インスタンス名、リレー URL とアプリケーション トークン、接続スイッチ、高度なタイムアウト、音声プロキシ、およびエージェントのアップロード制限が保存されます。これらのフィールドは [設定] に表示されなくなりました。ディレクトリ、LAN アクセス、デスクトップ機能はそのまま残ります。

ホームは、管理ページを埋め込む代わりに、現在のアプリケーション内のコンピュータ名、識別子、オンライン状態、およびサービスを示す、中国語のUIに中国語のラベルを備えたコンパクトなネイティブビューである。有効な接続設定が保存された後、この情報を読み取るために、Relay 管理アカウントに再度ログインする必要はありません。マネージャーは、読み取り用のアプリケーション トークンを保存して使用します。ホームがそのトークンを受信することはなく、ページ URL にトークンが含まれることはありません。 HTTP(S) ルート リレー アドレスのみがサポートされ、ユーザー情報、クエリ、ハッシュ、パス プレフィックスはサポートされません。

PC の行は RabiPC のバージョンを示し、このコンピュータには Local ラベルが付いています。バージョンは、各コンピュータの実行中のインストールから取得されます。広告のない古いデバイスには不明なバージョンが表示されます。このコンピュータのバージョンは、別のコンピュータが更新されたかどうかを証明しません。ローカル ペルソナ ソース オプションには実際のデバイス名も表示され、このコンピュータはリモート ソースとして繰り返されません。別のコンピュータが同じデバイス ID を共有している場合は、最初に両方のコンピュータの ID 構成を確認してください。

未構成の場合は、[構成] を開きます。接続、認証、読み取りに失敗した場合は、表示されたエラーに従って接続を確認した後、再試行してください。読み取りの失敗は、デバイスがゼロであることや、初めての初期化を意味するものではありません。空の応答が成功した場合のみ、デバイスがないことを意味します。

**ホームログインを繰り返しても、管理者権限は付与されません。** アカウントまたはアプリケーションを管理するには、次を使用します。 **新しいウィンドウで開きます** 個別用 `/manage` ページでは、依然として管理アカウントのログインが必要です。ホームはそのページのログイン Cookie に依存しません。この設計の展開と実際のページの対話には、依然として個別の承認が必要です。

ページは、ユーザーがプランを展開した場合にのみ Codex Desktop の状態を読み取り、ページを更新した後は、展開されたままのプランのみをチェックします。ロードされたプランごとに状態スキャンが開始されなくなりました。 1 つのプランは同じパスで 2 回要求されることはなく、各読み取りには 3 秒の制限があります。展開された詳細には、タスク エージェント、有効になっている場合のプラン セクレタリー、各エージェントの作業状態、および一致する Codex タスクの状態が表示されます。不足しているタスクには独自のタスクがあります `Task Agent session is missing` ラベル。有効な非動作バインディングは、カードまたはエージェント行から Codex で検索または起動できます。これにより、正確なタスク ID のみが開かれ、メッセージや置換タスクは送信されません。

マネージャーが戻ってきたら `presentation.acceptsGuidance=true` 承認外の計画の場合、カードを展開すると計画全体のガイダンスが表示されます。のみ関連付けられています `planId`、1ステップではありません。エージェントはそれを使用して計画を継続し、必要に応じて後のステップを調整し、 `guidance_response` なし `stepId`。承認計画では、所有するステップの承認契約が引き続き使用され、 `approval_response`.

サイドバーで現在のルートを選択し、上部バーでマネージャ接続を確認します。コンソールまたはログ診断のランタイム状態を使用して、そのルートが実行されているかどうかを判断します。

The **計画と記憶** ページは読み込まれません `data/` 第2のステータスを直接的に、または導出する。 `plan.status` には、現在のペルソナ構成のキーのみが保存されます。 Manager は、設定されたラベル、説明、パレット、順序、ビューとともにキーを返します。 WebGUI と Qt トレイはそれらの結果のみを表示します。エージェントは、プログラム コードを変更せずに、マネージャーを通じてペルソナ計画のステータスを追加、修正、または削除できます。ステップ、待機理由、および承認メタデータは、構成されたステータスを置き換えることはありません。

現在のステップの概要にステップの内容が表示されます。 `detail` の説明がタイトルのすぐ下にあるため、ユーザーは完全な実行プランを開かなくても、ステップに必要なものを確認できます。説明のないステップでは、空のプレースホルダーは表示されません。ステップの詳細に検証ターゲット、レビュー担当者、リソース、レビュー担当者が行う内容、および合格セクションが含まれる場合、WebGUI はそれらを見出し、リソース リスト、順序付けされたアクション、および別の結果ブロックとしてレンダリングします。従来の検証パス/検証ステップ/合格基準形式は互換性を維持し、通常の詳細は改行を維持し、長いパスはカード内で折り返されます。

ディレクトリは、パネル全体の水平スクロールを決して導入しない。末尾の並べ替えラベルは固定されたままですが、オーバーフローしたタイトルはポインターのホバーまたはキーボード フォーカスで一定の速度で移動します。 Reduced-motion 設定では、タイトルの移動が無効になります。リスト ダイアログの選択肢は、次の時点まで下書きのままです。 **完了**。ダイアログを閉じると、現在のリストは変更されません。 **完了** は、それを閉じて、選択したマネージャー側の並べ替えとフィルターを使用して完全なプラン リストをただちに 1 回呼び出し、ディレクトリとコンテンツ カードを一緒に更新します。ダイアログを開くと、最初にそのフレームと現在の結果がペイントされ、次に計画データを再度要求することなく、次のフレームに並べ替えとフィルターのコントロールがマウントされます。

幅の広いダイアログは 2 つの列を使用します。左側は並べ替えとステータス、右側はタグ検索とタグです。ステータスと計画 `keywords` タグはどちらも、各グループ内での OR マッチングによる複数の選択をサポートします。プランは両方のグループに一致する必要があります。タグ セクションは検索可能で、表示されている行のみが表示されます。フィルター候補と下書き選択は、現在のページ セッションで再利用されます。トリガーと結果の概要には、グループごとのクリア アクションと、アクティブなフィルター数が表示されます。 **フィルターをクリアする**。狭い画面では列が積み重なり、チェックボックスとアクション ターゲットは少なくとも 44 ピクセルのままになります。

5. クリック **送信**、オプションのテキストを追加し、アクティブなペルソナを選択します **ペルソナに送信**と確認します。テキストが空でも画像は送信されます。

スクリーンショットおよびテキストは、ペルソナパネル配信エントリを使用する。 Codex と DSH は、スクリーンショットを画像入力として受け取ります。ファイルはプライベート プロジェクト ディレクトリに一時的に保存されます `.rabiroute-message-images/`;ピン留めされた画像と選択領域の記録はプライベートに保存されます `data/desktop/`。スクリーンショットの切り替え、スクリーンショットのショートカット、自動コピー設定、ピン留めショートカット、または **Windows ログインの起動**トレイは新しい設定を自動的に読み取ります。再起動は必要ありません。

選択オーバーレイは、現在の表示スケールで物理ピクセルを保持し、125%、150%、または 200% のスケーリングで細かいテキストや線を歪ませるダウンスケール/アップスケール サイクルを回避します。スクリーンショットには追加のシャープ化やぼかしは適用されません。コピーして送信しても、元のキャプチャはトリミングされます。選択範囲外の調光は画像に保存されません。

## 選択テキストメニューを有効にする

開く **設定** WebGUIで検索してください **選択テキストメニューを有効にする**:

2. カーソルを移動します **に送信します** 現在有効で実行中のペルソナをリストする。 1 つの項目をクリックすると、選択したテキストがそのルートに配信されます。

## ペルソナ自動化とエージェントフック

[利用可能なテンプレート変数] ボタンをクリックすると、閉じることができる参照ダイアログが開きます。変数リストはオートメーション ページに表示されなくなりました。

エージェントフックは、エージェントカードを左側、または狭い画面の設定の上に表示します。各カードには有効な項目の数が表示され、選択したエージェントの設定が右側に表示されます。各エージェントは独立して構成され、複数のエージェントの設定を同時に有効にすることができます。カードを切り替えると、表示される設定が変更されるだけです。 「保存」をクリックして変更を適用します。

セッションコンテキスト、ツールコンテキストのリフレッシュ、完了通知、およびRabiを介したエージェントメッセージの送信は、スイッチとして表示されたままである。計画タスクのフォローアップとイベント配信は、デフォルトでは折りたたまれています。見出しを選択してパラメータを展開します。パネルを折りたたむと、有効な状態が変更されません。

[エージェント フック] → [イベント配信] を展開し、次に [イベント] → [条件] → [宛先] を設定します。タスク完了は現在サポートされています。ターンは完了チェックに合格する必要があります。プロジェクト フィルター、リンクされたプランが必要、セッションを含める、およびセッションを除外する条件を追加または削除します。すべての条件が一致する必要があります。条件がない場合は、すべての Codex タスクが一致することを意味します。

セッション条件は、検索可能な複数選択と明示的なページ分割された読み込みをサポートします。 「セッションを含める」は、選択したセッションに一致します。セッションの除外が優先され、他のすべての条件が一致する必要があります。照合では完全なセッション ID が使用されるため、名前を変更してもルールは変更されません。名前は表示ラベルのみです。空の選択を有効にすることはできません。スキャンは、ボタンで要求された場合にのみ実行されます。

NapCat の場合、ルート、QQ アカウント、グループまたはプライベート QQ、および対応する ID を選択します。音声では、QQ フィールドを使用せずに、選択したルートの合成および再生設定が使用されます。既存のグループ ルールは、プロジェクト、計画要件、宛先、有効な状態を維持したまま移行されます。保存すると、従来のフィールドが削除されます。新しいルールは無効になって開始されます。設定を完了し、ルールを有効にして、ペルソナを保存します。

プロジェクトフィルタを使用すると、異なるリポジトリディレクトリ内のCodexプロジェクトは分離されたままになります。ワークツリーは相対プロジェクト ディレクトリを保持します。非 Git プロジェクトはディレクトリと正確に一致します。通知には、プロジェクト パスやセッション ID なしで、タスク名、リンクされたプラン名、および最終応答が表示されます。現在の Codex タイトルは、保存されたプラン バインディング タイトルよりも優先されます。どちらも存在しない場合、タスクには名前なしのラベルが付けられます。 「リンクされたプランが必要」では、このペルソナのプラン内のタスク バインディングのみが受け入れられます。

繰り返されるイベントでは、同じタスク、ターン、ターゲットのレシートが再利用されます。不確実な送信結果は自動的に再試行されません。ルートの送信ログを確認してください。ターン ID または最終応答のないイベントは無視されます。ルールは無効な状態で開始され、追加時に履歴メッセージは送信されません。

[ペルソナ] → [自動化] には、[メッセージ ルール] タブと [エージェント フック] タブがあります。左側のメッセージ タイプを使用して、スケジュールされたタスクなどのルールを表示します。メッセージ ルールを追加すると、エディターが直接開きます。メッセージ タイプを選択し、エージェントに通知するかスクリプトを実行します。フック設定は、エージェントごとにペルソナの設定に保存されます。 `personaConfig.json`;そのペルソナを使用するルートは、対応するエージェントの設定を共有します。レガシー ルート設定は、保存または明示的な移行時にペルソナ ファイルに移動します。

エージェントパネルは、初期インストールおよびその後のアップデートのためにエージェント内のアップデートフックのみを提供する。 Codex は公式プラグイン インストーラーを使用します。 DSH はローカルにインストールされます `web` プロファイルを作成するには、プラグインのリロードまたは DSH の再起動が必要です。パッケージが存在する `plugins/rabi-codex-context/` そして `plugins/rabi-dsh-context/`.

### 承認と情報要求に重点を置く

通常モードはデフォルトのままである:承認し、情報を提供し、内部プランカードを提出する。の **フォーカス** 検索の左側にあるスイッチは、別の全画面表示を開かずに、このページ上のコンテンツのレイアウトのみを変更します。ナビゲーション、ディレクトリ、カードのスタイル、検索、タグとステータスのフィルター、並べ替えは変更されません。スイッチをオフにすると通常のリストに戻ります。

有効にすると、コンテンツは 2 つの列に分割されます。左側で選択した計画の質問、提案、添付ファイル、およびコンテキストを読み取り、右側で承認と情報入力を使用し、その列の下部に送信ボタンが表示されます。各列は独立してスクロールし、レイアウトは残りのビューポートの高さに適合します。エディタを展開して右側の列を広げます。コンテンツ幅 640 ピクセル未満では、ペインは読み取りと応答用に確保された等しいスペースでスタックされます。同じディレクトリからプランを選択します。検索とフィルターは引き続き同じ結果を制御します。結果が空であっても、古い回答フォームが表示されたままになることはありません。回答するものが何もない計画は、承認欄を空にせずに全幅を使用します。検索フィールドの更新アイコンは、元のページ更新動作を保持します。

選択肢、追加テキスト、添付ファイルは同じフォームを再利用します。長い形式の場合は回答エリアを拡大します。どちらのレイアウトもドラフトと送信ロジックを共有しており、切り替えてもフィードバックは送信されません。不完全な承認資料では依然として不足しているものが説明されており、承認が妨げられています。フォーカス モードでは資格が緩和されません。

同じペルソナのページ内で項目を切り替えたり、フォーカス モードを閉じて再度開くと、未送信の下書きが保存されます。下書きはフィードバックとして保存されません。ブラウザをリロードするかペルソナを切り替える前に、未完了の入力を処理します。変更された質問や提案には、古い選択肢を再利用するのではなく、新たな確認が必要です。送信では、選択内容を積極的に変更しなくても、保存、配信、または失敗の結果が表示されます。更新されたアイテムが現在のフィルターに一致しなくなった場合、選択は元のリストのルールに従います。

**送信する** は保存のみです。 **提出して納品する** は保存してエージェントに通知します。フォーカス モードでは、計画の既存の承認条件、添付ファイル、フィードバック レコードが再利用されます。 2 番目の計画は作成されず、保存の成功とエージェントの配信の確認は同等ではありません。

### 決定事項と添付ファイルのプレビューの確認

承認エリアでは、決定、推奨、添付ファイルのプレビューが行われます。画像とビデオは大きなビューアで開き、Markdown レポートには抜粋カードと完全なプレビューが含まれ、その他のファイルは開いたアクションを保持します。これらのプレビューでは、プランの説明と同じコンポーネントを使用します。

理論的根拠、代替案、ファイル変更、コマンド、検証、ロールバック、レシート、および以前のフィードバックは、デフォルトでは折りたたまれています。空のファイル、コマンド、および変更セクションは非表示になります。実際の構成または外部の影響、および承認不足の警告は引き続き表示されます。承認資格は変わりません。

左側のナビゲーションを折りたたむと、外側のマージンを維持したまま、プラン ページが最大 1880 ピクセルまで広がります。モバイル レイアウトでは 16 ピクセルのサイド パディングが維持されます。

計画リストとカウントは独立してロードされます。カウントに失敗した場合、 **再試行回数** 統計のみをリフレッシュする。 **エラーの詳細** 診断結果を保持する。初期リストの準備ではコンパクトな読み込み通知が表示され、検索フィールドの更新ボタンで読み込みを再開できます。狭い画面では、検索は独自の行を占有します。
