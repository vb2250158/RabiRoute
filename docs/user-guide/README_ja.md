# RabiRoute ユーザーガイド

このガイドは、RibiWebGUIを介してRabiRouteを構成および操作する人々を対象としたものである。最初の画面から始まり、コード、スキーマ、エージェントの内部構造を理解することは期待されていません。

> RabiRoute 0.4.xに適用されます。プロジェクトは現在活発に開発中です。 「実験的」とは、統合は存在するが、その外部プラットフォームまたは実際のデバイスのパスが環境内でまだ検証される必要があることを意味します。

## まず一つのことを理解してください

RabiRouteは、メッセージのトリアージおよびディスパッチ層である。メッセージを受信し、イベントを記録し、ルートを選択し、コンテキストを追加し、Codex または別のハンドラーに作業を渡します。ハンドラーは、実際の応答、コーディング、ツールの使用を行います。

インターフェースでは、 **ルート** は、独立して制御されるメッセージ フロー構成です。

```text
Message adapter -> matching rules -> persona and context -> Agent handler -> reply or draft
```

- A **メッセージアダプター** NapCat/QQ、Heartbeat、Webhook、またはRabiLinkなど、メッセージがどこに入るかを決定する。
- A **ペルソナとそのルール** どのメッセージが一致するか、およびそれに伴う指示は何かを決定します。
- An **エージェントアダプター** どのハンドラ、プロジェクトディレクトリ、タスクがメッセージを受信するかを決定します。
- **ログ診断** メッセージが停止した場所を示します。

## 最良の初回実行パス

ソフトウェアが動作することを証明するには、ハートビートとCodexから始める。このパスは QQ ログインを必要とせず、配信を検証する最短の方法です。

1. 左下の「ペルソナを追加」でペルソナを作成して保存します。
2. 「ペルソナ設定 → メッセージアダプター」でメッセージルートを追加します。
3. Heartbeat と Codex を選び、プロジェクトディレクトリと Desktop タスクを関連付けます。
4. 設定を保存し、そのルートを有効にします。
5. 一度手動で実行し、ログ診断の配信記録と宛先タスクの受信を確認します。

参照 [最初のルートを実行します](first-route_ja.md) 完全な手順については。 QQ の準備ができたら、次の手順に進みます。 [ルートとメッセージアダプタ](routes-and-adapters_ja.md).

通常の使用では、次のことを確認してください。 **マネージャーが接続しました**、保存して独自のルートを開始します。

## 読書規則

- パス、タスク名、ルール名、トークン、およびログは、UI言語が変更されても変更されないままである。
- 設定を保存すると、ローカル設定が書き込まれます。一部の変更では、現在のルートが同期または再起動されます。
- 手動トリガーが実際の配送経路に入る。これは副作用のないプレビューではありません。
- アウトバウンドの結果は次のようになります。 `sent`, `draft`, `blocked`、または `failed`。外部アクションに対する一般的な WebGUI 承認センターはありません。 [計画] ページには、承認フィードバックを保存した後に承認済みと表示され、配信の確認後にのみ分析中と表示されます。これは、すべてのオプション、アウトバウンド配信、または自動実装を許可するわけではありません。ガイダンスによってステータスは変化しません。
