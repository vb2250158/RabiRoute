# コンピューター操作

**RabiLink → コンピューター操作**を開きます。この PC、接続済みの RabiPC ホスト、軽量クライアントのノードを同じ一覧に表示します。行を展開しても、設定と作業状態を読み込むだけです。取得に失敗した場合は前回の情報を保持し、状態不明とオフラインを区別します。

全機能は 0.13.0 と更新済みの Windows 実行端で提供されます。古いノードは、宣言している機能を引き続き使用します。オンライン表示だけでは更新済みとは判断できません。名前、IP アドレス、空のターミナル一覧から推測せず、実際の対応機能を確認してください。

## 機能を選ぶ

各コンピューターには総合スイッチと、ターミナルコマンド、ファイル、ウィンドウと画面取得、Agent タスク、マウスとキーボード、画面注釈の六つのスイッチがあります。未設定の項目は有効です。無効にするとその入口からの新しい作業を停止しますが、元の状態確認と後処理は残ります。ターミナルや Agent が独自のツールでファイルや入力を操作する場合もあります。これらのスイッチは各入口の範囲を表します。

設定は対象の既存の設定 owner に保存します。画面では保存の確認と実行端への適用を区別します。適用が未確認の場合は、設定を書き直さず、元の作業状態を確認してください。

## 入力と観測

1. コンピューターを選び、ウィンドウ一覧または画面を取得します。
2. 「手動操作を開始」を選ぶか、Agent が `control.begin` を呼び出します。
3. ポインター移動、クリック、スクロール、ドラッグ、Unicode 文字、ショートカットを順序付きの入力として送信します。画像座標には元フレーム、インスタンス、ウィンドウ、ピクセル範囲を保持します。配置が変わった場合は再度観測してください。
4. 画面の終了ボタンまたは対象の終了ショートカットを使います。初期値は **Ctrl+Alt+Esc** です。Esc 単独は通常どおりアプリに渡されます。初期設定ではアイドル状態が 120 秒続くと終了し、最後の 10 秒にカウントダウンを表示します。両方とも設定で変更できます。

観測、入力の注入、アプリの結果は別々に報告します。`captureAfter` の初期値は false です。入力後の画面取得に失敗しても、注入済みの入力を未実行にはしません。中止しても実行済みの部分を保持し、バッチを再送しません。プレビューを閉じても Agent のバックグラウンド作業は終了しません。

## 画面への注釈

観測した画像に四角、楕円、矢印、パス、通常の文字、ハイライトを描画できます。静的注釈の初期表示時間は 10 秒で、任意の時間または明示的に消去するまでの保持を選べます。注釈はマウスやキーボードの操作とは独立しています。注釈の消去、追跡の停止、操作の終了はそれぞれ別の処理です。

動的注釈の初期値はオフです。有効にした後、CPU KCF またはローカルのテンプレート照合を明示的に開始すると、追跡ライブラリを読み込みます。要求した頻度と実際の頻度は別に表示します。対象の喪失、曖昧さ、短い予測、リソースの削減は実際の状態を保持します。予測を認識結果とは表示しません。自動予算は、まずプレビューの負荷を減らし、次に頻度や解析サイズを調整します。一時停止した作業には理由を表示します。詳細設定は共通の設定 schema を使用します。

追跡は、明示的な期限、停止、記録された元の接続の切断、機能の無効化によって終了します。通常の HTTP リクエストが終わっても業務タスクの終了とは見なしません。継続する接続の範囲がない場合は、期限または明示的な後処理を使用してください。Rabi 計画が完了した場合は、その正確なタスク関連付けで識別できる作業だけを終了します。モデルの一回の応答終了は業務タスクの終了ではありません。実際のタスクに対応していない接続に架空のタスクを割り当てず、明示的な期限または後処理を使用してください。

## CLI、MCP、その他の Agent

すべての入口は同じ実行中のカタログとパラメーター schema を使用します。汎用 HTTP ツールを備えるホストは、専用の業務ツールを別に実装せずに API を呼び出せます。

```sh
node apps/rabi-agent/rabi-cli.mjs search "computer list" --category devices
node apps/rabi-agent/rabi-cli.mjs describe manager.lan-agent.computers.list --view input
node apps/rabi-agent/rabi-cli.mjs call manager.lan-agent.computers.list --input-json '{}'
node apps/rabi-agent/rabi-cli.mjs describe manager.lan-agent.computer.execute --view input
```

標準 MCP は `rabi_search`、`rabi_describe`、`rabi_call` を使用します。呼び出す前に業務一覧から実際の `instanceId` と所属ホストを取得してください。API の検索件数はコンピューターの台数ではありません。

完全なリモートホストの行には `ownerDeviceId` が含まれます。そのホスト自身の契約を読み、既存の `manager.rabilink.peer.http.get/post/patch` operation を使用します。`deviceId` はその owner、`service` は `manager`、`path` は元の API パスです。本文と対象パラメーターは保持してください。リモートの `instanceId` をローカル対象として扱わないでください。UI も同じ Peer 入口を使用します。

操作、入力、注釈は `POST /api/lan-agent/instances/:instanceId/computer` の `body.action` を使用します。`control.status` などの action は別の operation ID ではありません。結果の照会には元のリクエスト ID を保持し、入力を自動で再送しません。設定は同じ対象の `GET/PATCH .../computer-settings` と元の ETag を使用します。
