# Inspect devices and test actions

Open Smart home → Xiaomi Home → Device list in a message route. Each registered device has a card with its name, room, model and published entity count. Search by name, room or model. Scenes and helper entities without a device are shown separately.

Opening a device card records its usage. On the next page reload or Refresh devices, frequently opened devices appear first, with the most recently opened first for equal counts; other devices keep their original order. Clicking does not immediately rearrange the current list. History stays in the current browser and clearing site data resets it. Scenes and helper entities are excluded.

1. Open a card and select a query/control entity to inspect its current state and Agent capabilities.
2. Select an advertised action and enter JSON matching its schema. Preserve numeric, boolean and array types; do not guess undocumented protocol strings.
3. Preview parameters validates without operating the device. Execute test sends the action.
4. Inspect the result, query its original receipt and read fresh state when needed. Service acceptance does not confirm physical completion. Unknown outcomes permit receipt queries without resending. The browser retains the latest receipt so queries can resume after reload.

Vacuum details include Map and position with version-2 rendering and5/10/30-second snapshot refresh. Hiding the page, closing details or switching tabs pauses reads. Three consecutive failures stop refresh and keep the last map. Update time is download time; pose freshness is unverified. Rendering stays unchanged when both the map and trajectory position are unchanged.

The map and Agents share the same map/trajectory feedback API. When a usable trajectory tail is available, the orange marker shows Trajectory position and the page reports whether new points were received. Otherwise it displays the cloud snapshot and a reason. A changed trajectory position updates the marker even when the map file stays unchanged; repeated points are not counted as movement again. Switching devices or robot tasks resets the continuation. Read time still does not establish device localization time, arrival, or readiness for automatic navigation.

The map fits the available width and height by default. Use Zoom in/out to inspect details and Fit to window to restore the whole map. Scroll when zoomed in. Map details and the raw file link are collapsed by default. Scaling preserves native map coordinates when selecting a point.

The map has a compact 16:9 video preview at its bottom right. Playback shows only the picture by default. Click it to reveal status, refresh and Exit video inside the picture; click again or press Escape to hide the controls. Tab focuses the picture and Enter or Space toggles the controls. Toggling controls preserves playback. Narrower maps use a smaller preview; very narrow windows such as phones place it below the map, aligned right, to keep point selection unobstructed. Password management shows the full form using the page's light/dark theme. The map device selector fits narrow widths without horizontal overflow. Enter the existing four-digit Mi Home PIN when needed, then select Start video. Input is masked with an optional visibility toggle and clears on submission. Remember password (local) encrypts it only after device verification. Once saved, the default view shows Password saved and the connection button without the input form.

PIN input, replacement and deletion disappear during submission, connection and playback. Select Exit video to restore password management after the exit receipt is confirmed. An uncertain exit retains the session and error instead of exposing deletion. After exit, Manage password opens replacement and local deletion; neither changes the device PIN. Exit a failed session before retrying or checking its PIN. The controls show Live picture only after real frames render. Install the [video transport component](../vacuum-cloud-map_en.md) first. Video has no audio, recording or movement; it has no playback time limit and stops when closing details, changing tabs or hiding the page. Camera switch state still refreshes every five seconds, with manual refresh in the controls. An enabled switch or connecting session does not establish received video frames.

Video timeouts and unreachable connections show their reason. For a PC behind an upstream router or on another subnet, CS2 attempts experimental relay transport when Xiaomi cloud supplies valid parameters and displays its connection mode. Only actual received frames establish success. Relay failures distinguish discovery, registration, allocation and device joining. Failed LAN connections show the vacuum address and network guidance when there is no matching interface; connect the PC to the vacuum router's LAN port or Wi-Fi if needed. No network settings are changed, and a matching subnet alone does not prove reachability. Device queries and control still use Home Assistant; maps and video are additional Xiaomi cloud capabilities.

Click the map to select coordinates and preview a blue dashed path. Walls, restricted areas or insufficient clearance produce an explicit reason. Select again after map changes. The start remains a cloud snapshot with unverified freshness; preview sends no movement commands. A verified coordinate-navigation payload is unavailable, so Move robot to target is not enabled. Starting cleaning is not navigation. Advertised start, pause, stop and return-home actions are available under Capabilities and testing. Arbitrary robot speech and audio input are not connected.

Existing connection authentication applies without per-device approvals. Cards contain registered devices with currently published entities; disabled devices or devices without published entities are outside this directory. See the [home API](../home-device-agent-api_en.md) and [map connection guide](../vacuum-cloud-map_en.md).


Manual control below the map pauses and confirms active cleaning before entering remote mode. Focus the panel and hold W forward, A left or D right; S stops. Key release or focus loss sends stop. This model has no reverse command. Exit does not resume cleaning and closing the map exits remote mode. Observe the physical device when video lags. WebGUI and Agents use the same [remote API](../home-device-agent-api_en.md#shared-manual-remote-control).
