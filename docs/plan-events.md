# 计划变更事件与按需加载

计划页首屏读取8条摘要。需要更多时点击“加载更多”，每次最多读取50条；滚动仅挂载已读取的卡片，不自动遍历所有分页。数量和分页游标由 Manager 返回，列表只显示已读取内容，不代表全部计划已加载。

`GET /api/events` 的 `ready` 用于连接后校准；`plan_changed` 是缓存失效通知，不是计划数据真源。页面按人格过滤事件，300毫秒合并通知，最多一个刷新在途和一个待刷新标记。分页正在执行时，事件等待它结束，不抢占第二个分页请求。

每次事件刷新只读取首屏8条，保留新的 `nextCursor`，成功后替换列表并显示“当前显示首屏”。专注单计划时只刷新该计划。此实现不保持深页位置；表单草稿仍由现有按计划ID的状态保存。它不会为一次通知遍历整个十万条目录。

隐藏页面、退出、切换人格或筛选时取消当前请求；调用方 AbortSignal 经过客户端传到底层 fetch，其他请求不受影响。取消之外仍检查请求版本、人格和筛选，迟到响应不能覆盖新视图。重新显示时恢复订阅，由连接 `ready` 或已有待刷标记触发一次有界校准。

失败保留此前列表并提示重试，不自动循环重试；未知数量显示“—”，不表示0，也不显示成功空态。只有成功的零条结果才能显示无匹配计划。

验证入口：`ribiwebgui/tests/bounded-plan-refresh.test.ts`（合并、取消、队列和客户端透传）、`knowledge-pagination.test.ts`（页面有界合同）、`knowledge-load-failure.test.ts`（失败状态）。这些测试不是浏览器部署验收；集成版本仍需构建并验证实际页面。
