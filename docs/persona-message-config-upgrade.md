# 角色消息配置升级

角色配置的第二个标签“消息”统一管理其消息路由。左侧不再单列路由配置，“快速配置”按钮改为“新建角色”并打开角色创建窗口。

## 配置归属

| 文件 | 保存内容 |
| --- | --- |
| `data/roles/<角色ID>/personaConfig.json` | 自动化、消息规则、消息上下文、唤醒词、语言风格和 Hook |
| `data/route/<路由名>/adapterConfig.json` | 消息端连接、处理 Agent、会话、工作目录、独立启停，以及角色 ID / 来源 PC 引用 |
| `data/manager.json` | 全局设置和自定义 `rolesDir` / `routeDir` |

角色与消息路由通过 `agentRoleId`、`agentRoleDeviceId` 关联；角色页面从路由目录派生关联列表，不保存第二份路由清单。目录不搬迁，历史消息、日志和外部路径引用保持原位置。同一角色可关联多个路由；远端同名角色按来源 PC 区分，其角色配置留在来源 PC。

已鉴权的远端角色与本机角色使用同一套读写编辑页，不增加只读限制或功能许可。配置、头像、身份、虚拟形象、聊天记录、全天记录与共同活动通过来源 PC 的完整 Manager 通道读写；打开配置文件也在来源 PC 执行。切换来源时使用独立页面身份和缓存，失败不改投本机同名角色。角色配置页顶部不再重复放“新建角色”，统一使用左下入口。

旧版路由中的角色规则、上下文、唤醒词、语言风格和 Hook 迁入对应的本机角色配置。旧 `roleMessageConfig.json` / `routes.json` 中的已知消息规则合并后移除。已有角色值优先，规则沿用运行时的按 ID 合并规则。Agent 投递目标复用现有运行时迁移，保留真实任务与收件人。未知扩展字段保留；旧消息规则文件存在无法识别的字段、非法 JSON、无角色却带角色配置或找不到角色时，脚本停止并保留原文件，需先核对关联。

## 升级步骤

使用新版发行包中的脚本，或在源码目录安装依赖并完成 `npm run build` 后运行。需要 Node.js，不依赖 `tsx` 或开发工具；脚本不要求 Manager 在线，也不访问网络。`--root` 指应用的数据根目录，即其中包含 `data/manager.json` 的目录。省略自定义路径时读取该文件中的目录设置，再回退到上表默认值。

1. 先预览；默认不改源配置，只输出文件数量：

   ```powershell
   node scripts/upgrade-persona-message-config.mjs --root "<应用根目录>"
   ```

2. 通过应用正常退出 Host，停止所有使用这些共享目录的实例；不要在线修改文件。然后执行：

   ```powershell
   node scripts/upgrade-persona-message-config.mjs --root "<应用根目录>" --apply --offline
   ```

   自定义目录可传 `--roles-root "<角色目录>" --route-root "<路由目录>"`。备份默认保存在应用的 `data/config-upgrade-backups/<唯一ID>`，也可用 `--backup-dir "<私有备份目录>"` 指定位置。配置及备份可能含连接凭据，只在本机私有位置保存，不上传到公共仓库或问题附件。

3. 成功返回 `applied:true` 和 `snapshot`。脚本在临时目录复用运行时迁移，生成完整候选后才备份原字节、比较源文件、逐项原子替换并回读。重复预览返回 `changedFiles:0`。没有变化时 `applied:false`。
4. 正常启动应用，在“角色配置 → 消息”核对各路由、消息端、处理 Agent 和会话。旧路由链接自动跳到该标签并选中原路由。未绑定角色的路由仍可从旧链接打开，或在“消息”中手动关联；无须创建替代角色或任务。

## 失败与还原

写入失败时脚本还原本次已写且未被别人改动的文件。出现 `recovery_required` 时停止后续操作，保留返回的备份目录进行核对，不覆盖并发改动。预览中的临时文件会清理，正式备份不会自动删除。

对已完成或中断的迁移，可在应用停止后按返回的 `snapshot` 还原。中断的快照仅恢复本次已写入的文件，尚未写入的原文件保持不变：

```powershell
node scripts/upgrade-persona-message-config.mjs --restore "<snapshot目录>" --apply --offline
```

还原先校验快照和当前文件；若迁移后又有配置修改，拒绝覆盖。还原本身也保存可恢复快照。旧程序可能在启动时重新执行自己的迁移，因此降级前应先退出新版、还原配置，再使用对应的旧程序。
