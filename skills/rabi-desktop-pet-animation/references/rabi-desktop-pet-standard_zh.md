# Rabi 桌宠动画规范

本参考说明 Rabi 桌宠的资源位置、动作语义、外观基准、不可变资源包及运行时验收。

## 位置映射与查找顺序

下文的 `RabiRoute/` 和 `RabiRoute/data/` 表示概念上的项目及数据位置，不代表本机当前工作目录。应根据实际项目与数据配置解析。`<MediaWorkspace>` 是已确认媒体工作区的占位符。

用户询问动画、已安装动作或旧工作流的位置时，先检查以下已知归属位置，再考虑扩大搜索：

1. 共享的已验收源资源包：`RabiRoute/data/roles/<personaId>/desktop-pet/packs/<packId>/`。
2. 人格创作与生成记录：`RabiRoute/data/roles/<personaId>/designs/desktop-pet/working/`。
3. Rabi 桌宠概览：`RabiRoute/data/roles/<personaId>/desktop-pet/README.md`。
4. H3 脚本与模板：`<MediaWorkspace>/scripts/` 和 `<MediaWorkspace>/workflows/`。
5. Manager 插件：`RabiRoute/plugins/builtin/io.rabiroute.manager.desktop-pet/`。
6. Desktop 播放实现：`RabiRoute/desktop/tray-task-window/rabiroute_tray/`。
7. 已安装资源包或缓存：从当前本地安装及 Manager 运行时 DTO 解析。这是部署副本，不是源资源的权威来源。

“Rabi 里实装的”意味着先查询人格桌宠绑定，再在 Manager 的运行时资源包索引中匹配该 `packId`。最新的源目录不能证明哪个包正在启用。

人格 README 中的“当前资源包”段落属于可能滞后于部署的维护文档。如果它与 Manager 绑定或运行时 DTO 冲突，应报告不一致，并以 Manager 回答当前状态；不得悄悄改写历史，也不能认定 README 是当前状态的权威来源。

定位模式只读。除非用户要求变更且已知归属位置确实没有目标对象，否则不要启动 ComfyUI、运行 H3、导出资源包、重新构建 Desktop、修改绑定、重启进程或扫描 Downloads／整个工作区。

回答位置问题时，每条路径都应标明其类型：已验收源资源、创作中间产物、生成工作流、播放实现或本地运行副本。

## 判断需要修改什么

| 观察到的需求 | 负责层 | 媒体生成范围 |
|---|---|---|
| 定位源资源、当前启用包、工作流或帧数 | 文件与 Manager 只读 API | 无 |
| 点击无反应、状态映射错误、随机动作从不触发 | Desktop／Manager 代码或配置 | 无 |
| 播放启动缓慢 | 运行时客户端／缓存／网络路径 | 无，除非已证明媒体大小是原因 |
| 动画过长、眨眼剪切不佳、透明效果差 | 重新剪辑或导出已验收源资源 | 先不生成 |
| 某个指定手势的运动、人体结构或归位姿势不正确 | 该动作的首尾基准帧与源媒体 | 仅指定动作 |
| 增加一个随机待机动作 | 新 `idle-*` 动作及待机动作池更新 | 仅新动作 |
| 角色身份、服装、比例、身体宽度、画风、画布、相机或背景基准变化 | 共享该基准的所有动作 | 受影响动作集；仅全局变化时才全部生成 |

开始媒体或资源包工作前，写明选定的动作 ID 和已验收基线包。`-All` 绝不是局部缺陷的默认处理方式。

## 外观基准

根据目标人格及已验收的基准帧确定角色身份。保留明确指定的头发、眼睛、耳朵或物种特征、标志性配饰、服装、配色、比例和画风。

从目标人格已批准的外观参考读取头发、眼睛、服装、比例及画风约束；不同人格或不同设计线不得共用未经确认的外观基准。

桌宠媒体通常应保持：

- 固定相机与连续一致的构图；
- 用于可控透明化导出的均匀色键背景；
- 角色尺寸、身体中心、轮廓宽度、脚底接地与安全边距；
- 双鞋及标志性特征可见，除非动作明确需要遮挡；
- 没有文字、标志、重复肢体、粘连的手／脸、多余角色或来历不明的道具。

“保持角色细节”指保留可观察的身份基准。如果已验收风格是平涂赛璐璐渲染，并不要求改成绘画式明暗处理。

## 动作语义

- `idle`、`thinking`、`talking`、`sleep` 或 `drag` 等基础状态，只有在动作及接缝为循环设计时才循环播放。
- 交互手势与随机待机手势通常单次播放：`loop: false`、`next: "idle"`。
- 回到静止状态的单次手势，应从已验收的待机基准开始，并回到同一基准结束。
- 真正的状态过渡可以采用不同的尾帧，但必须是已验收的目标状态基准帧。
- 新增随机待机动作时，将其状态 ID 向 `idleBehavior.randomStates` 插入一次；保留既有条目及顺序，避免重复，并保留间隔、睡眠阈值和睡眠状态，除非明确要求修改。
- 随机待机播放不重新定义点击行为、工作状态映射、唤醒规则或长时间待机后的入睡时机。

手部靠近脸部时，应明确掌心朝向、目标区域、必须保持无遮挡的特征、手指／手腕的一致性、手势峰值、停留与恢复过程。

## 媒体生成边界

如果必须生成或重新生成源媒体，加载 `$minimax-h3-character-animation`，并提供：

- 选定的动作 ID；
- 精确的首尾基准帧；
- 该人格专属的视觉连续性约束；
- 画布／背景／相机要求；
- 可观察的运动及禁止出现的失败模式；
- 种子、帧数和输出目录。

通用 H3 技能返回已验收的源视频及证据。它不决定 Rabi 的 `loop`、`next`、随机待机池成员、资源包 ID、运行时安装或当前启用绑定。

## 清单与导出

Rabi 动作清单绑定人格、画布、生成输入、动作 ID、首尾基准帧、`desktopFrames`、`loop`、源输出，以及任何明确要求的 `idleBehavior` 变更。仅在新包必须修改 `idleBehavior` 时才包含该字段；否则从已验收基线继承。

对于桌宠增量更新，下面仅是占位示例，不是已验证的本机命令。本次文档更新未验证示例源脚本是否存在及其参数。使用前须确认实际媒体工作区，核实源脚本确实存在，并检查它支持的参数与示例一致。本参考不能证明资源包已经安装或部署。

```powershell
& <local-python-with-export-dependencies> `
  <MediaWorkspace>/scripts/export_minimax_h3_desktop_pet.py `
  --manifest <action-manifest.json> `
  --pack-directory <new-pack-directory> `
  --pack-id <new-pack-id> `
  --action <action-id> `
  --base-pack <accepted-pack-directory> `
  --target-width 512 `
  --target-height 512
```

修改多个动作时，重复传入 `--action`。导出行为要求为：对已验收源媒体进行色键抠像，生成透明 RGBA PNG 序列；采用各动作的 `desktopFrames`；保持未选中状态的文件字节不变；拒绝覆盖已有资源包。应核实实际导出器满足这些要求。原始 H3 MP4 绝不是运行时资源包。

导出后，对比源与目标清单，核对人格、画布、状态 ID、变更动作的帧数、`fps`、`loop`、`next` 和 `idleBehavior`。确认未变更状态的文件逐字节相同。

## 启用与验收

将运行时资源安装到执行电脑的本地 Rabi 安装目录；不要从 NAS 运行 Desktop 或其缓存。启用前，让 Manager 发现本地资源包，并核对人格、资源包 ID、状态数量、资源和大小限制。

请求包含启用时，通过 Manager 更新人格绑定，重新加载已安装的 Desktop，然后验证：

- 当前启用的是预期资源包 ID；
- 变更动作的帧数、`fps`、`loop` 和 `next` 符合预期；
- 随机待机及睡眠行为严格按要求变更；
- 至少一个有代表性的资源返回 HTTP `200`；
- 实际可见播放效果符合已验收的媒体评审结果。

媒体、导出、资源包校验、安装或运行时验证失败时，保持已验收基线处于启用状态。应在证据失败的层定位问题，而不是重新生成全部内容。
