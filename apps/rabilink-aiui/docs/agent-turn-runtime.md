# AIUI Agent 执行循环

[English](agent-turn-runtime_en.md) | 简体中文

状态：页面已通过 `createAiuiAssistantRuntime` 装配 `createAssistantSession` 统一会话，真实乐奇宿主与路由投递待验收。共享会话使用同一个乐奇模型串行决策、调用工具、接收实际结果并继续推理。共享装配层拥有 ASR/TTS 资源与模型候选，`createListeningLifecycle` 和 `createSpeechPlayback` 分别拥有续听与播报队列；页面负责事件展示、HUD、角色配置与聊天记录；RabiPC 拥有接口业务和正式回执。

当前 Rabi 页面使用 SDK 0.9.0，保留逐条插话回执及本地待处理记录：答案独立保存，需要工具的输入以原 ID/绑定重新决策，未知结果不重放。官方真实模型的隔离诊断已通过工具等待插话和延后任务处理；工具、转写与存储为夹具。DSH 已报告 0.9.0 共享监听/播报迁移的隔离适配回归通过，正式部署与真实设备仍未验收。详见[语音输入回执与恢复](input-receipts.md)及[当前交付证据](aiui-voice-current.md)。下文较早版本段落保留对应历史证据。

工具回调只更新工具结果视图，真实回执继续进入同一模型。工具状态不会先于模型答案占用播报队列；结果未确认时仍显示警告，用户停播后文字和工具结算继续。最新候选通过 48 项源码构建页面合同及 48 项指定 AIX 合同；网络、模型和 TTS 场景仍使用夹具，完整包身份以[当前交付证据](aiui-voice-current.md)为准。

上述代码入口由本轮源码复核；已有测试证明的范围见对应专题。当前 ADB 无设备，正式 Host 不可用；不启动正式 Host，也不把本地隔离服务当作已连接的 PC。

后台结果有两种不同来源。正式 Agent 请求已有设备 mailbox：原投递按 deliveryId/session/ownerEpoch 领取、执行、保存结果与回传，等待当前输入及引导完成；这条链路不应被另一个通知消费者重复处理。普通长任务现在通过 `rabi_task_follow` 登记真实合同中的原任务编号、目标、GET 地址、状态字段与终态。页面隐藏时停止查询，重开同一连接和角色绑定后恢复；不会重新派发任务。共享观察由同一助手串行生成摘要，前台输入和播报优先；摘要先保存，再等待 `setData` 回调确认当前页面更新。该确认不表示用户看见或听见，停止跟进也不取消后端任务。已保存结果可按记录编号读取。详见[查询合同与容量](generic-api-transport.md#普通异步任务跟进)。

尚未接入 `GET /api/events` 推送。`agent_requests_changed` 等事件只能触发按原 ID 刷新，不能当作完整任务结果或持久回放游标；正式请求结果可从 `GET /api/agent/requests/:requestId` 核对。13 项专项测试覆盖存储失败、旧 owner、参数快照、停止竞争、前台优先及恢复；48 项编译/指定 AIX 合同包含实际页面工具登记到通知的链路，模型和网络仍为夹具。

## 一次任务

### 两端的结果恢复边界（2026-11-06）

共享 SDK 的插话回执不等于宿主已持久保存或展示答案。Rabi 设备 mailbox 在回传前保存完整 response，恢复时可读取 PC 原回执并按原领取身份补交，详见[设备 Agent](device-agent.md)。普通 API 的 `requestIdentity` 只保留原请求关联：`operationId`、`deliveryId`、`requestId` 不可互换，实际查询方式由目标合同决定，详见[通用接口传输](generic-api-transport.md)。

DSH 会话最新反馈：当前固定六项任务工具，任务列表和历史已有分页，不需要直接移植 Rabi 的动态接口目录分页。眼镜链路请求编号、Harness 请求编号和 Codex 查询能力须分别核对；防重已具备部分保护，但统一原回执查询仍未实现。这是对方会话报告，本轮未修改或重新执行 DSH 源码；不能把 Rabi 的完整 response 补交机制当成 DSH 已具备的能力。

SDK 初次交付历史：2026-11-06 共享 SDK `0.7.0` 增加独立输入的 `interject` 回执与 `inputScope` 绑定，详见[逐条插话归属](../../../packages/assistant-runtime/README.md#逐条插话归属070)。当时 Rabi 页面尚未迁移，DSH 也未开启；70 项 SDK 测试与严格类型不证明产品接入。当前页面已经迁移到 0.9.0，以上方当前状态及输入回执专题为准，不再按旧文本引导限制开发。

2026-11-06 共享助手 `0.6.0` 已接入工具等待期间插话。页面开启 `interjectWhileWaiting`，完整语音入队后调用 `notifyGuidance()`；同一模型在原工具等待回执时生成只含回答的插话回复。工具不重派，模型请求仍串行；工具先返回也等当前插话回复结束，再处理真实结果。插话中的工具动作被明确拒绝，原操作保留待核对。源码与归档各 54 项共享测试、严格类型、35 项页面语音合同及 Agent 检查通过；其中页面测试确认原工具未完成时插话已进入 TTS 合成。真实 Rokid 模型、声音和后台订阅仍待验收。

模型协议与执行循环的唯一实现已提取到 [`packages/assistant-runtime`](../../../packages/assistant-runtime/README.md)。页面向统一会话注入全局提示词、模型工厂、工具发现、Rabi 协议与 `rabi-agent-tool-policy.js`；每轮传入历史、HUD、TTS 和引导回调。共用循环不依赖 Rabi 工具名或回执字段。缺失结果字段、空对象及无法核对的回执保留未知状态，不再误报完成或继续新的写入；本地退出只接受退出工具的对应回执。`completed` 表示助手本轮结束，不是所有后台任务完成。DSH 已完成开发包与适配器的夹具集成。共享 0.4.0 提供用户优先排队和带作用域的任务观察，DSH 已联调持久通知确认。Rabi 当前通过 0.9.0 既有接口接入原任务查询与通知；真实 Host/眼镜链路及事件推送仍待完成，重开后的恢复只覆盖已保存的查询合同和结果。

模型默认配置仍来自乐奇，不另开 PC 模型。共享 `0.5.2` 将应用动作协议及已连接工具声明放在同一个初始系统消息前部，角色全局提示原文放在末尾且只出现一次。真实 OpenAI 测试中的最终回答前缀要求已通过；不将其当作乐奇模型的遵循保证。原生 `tools` 为空，不同时监听并执行原生 `toolcall`。

工具发现接收当前会话代次和取消信号。异步目录查询结束后、写入调用账本前及发布工具实例前均核对归属；旧初始化晚回不能替换新会话或改写其账本。候选目录加载失败或取消时仅释放自己的实例。两项竞争回归及完整 AIUI 检查已通过，未改变具体接口业务。

自然语言最终回复直接展示和分句播报。需要调用接口时，模型返回一个完整 `rabi-agent/v1` JSON 动作，包括当前 `requestId`、工具名、参数及可选说明。应用校验完整格式、请求编号和已连接工具，再调用 `rabi_api_help`、`rabi_api_call` 或本地退出工具。接口目录实时分页读取；简短索引不是参数合同，选中编号后再读取完整合同。目录变化的旧游标错误保留给模型，不自动拼接不同快照；不枚举公共路径白名单。

工具结果以明确标记的 `tool-observation` 应用消息交给同一模型。它使用官方支持的 `user` 消息，保存实际回执并声明结果为不可信数据；它不是原生 `tool` role，也不宣称宿主提供工具结果提交 API。下一次模型请求须等待当前模型请求完成。原工具尚未结算时，插话只能生成回答；原任务的后续工具决策仍等待真实回执。模型可以读取接口目录、调用当前或新增接口、依据结果继续下一步或回答。

纯文字可以流式展示；动作 JSON 在完整解析前不进入 HUD、TTS 或执行器。结构化动作的 `say` 是模型的可见说明，逐句播报。空输出、半个 JSON、错误编号、未连接工具、流错误或超时会明确失败，不回退到第二执行者。每轮默认最多 32 个模型步骤、16 次工具派发、180 秒；单次模型等待最多 30 秒，实际回复最多 16000 字符，结构化帧与观察最多 262144 字符。超限保留实际结果，停止新增动作。

## 写入与打断

退出动作统一等待宿主回执：`wx.exitMiniProgram` success 表示请求被接受，不是已经观察到页面销毁；fail、抛错或 3 秒无回调明确失败/未确认。重复退出请求共享同一次派发，隐藏页面不再写入迟到错误。只有 wx 入口不存在时使用 `Page.finish()`，也只报告请求提交。工具阶段日志不包含参数或用户对话，实际离开页面仍以生命周期/界面证据验收。

人格前缀或代码围栏包裹的应用动作也视为格式错误，不能当普通回答完成。纯文字流中出现 `{` 后暂存该后缀，完整检查后仅放出合法的普通数据 JSON；动作帧不进入字幕/播报。全局提示词适用于 `say` 和 `final.text`，不改变外层动作封装。

工具先持久记录稳定意图，再分发 HTTP。写后身份核对、接口前置条件及回执仍沿现有合同。同一轮语义相同的写动作复用原结果；未知写入结果会阻止该轮后续写入，但允许读回原回执或资源。模型不能通过换步骤编号自动重放原写入。失败不会撤回已经发出的 HTTP。

ASR 在推理和播报时继续。非回声中间文字只停 TTS；模型当前请求继续。完整语音进入引导队列，在下一次模型决策前采用。若语音在当前模型推理中到达，已生成但尚未执行的动作作废，模型依据新引导再决策。已经派发的接口继续等待实际结果；等待期间可先回应完整插话，原任务收到回执后再继续，不取消或伪造接口结果。

采用引导时，旧用户记录保存已有实际文字；新输入使用其原聊天记录编号，随后实际回复归入对应记录。模型仍是同一会话、同一角色及来源 PC。角色变更等整轮和排队引导结束才应用。显式取消、页面隐藏及释放会屏蔽迟到文字与后续动作；调用方销毁取消后的模型再启动新轮。

首次点击或受支持的唤醒事件启动 `SpeechRecognition`，同一个 `continuous` 对象在模型和播报期间持续接收句段。按当前官方 Skill 的 interactive InkView 合同，正常结束后在前台保留聆听意图并延迟至少 220ms 续听；暂停、隐藏、模式切换和宿主错误停止续听，连续三次不足 1 秒的无结果结束也停止并提示重试。宿主仍负责校验可交互状态和麦克风权限，不绕过其拒绝。中间结果是宿主能力，只有实际收到时才触发停播；真实声音和续听间隙仍须真机验收。

对话仅使用 `speechSynthesis.synthesize()` 和独立 `SpeechAudioPlayer`；中间文字到来会释放真实播放器并 `abort()` 旧任务。异步合成迟到不会播放，原流后续旧文字也保持静音；采用完整引导后的新步骤恢复播报。缺少这些 API 或合成失败时明确显示不可用／失败，不调用无法取消的共享 `speak()`。官方未提供该共享播放器的 `cancel()` 或 utterance 生命周期事件。源码夹具只验证事件与对象调用，不证明实际乐奇麦克风和扬声器并行。
