# AIUI 角色、接口与语音引导

[English](persona-agent_en.md) | 简体中文

状态：实验实现。通用 HTTP 传输、角色配置、记录写入和引导队列已接入源码；设备安装与硬件验收未完成。应用模型执行循环已接通，路由自动唤醒与真实宿主验收未完成，不能标为完整 Agent。

## 手机设置

在 RabiLink 手机端打开 **全天记录 → 设备 → 眼镜 → 眼镜设置**。选择眼镜、角色所在电脑和角色，可预载该角色的 Skill 后保存。保存使用版本比较与稳定请求编号，确认回执后再次读取配置。网络故障时保留原请求，刷新核对，不能换编号重复保存。

角色提供身份、系统指引、Skill 和聊天记录归属。模型仍由乐奇运行环境配置。角色所在电脑保存在 `personaRef.sourceDeviceId`，作为默认接口目标；`personaRef.roleId` 为角色身份。绑定、解绑和切换角色均不改变连接或设备凭据的权限。未绑定也可调用接口。

配置变更等当前轮及其排队引导结束后应用。工具调用固定使用创建模型时的角色来源 PC；旧轮记录仍保存到旧角色所在电脑。配置只有一个可写来源：设备连接登记的 PC。它可以引用其他同应用 PC 的角色，切换来源只做该 PC 的一次版本比较保存，不迁移或复制配置真源。

用户手势同步启动 ASR，已配置设备连接时，初始化期间的完整语音先有界保留原文；角色配置、接口工具与设备 owner 初始化确认后才创建聊天记录和原模型轮。读取失败明确显示未确认并保留输入，不当作无绑定。明确返回未绑定仍可使用全部已鉴权接口；未配置凭据的默认包保留独立原生模型对话，接口显示未连接。隐藏、卸载或连接归属变化会废弃旧初始化和旧输入；活动轮收到解绑成功也只在轮次结束后清除角色与模型。

## 通用接口传输

模型工具为 `rabi_api_help` 和 `rabi_api_call`。前者读取目标 RabiPC 的 `/api/agent/help`，后者按接口合同传递方法、相对路径、请求体和必要前置条件。路径不枚举静态白名单，新增公共 HTTP 接口可复用传输。`targetDeviceId` 可显式选择同应用已鉴权的其他 RabiPC；未提供时使用本轮已固定的角色来源 PC。目标选择是连接元数据，不把角色作为权限边界。

所有调用仍受目标接口本身的鉴权、参数、版本和能力限制。内部服务路径、外部 URL 和模型提供的认证头不属于公共传输。长期事件流、超出体积或时间限制的请求需要目标接口提供适用的查询/任务合同；有限 HTTP 代理不能证明所有协议已覆盖。

调用前核对目标 `/meta` 身份和就绪状态；写后再次核对身份。写入在派发前保存原意图和稳定 `Idempotency-Key`，相同编号的不同内容拒绝。超时、断连或旧写入重复请求返回待核对状态，不重新派发；应读取原回执或资源。角色不参与接口权限过滤。

应用将实际工具结果作为明确标记的观察消息交回同一乐奇模型，支持查目录、调用接口及依据结果继续推理。原生工具结果提交 API 保持未证实，默认不执行原生工具事件。

手机使用真实加密连接，按局域网、P2P、中转顺序建立 manager 服务连接；业务请求派发后不会因失败换线路重发。AIUI QuickJS 当前仅支持有限 HTTP 中转，明确不宣称已具备原生 P2P、流式 HTTP 或 WebSocket。详见[通用接口传输](generic-api-transport.md)。

## 聊天记录

绑定后，用户文字先保存在眼镜的待同步队列，再调用模型；实际回复在本轮结束时补存。客户端在轮次开始时固定角色和来源电脑，经同一通用接口调用该 PC 的角色聊天记录。Relay 不解析角色或配置版本。持久随机设备会话种子参与会话编号，避免多副眼镜计数相同而碰撞；已排队记录保留原目标。

PC 使用角色现有聊天记录保存 `aiui_user`、`aiui_assistant`。重复内容去重，同一轮不同正文拒绝。中断后保留已接收用户文字，不生成虚假回复；失败记录留在原队列。手机读取角色记录，并按来源电脑及角色映射到对应聊天记录。

## ASR、TTS 与引导

日常 AIUI 对话在推理及播报时保留原生 ASR 监听。识别到非回声文字时停止 TTS、清空旧播报队列，当前推理继续，旧轮后续文字不重新播报。完整输入排入引导队列；同一模型当前请求结束后、下一次决策前采用引导；已派发工具先等实际结果，不并发启动第二个模型请求。

这是同一 Agent 轮次中模型步骤之间的引导。原生模型内部单次请求能否插入引导、ASR/TTS 真正并行的设备效果及噪声下回声误判，仍需真实宿主验证。显式触摸取消仍会取消模型；语音输入和唤醒词不执行该取消路径。


用户点击或受支持的唤醒事件必须在任何 `await` 前同步调用 `SpeechRecognition.start()`，同一个 `continuous` 对象在模型和播报期间持续接收句段；结束或出错后等待新的用户交互，不通过定时器重新启动。官方合同要求每次 `start()` 有用户交互，未说明首次授权后可跳过。中间结果是宿主能力，只有实际收到时才触发停播。

对话仅使用 `speechSynthesis.synthesize()` 和独立 `SpeechAudioPlayer`；中间文字到来会调用真实播放器 `stop()`、释放播放器并 `abort()` 旧任务。异步合成迟到不会播放，原流后续旧文字也保持静音；采用完整引导后的新步骤恢复播报。缺少这些 API 或合成失败时明确显示不可用／失败，不调用无法取消的共享 `speak()`。官方未提供该共享播放器的 `cancel()` 或 utterance 生命周期事件。源码夹具只验证事件与对象调用，不证明实际乐奇麦克风和扬声器并行。

## 完整 Agent 的剩余合同

目标是作为 RabiRoute Agent 处理端接收投递，通过乐奇自定义指令唤醒 AIUI，由同一个宿主模型处理并正式回传。尚待验收的链路：

1. 唤醒按用户确认的链路实现：代码触发双指单击 → 乐奇 App 已配置的自定义指令 → AIUI。已增加手机 CXR 测试入口，由眼镜组件发送 `com.android.action.ACTION_TWO_FINGER_SINGLE_TAP` 有序广播。组件安装、启动及双向自定义消息已在真机验证；发送双指广播收到 `dispatch_security_rejected`，系统拒绝普通应用发送。官方正文说明接收方向，尚无已验证的受支持发送接口。自动唤醒及领取原投递仍未完成。详见 [双指单击唤醒验证](aiui-wake-probe.md)。
2. 应用观察驱动的续推理已实现；真实宿主多步骤行为、取消、重复事件和正式投递回执待验收。原生结果提交接口仍未证实，见 [工具合同核对](agent-tool-contract.md)。

未补齐上述合同前，不注册宣称可用的完整 Agent adapter，也不启动 PC 模型替代眼镜执行者。
