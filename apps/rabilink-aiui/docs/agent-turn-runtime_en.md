## One task

### Result recovery across the two hosts (2026-11-06)

A shared-SDK interjection receipt does not establish durable storage or presentation. Rabi's device mailbox saves a complete response before submission and reconciles its original PC receipt before resubmitting under the original claim; see [device Agent](device-agent_en.md). For generic APIs, `requestIdentity` only correlates the original request. `operationId`, `deliveryId` and `requestId` are not interchangeable; the target contract defines recovery. See [generic transport](generic-api-transport_en.md).

The DSH chat's latest report describes six fixed task tools, with existing pagination for task lists/history, so Rabi's dynamic API catalog pagination need not be copied. Eye transport IDs, Harness request IDs and Codex query capabilities require separate checks. Some duplicate protection exists, but unified original-receipt lookup remains unimplemented. This is a report from that chat; DSH source was neither modified nor rerun here. Rabi's complete-response recovery must not be attributed to DSH.

Initial SDK delivery history: on November 6, SDK `0.7.0` added independent `interject` receipts and `inputScope` binding; see [per-input ownership](../../../packages/assistant-runtime/README_en.md#per-input-interjection-ownership-070). Rabi had not migrated and DSH had not enabled it at that point. The 70 SDK tests and strict types did not establish product integration. The current page has migrated to 0.9.0; use the current status above and the input-receipt topic rather than implementing against the old text-guidance limitations.

November 6: shared assistant `0.6.0` is connected to tool-wait interjections. The page enables `interjectWhileWaiting` and calls `notifyGuidance()` after complete speech enters its queue. The same model answers without tool actions while the original tool awaits its receipt. The tool is not replayed and model requests stay serial; earlier tool completion waits for the current interjection before delivering its actual result. A tool frame in an interjection fails explicitly, retaining the original operation for reconciliation. Shared source/archive tests (54 each), strict types, 35 page voice contracts and Agent checks passed; the page test establishes TTS synthesis before tool completion. Real Rokid behavior, audio and background subscriptions remain unverified.

The single protocol/loop implementation lives in [`packages/assistant-runtime`](../../../packages/assistant-runtime/README_en.md). The page injects global instructions, a host model factory, tool discovery, Rabi protocol compatibility and `rabi-agent-tool-policy.js`, with per-turn history/HUD/TTS/guidance callbacks. Shared code has no Rabi tool-name or receipt-field dependency. Empty, malformed or unverifiable receipts remain unknown rather than certifying completion or permitting more writes. Local exit accepts only its own tool receipt. `completed` denotes assistant-turn completion, not completion of backend tasks. DSH has integrated the package and its adapter in fixtures. Shared 0.4.0 provides user-priority scheduling and scoped task observations, with DSH durable notification receipts covered by integration tests. Rabi now uses existing 0.9.0 interfaces for original-task polling and notification. Real Host/glasses connections and event push remain pending; restart recovery covers only saved query contracts and results.

The model remains the Rokid host default, without a PC model. Shared `0.5.2` puts application framing and connected tool declarations first in the initial system message, followed by the unchanged global persona instructions exactly once. Live OpenAI tests passed the final-answer prefix requirement; this is not a compliance guarantee for Rokid models. Native `tools` is empty and no second native `toolcall` execution path is registered.

Tool discovery receives the session generation guard and cancellation signal. Ownership is checked after asynchronous directory lookup, before ledger writes and before publishing the adapter. Obsolete initialization cannot replace a newer session or its ledger. Failed or cancelled catalog candidates release only their own instance. Both race regressions and the complete AIUI check passed, without changing API business behavior.

Natural-language final replies are displayed and spoken by sentence. An API action is one complete `rabi-agent/v1` JSON frame with the current `requestId`, tool name, arguments and optional narration. The application validates the full frame, ID and connected tool before calling `rabi_api_help`, `rabi_api_call` or local exit. Live discovery is paginated: a compact index is not the parameter contract, so selected IDs require complete contract lookup. Stale-cursor errors remain visible without mixing snapshots; public paths are not enumerated in a static allowlist.

Actual results return to the same model as explicit `tool-observation` application messages. They use supported `user` messages, preserve real receipts and mark outputs as untrusted data. They are not native `tool` roles or a claimed native result-submission API. Each model request waits for the preceding model request. Before a dispatched tool settles, interjections may only answer; further original-task tool decisions still require the actual receipt. The model can read current help, call existing or future APIs, reason from outcomes and continue or answer.

Plain replies can stream; action JSON is withheld from HUD, speech and execution until fully parsed. A structured action's optional `say` is visible model narration and uses sentence TTS. Empty output, partial JSON, wrong IDs, disconnected tools, stream errors and timeouts fail explicitly without another executor. Defaults are 32 model steps, 16 tool dispatches and 180 seconds per turn; each model wait is at most 30 seconds. Visible output is limited to 16000 characters; frames and observations to 262144. Limits stop new actions while preserving actual results.

## Writes and interruption

Exit actions share a host-receipt owner. `wx.exitMiniProgram` success means the request was accepted, not that page destruction was observed. Failure callbacks, throws and no callback after three seconds remain failed/unconfirmed. Concurrent requests share one dispatch and late errors do not update hidden pages. `Page.finish()` is used only when wx exit is absent and confirms submission only. Tool-stage logs contain no arguments or user dialogue; actual exit still requires lifecycle/UI evidence.

Persona-prefixed or fenced application actions are invalid framing, never successful plain answers. A `{` suffix in a plain stream is held until full validation; ordinary data JSON is displayed afterwards, while action frames never enter captions or speech. Global instructions govern `say` and `final.text` without changing the outer action envelope.

Tools persist stable intent before HTTP dispatch. Identity checks, API preconditions and receipts retain existing contracts. Equivalent writes within a turn reuse the original outcome. Unknown write outcomes block subsequent writes in that turn while permitting receipt/resource reads. Changing step IDs cannot automatically replay a write. Failure does not undo dispatched HTTP.

ASR stays active during reasoning and playback. Non-echo interim text stops only TTS. Final speech queues guidance for the next model decision. Guidance arriving during inference supersedes a generated but undispatched action; the same model decides again with that guidance. Already dispatched APIs settle first and their actual outcomes accompany the guidance.

Adopting guidance stores existing actual text in the preceding user record, keeps the new input's original history ID, and saves its actual response there. The same model, persona and source PC continue. Persona changes wait for the whole turn and queued guidance. Explicit cancellation, hiding and disposal fence late text and later actions; the caller destroys a cancelled model before starting a new turn.

The initial tap or supported wake event starts `SpeechRecognition`. The same continuous recognizer receives segments during model work and playback. Following the current official Skill's interactive InkView contract, normal completion retains listening intent and restarts in the foreground after at least 220ms. Pause, hide, mode changes and host errors stop continuation; three consecutive empty sessions ending within one second also stop with a retry message. The host still enforces interactivity and microphone permission. Interim results depend on the host; they stop playback only when actually received. Audible behavior and gaps between sessions still require device acceptance.

Conversation uses only `speechSynthesis.synthesize()` and an owned `SpeechAudioPlayer`. Interim text releases the actual player and aborts the old task. Late synthesis never plays, and later old-stream text remains silent; the next step resumes speech after adopting final guidance. Missing APIs or synthesis failure show an explicit unavailable/failure status without the uncontrollable shared `speak()` fallback, whose `cancel()` and utterance lifecycle events are not exposed officially. Source fixtures establish event and object calls, not simultaneous OEM microphone and speaker operation.

## Validation

Historical 0.6.0 review: DSH retained `interjectWhileWaiting=false`, and shared `guide` carried text without per-input handoff receipts. Those gaps led to later `interject` and durable input records; they must not be presented as evidence that the current 0.9.0 page is still unmigrated. Outstanding product gaps and physical-device acceptance are listed above.

Historical device-page regressions: 18 lifecycle/storage cases and `check:agent` passed at that point. Stale context cannot create a model or overwrite a replacement startup, registration/unregistration settle serially, and records added during model/network waits survive old completions. The SDK was `0.5.3` then; its current version is `0.9.0` above.

On November 6, an isolated official Studio diagnostic package verified that the real Rokid host follows a custom natural-language prefix and emits a parsable close-tool action in the same session; `tool:dispatch close_app` was followed by `exit:accepted`. Only the fallback system prompt changed, not the protocol or loop. Actual page exit, device delivery of phone-profile/launch-parameter prompts, PC API calls and audible speech remain unverified. See [current evidence](aiui-voice-current_en.md#november-6-current-candidate-and-real-host-prompt-validation).

Shared `0.5.3` prevents background observations from running when speechend precedes the final transcript. The Rabi mailbox consumes its input-priority state. All 48 shared tests passed in source and the independently unpacked archive, with strict TypeScript, 12 device Agent tests and 34 packaged-page voice contracts. Coverage includes both final/end orders, interim/final-only hosts, obsolete callbacks and actual page wiring. These software contracts do not establish a backend subscription or audible device acceptance.

The device Agent renews every 15 seconds using the current `chatAssistant.getState().ready`, replacing the retired `chatModel` field. Timer callbacks and request success/failure check both original owner and timer identity, so obsolete renewals cannot unregister or reschedule a replacement. Ten device Agent regressions cover renewal, unready retirement, owner replacement, same-owner timer replacement, late failures after hiding and original delivery receipts. This is not acceptance of a live device connection.

`npm run check:agent` covers live-help/future-API/result reasoning on one model, serial settlement, duplicate writes, uncertain writes/readback, partial JSON, invalid actions, timeout, cancellation, step-boundary guidance and deferred persona application. An exit request accepted by the host ends the loop without another model request.

A separate read-only integration used a fixture Relay, the current source PC worker and the actual Manager: `GET /meta` and `GET /api/agent/help` both returned 200, and both actual receipts entered the next step of the same application loop, with zero mutations. Its model remains a fixture and the installed worker was not updated. The real host model, concurrent ASR/TTS, two-finger wake and original delivery response require device acceptance; no formal Route Agent is registered.
