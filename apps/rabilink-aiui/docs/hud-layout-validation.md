# HUD 布局验证记录

[English](hud-layout-validation_en.md) | 简体中文

当前 HUD 保留顶部状态、底部回复及透明中区。修复了旧 `.unifiedModeHud` 的 87px 高度限制与新绝对定位子节点冲突；配置状态另起一行，不与版本及触控说明挤在同一行。紧凑卡片隐藏用户原文与逐词提示，缩小回复字号并限制回复高度。

本机 Ink SDK 的 480×352 与 448×150 渲染已用于检查。现阶段采用有界显式宽度；不得把 CSS 编译通过当作设备不截断的保证。默认 Ink 检查现验证顶部状态、底部回复、中央零绘制及四边安全区，两个尺寸通过；向像素副本左上角注入越界点时，同一判定明确拒绝。保留状态变化可见、无黑帧、无半帧和 20 次同页切换检查。无 Token 场景按本地 Agent 合同验证 ASR 启动。结构审计默认验证当前 HUD，原 87px 合同仅通过 `--legacy-hud` 显式运行历史诊断。标准尺寸中央透明预算明确为 y=60..189（130px），底部从 y=190 起容纳用户原文及两行回复；紧凑尺寸中央预算为 y=32..49。中心 y=100 注入绘制也必须被拒绝。测试 AIX 不得作为已验收安装包。

长名称、长状态、长回复已通过测试专用原文注入覆盖中文与无空格英文；两类数据在标准、紧凑两个尺寸共四场景通过正式分区检查。注入经过生产显示转换，未覆盖最终显示字段；完整原文保留由结果分页和显示模块测试验证。交互点击区域与真机仍需进一步检查。此次本机产物使用 `https://example.invalid`、空 Token，不连接真实 Relay。

最终本机完整 `npm run check` 已通过，包含固定化的九项 Agent 回归、11 项接口/配置/状态合同测试、真实 Ink、两种操作状态的交互缩放和 AIX 校验。旧远端观察用例显式选择兼容 owner，同时验证默认有 Token 仍走宿主模型、不向 Relay 转发语音。宿主语音与模型在这些测试中由夹具模拟；这不是手机或眼镜真机验收。
